# 系统同步机制

> 问题:新内容进入系统后,不同模块可能不同步(MOC 没更新、审阅没做、frontmatter 不全、死链产生)。
> 需要一个机制确保系统各部分始终一致。

---

## 一、不同步的来源

| 场景 | 什么会不同步 |
|---|---|
| 单篇精读 | MOC 可能没更新;审阅可能被跳过 |
| 批量精读 | 所有维护动作(MOC/审阅/lint)被跳过或冲突 |
| 概念页更新 | MOC 可能需要刷新;新概念可能需要 MOC 收录 |
| 系统规则修改 | 已有内容可能不符合新规则(如新增的 frontmatter 字段) |
| 时间流逝 | 概念页过时;死链积累;confirmed 比例停滞 |

---

## 二、两级同步机制

### Level 1: 单次同步 (每次 ingest 后自动触发)

精读/复现 pipeline 完成后,执行以下检查:

```
笔记生成 + 审阅 + 反向更新 + lint 完成后:
    ↓
□ 本篇笔记的 frontmatter 所有字段齐全?
□ 本篇涉及的 MOC 是否需要刷新?(论文的 tags 对应的 MOC 是否包含本篇?)
□ 审阅 callout 是否已追加?
□ log.md 是否已更新?
□ Git commit 是否完成?
```

**如果有遗漏:** 当场补完,不留到以后。
**耗时:** < 1 分钟(都是检查+小修补)

### Level 2: 全面同步 (周期性或批量操作后)

触发条件:
- 每周一次(跟 full lint 一起)
- 批量操作(≥ 5 篇)完成后
- 用户说"跑一下系统同步"

检查清单:

```
□ MOC 覆盖: 所有 deep/repro 笔记是否被至少一个 MOC 收录?
□ 审阅覆盖: 所有 deep/repro 笔记是否有审阅 callout?
□ Frontmatter 一致性: 所有笔记是否符合当前模板 schema?
□ 死链: 全 vault wikilink 有效性
□ 孤儿页: 没有入链的实体页
□ 概念去重: title/aliases 是否有语义重叠
□ 可信层进度: confirmed 比例是否在增长?(如果停滞 → 提醒 batch review)
□ 概念溯源: key_papers ≥ 3 但 origin_paper 空的概念页
□ 系统文档: CLAUDE.md vault 状态是否反映当前数据
□ 审阅积压: pending-review 和 draft deep 数量
```

**产出:** `_lint/YYYY-MM-DD-system-sync.md`

## 三、同步报告格式

```markdown
# System Sync Report YYYY-MM-DD

## 同步状态

| 模块 | 状态 | 详情 |
|------|------|------|
| MOC 覆盖 | ❌ 53/67 缺失 | 需要重建 |
| 审阅覆盖 | ❌ 57/67 未审阅 | 需要批量审阅 |
| Frontmatter | ⚠️ 13 篇缺字段 | 列表见下 |
| 死链 | ⚠️ 25 个 | 列表见下 |
| 可信层 | ⚠️ 22/92 confirmed | 建议 batch review |
| 系统文档 | ⚠️ 系统总览过时 | 需更新数据快照 |
| 概念去重 | ✅ 无重叠 | — |
| Log | ✅ 90/94 | 接近完整 |

## Action Items (按优先级)
1. [高] MOC 重建(覆盖全部 deep/repro)
2. [高] Frontmatter 修补(补缺字段)
3. [高] 死链修复
4. [中] 批量审阅(57 篇待审)
5. [中] 系统文档更新
6. [低] Batch review 扩大 confirmed 范围
```

## 四、谁触发、谁执行

| 触发 | 执行者 | 怎么触发 |
|------|--------|----------|
| 单次同步 | paperwiki-reader skill 自动 | pipeline 最后一步 |
| 全面同步 | 用户手动或每周定时 | "跑一下系统同步" |
| 批量后同步 | 用户手动 | 批量操作完成后说"同步一下系统" |

**关键原则:** 单次同步是自动的(不需要你记得);全面同步是提醒式的(你决定什么时候做)。

---

## 五、与现有模块的关系

```
系统同步 = lint(结构健康) + MOC 刷新(导航) + 审阅检查(质量) + 文档更新(一致性)
```

它不是新模块,而是**把已有能力串成一个检查流程**:
- lint 已有 → 纳入同步
- MOC 刷新已有 → 纳入同步
- 审阅已有 → 纳入同步
- 文档更新 → 纳入同步

区别是:以前各自独立运行(容易遗漏),现在统一成一个检查清单(不会漏)。
