# 2026 下半年 TTS 方向思考

---

## 0. 开场：三个结论

从 SoundStream 到 VoxCPM，我基本完整经历了这一轮 TTS-LLM 的演进。先说三个结论：

1. **半年内主矛盾不再只是"稳"，而是在保稳前提下提升表现力。** 语义/声学拆分解决了可用性，但也把表现力天花板压下来了。
2. **下一个高价值分化点不是单句 TTS，而是上下文与交互。** 单句竞争已经拥挤，真正的应用需求在往段落级、对话级、交互级走。
3. **评价、标注、对齐正在从附加项变成基础设施。** 不建自己的评价和对齐体系，模型迭代就只能靠人工试听。

下面展开讲为什么是这三个判断。

---

## 1. 今天的 TTS 行业，已经不是一个赛道

当前行业不再围绕一个统一答案收敛，而是在不同应用目标下，寻找不同的 Pareto 最优点。

### 1.1 五大路线分化

#### 稳定性路线：先守住可部署性

- 阿里 CosyVoice 系列、智谱 GLM-TTS
- 坚持语义/声学拆分，持续优化稳定性和鲁棒性
- CosyVoice 3 引入 DiffRO 做可微分 Reward 优化，在不动架构的前提下提升质量
- 背后判断：TTS 的首要价值是可靠可部署，先把基本盘守住

#### 表现力路线：先拉高上限

- 字节 DiTAR / DiSTAR、X-LANCE WavTTS
- 连续表征、全量信息、波形直接建模
- DiTAR 已被 ICML 接收，WavTTS 跳过所有 codec 直接在波形空间建模
- 背后判断：未来竞争点是表现力上限，稳定性可以后补

#### 实时交互路线：先抢低延迟入口

- Cartesia（40ms，SSM 架构）、Qwen3-TTS（97ms）
- SSM 替代 Transformer，线性复杂度天然适合端侧
- 背后判断：Voice Agent 的第一约束是实时交互，延迟决定体验

#### 对齐路线：把"好"变成可优化目标

- 字节 SpeechJudge、阿里 DiffRO、阶跃三模式 RLHF、智谱四维 GRPO、Fish Audio GRPO
- 2024 年字节首创 TTS RL，2026 年已成行业标配，从 1 家到 5+ 家
- 背后判断：未来不是随机地好，而是可控地好

#### 平台路线：模型之外，做分发与生态

- ElevenLabs（语音 OS，$11B 估值，$500M ARR）、Fish Audio（开源 31K stars）
- Mistral Voxtral TTS — 开源 TTS 挑战 ElevenLabs
- 背后判断：不只做模型，做语音基础设施

### 1.2 Tokenizer/Codec：分歧最大的技术层

| 路线 | 代表 | 特征 |
|------|------|------|
| 监督语义 token | CosyVoice（阿里） | ASR/TTS 多任务监督，高语义保真 |
| 自监督 token | Mimi（Kyutai/Sesame） | HuBERT 系，无需标注 |
| 双流/双码本 | SAC（Soul/NPU）、StepAudio（阶跃） | 语义声学物理并行 |
| 超低码率 | GLM（智谱，175bps） | 12.5Hz 单 codebook |
| 连续表征 | MingTok-Audio（蚂蚁）、DiTAR（字节） | 非离散，连续 VAE |
| 变长 token | VARSTok（阿里，AAAI 2026 Oral） | 自适应压缩率 |
| 无 codec | WavTTS（X-LANCE/字节）、MELLE | 跳过所有中间表征 |

10+ 种路线并行分化，共识尚未形成。

### 1.3 组织动态：谁在上升，谁在退出

**上升：**
- NPU/ASLP 谢磊组 — Spark-TTS 11K stars，论文产出急剧上升
- CUHK-SZ 武执政 — MaskGCT（ICLR，210 citations），Amphion
- 蚂蚁 Ming — 连续 VAE tokenizer，16B MoE，独特赌注

**退出/收缩：**
- 微软 TTS — 核心团队解体，Xu Tan 离开，NaturalSpeech/VALL-E 停更
- Meta FAIR 语音 — 6 个 speech repo 中 4 个 archived，收购 PlayHT 代替自研
- CMU — Alan Black 退出前沿，北美顶校 TTS 边缘化

### 1.4 已饱和 vs 正在拉开差距

**已饱和（不再是差异化）：**
- 零样本克隆（3-10 秒参考音频）
- 多语言支持（30+ 语种）
- 基本流式能力

**正在拉开差距：**
- Post-training / RL 对齐 — 从探索到标配
- 全双工 / 实时对话 — 首个竞赛 HumDial（ICASSP 2026）
- Codec 设计创新 — 分化最快的技术层
- 长语音一致性 / 多说话人对话 — 空白地带

## 2. 它是怎么走到这里的

行业为什么会从一条路分化成今天这样？回看过去三年，每一次分化都是上一轮方案瓶颈暴露后的必然结果。

### 三阶段速览

| 阶段 | 时间 | 核心选择 | 打开了什么 | 暴露了什么 |
|------|------|----------|-----------|-----------|
| **1. 全量建模** | 2022-2023 | 复用 GPT 范式，全量 RVQ + AR | 零样本克隆第一次可信 | RVQ 层级多、帧率高、AR 管不住 → 幻觉/跳词/不稳定 |
| **2. 信息解耦** | 2024-2025 | SSL/ASR/解耦表征，AR 管语义，Flow/DiT 管声学 | 大规模上线，真实场景落地 | 表现力被压缩，prompt 不鲁棒，克隆音色≠克隆风格 |
| **3. 新范式** | 2025-2026 | 端到端统一 / 连续表征 / Post-training 对齐 | Voice Agent / 播客 / 配音 / Omni | 路线未收敛，快稳好仍难同时最优 |

### 背后的规律

- **新技术出现 → 路线发散**（2022-2023：AudioLM/VALL-E 证明可行性，百花齐放）
- **场景落地 → 路线收敛**（2024-2025：大规模上线诉求，收敛到语义/声学拆分）
- **瓶颈暴露 / 新需求 → 再发散**（2025-2026：表现力天花板 + 上下文/双工/Agent 新需求）

### 当前主流架构（阶段 2 遗产）

```
文本 → [LLM AR] → 语义 token → [Flow Matching / DiT] → 声学特征 → 波形
```

采用者：CosyVoice、Seed-TTS、GLM-TTS、Voxtral TTS、Spark-TTS、StepAudio、Qwen3-TTS

### 正在挑战共识的新路线

- **端到端统一**：DiTAR、WavTTS、VoxCPM — 消除多阶段割裂
- **连续表征**：LatentLM、MELLE、CLEAR — 绕开离散化损失
- **非 AR 并行**：MaskGCT、F5-TTS、LLaDA-TTS — 解决速度
- **Post-training 对齐**：SpeechJudge、DiffRO、GRPO — 让"好"可优化

## 3. 下一阶段，竞争会转向哪里

### 3.1 行业共同面对的三个痛点

#### 痛点 1：表现力天花板 — 稳了，但不够活

语义/声学拆分让发音稳定了，但情感、副语言、音量等信息在拆分时丢失，下游补不回来。一句话 prompt 只能克隆音色，克隆不了说话风格。海量用户场景下，对 prompt 质量不鲁棒，很多音色直接崩溃或不像。

**我们的验证：** 我们从 VALL-E 转向 semantic tokenizer 路线，做到 PilotTTS 2.0，2025 年初基础模型指标做到了 SOTA。但进入情感合成后发现，切换情感时音色会跑偏，发音稳定性也必然下降。当前只能离线合成 + 缓存，人工选取效果好的 demo，还做不到实时在线服务。这说明表现力不是"加一个 style 模块"就能解决的 — 根源是缺乏对应的训练数据，而现有架构的表征能力也在这里遇到了天花板。

#### 痛点 2：从单句到多场景 — 能说，但不知道该怎么说

单句 TTS 在通用朗读场景已经基本够用，但真正的应用需求在往段落级、对话级、交互级走。长语音的跨句一致性、对话级的韵律衔接、多场景的风格自适应，这些都是当前系统做不好的。

**我们的验证：** 做 VoiceAgent 支持时发现，核心难点不是单一场景做不好，而是要同时兼容太多场景 — 导航、讲故事、闲聊、专业术语、客服，每个场景的文本格式差异很大，标点不规范，需要的语音风格完全不同。模型必须在同一套系统里处理这些多样性。这要求的不只是"给什么文本说什么文本"，而是场景自适应的表达能力。

#### 痛点 3：质量迭代没有闭环 — 靠人工试听，不可持续

没有属性级评价体系，就无法系统地度量"好不好"；没有 reward model，就无法自动优化；没有标注闭环，就只能靠人工试听来判断质量。

**我们的验证：** 做方言和情感时，务实的思路是先收窄范围（情感只做开心、安慰、讲故事几类，方言只做有限几种），在受控范围内通过人工标注 + DPO 把质量拉上来，再逐步扩展。这说明人工标注和对齐不是锦上添花 — 离开它，质量就只能靠运气。

#### 三个痛点的共同根因

这三个问题表面上各不相同，但本质上是同一个问题：**数据缺失。** 情感语音没有大规模高质量标注数据，方言更缺，VoiceAgent 的多场景多风格数据几乎不存在。基础模型在通用朗读语音上做到了 SOTA，但一旦走向细分场景，训练数据就断层了。

下一阶段的竞争，不只是模型架构的竞争，更是**用算法弥补数据缺口**的竞争。

### 3.2 趋势判断

| 方向 | 信号 | 判断 |
|------|------|------|
| **Post-training 成为标配** | 2024 年 1 家 → 2026 年 5+ 家 | 没有 RM/对齐的团队会越来越被动 |
| **从单句走向上下文** | 播客/长语音/多说话人对话需求起来 | 跨句一致性、段落韵律成为新竞争维度 |
| **Codec 路线继续分化** | 10+ 种路线并行 | 短期不会收敛，选择能力比技术能力更重要 |
| **全双工 / Voice Agent** | HumDial 竞赛、ElevenAgents 2M+ agent | 从研究进入产品阶段 |
| **评估标准之争** | SEED-TTS-Eval 由字节主导 | 谁定义评估，谁定义方向 |

### 3.3 独立 TTS vs LLM-native

趋势：Qwen-Omni、Gemini Flash TTS — 语音正在成为 LLM 原生输出模态。

半年维度下不是主矛盾：
- 专用场景（影视配音/音色克隆/歌声）的训练数据，通用模型拿不到 — merge 的瓶颈是数据，不是模型能力
- TTS 的基础能力（快稳好）本身还没解好
- 更远的图景：语音 OS — 不同任务分流到不同 pipeline，强模型逐步 merge

### 3.4 空白地带（机会窗口）

| 空白 | 现状 | 潜在价值 |
|------|------|----------|
| 长文本一致性（> 10 分钟） | 仅 SoulX-Podcast（5 分钟+） | 有声书/播客需小时级一致性 |
| 多说话人对话（3+ 人） | 仅 JoyVoice（8 人） | 会议/播客/影视配音 |
| 端侧部署（< 1B） | 仅 Cartesia Edge | 手机/IoT/车载 |
| 对话韵律建模 | 仅 Sesame CSM | 打断/犹豫/共情 |
| 独立第三方评估 | SEED-TTS-Eval 由字节主导 | 需要更中立的基准 |

## 4. 我们的机会在哪里

### 判断 1：先做有限类别，不做开放世界

一上来追求"任意情感、任意方言、任意场景"在工程上根本没法验证，也没法形成稳定闭环。务实的思路是先收窄范围，在有限的、高价值的类别上做到充分验证和稳定上线。

**动作：**
- 情感先收敛到几类（开心、安慰、讲故事等），方言先做有限几种
- VoiceAgent 先聚焦少数明确的高价值场景，不铺全量
- 在受控范围内把质量彻底拉上来，再逐步扩展
- 指标：不是"能做出几个惊艳 demo"，而是"类别级可上线"

### 判断 2：先把"稳定可控"做实，再谈更大泛化

情感/方言一增强，稳定性就下降 — 这是当前架构的核心矛盾。表现力和稳定性的跷跷板不解决，泛化就是空谈。

**动作：**
- token/codec 不再只看语义压缩，要评估双流/连续/多尺度对表现力天花板的提升
- 短期：更大模型 + 更强 prompt/style module，在现有架构内挖潜
- 中期：验证更高信息密度表征，突破当前架构的表现力天花板
- 衡量标准：SIM/CER 不退的前提下，风格与情感跟随显著提升

### 判断 3：评价和对齐是必须投入的基础设施

没有评价体系，就永远只能"挑 demo"；没有对齐闭环，质量迭代就只能靠人工试听。字节从 RL 到 SpeechJudge，阿里从 DiffRO 到 CosyVoice 3，已经证明这条路有效。

**动作：**
- 搭建属性级评价体系（不只是 MOS，要有情感/风格/韵律分维度评价）
- 做人工标注 + 偏好数据采集
- 做 instruct-following / style-following reward model
- 建立从标注 → RM → post-training → 新数据的完整闭环
- 让"说得对"不只指文本正确，也包括表达正确

---

## 收束

### 优先级

1. **选定有限高价值类别，做到类别级可上线** — 不贪大求全
2. **并行搭评价/对齐基础设施** — 这是未来的复利项，也是从"挑 demo"走向"系统优化"的前提
3. **上下文/交互作为下一跳** — 不和主线争资源，但要开始建数据和评测

### 一句话总结

TTS 这两年已经把"能不能说"基本解决了，但离"能不能在真实场景里稳定地、合适地说"还有明显距离。下一阶段最重要的，不是盲目追求开放世界能力，而是选定有限但高价值的类别，把表达稳定性、评价体系和对齐闭环真正做实。
