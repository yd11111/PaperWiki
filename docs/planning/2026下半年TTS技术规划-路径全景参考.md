# Instruct + 上下文 Conditioning: 路径全景

> 生成时间: 2026-06-09 | 数据源: PaperWiki 本地 KB (529 篇论文笔记) | 不含推荐/排序

## 一、控制信号输入方式

### 路径 1: 固定标签 (Tag-based / Categorical Labels)
- **做法**: 预定义离散情感/风格类别 (happy/sad/angry/...), 通过 one-hot 或 embedding lookup 注入模型
- **代表**: EmoSphere-TTS (AVD 球面坐标, Interspeech 2024), FastSpeech 2 + emotion ID, Daisy-TTS (PCA 分解)
- **指标**: EmoSphere-TTS ECA 94.02% / nMOS 3.88 (ESD)
- **优势**: 实现简单; 训练稳定; 控制确定性高
- **劣势**: 类别数受限于标注; 无法表达连续变化和混合情感; 跨域泛化弱
- **成熟度**: 高 (已工业部署)

### 路径 2: 模板化自然语言 (Structured NL Description)
- **做法**: 预定义属性模板 (gender/pitch/speed/volume/emotion), 用 slot-filling 方式描述
- **代表**: PromptTTS (5 属性模板, 2023), TextrolSpeech (SpeechCraft, 2024)
- **指标**: PromptTTS 原论文未见标准 benchmark
- **优势**: 比标签更灵活; 描述可读性好; 评估相对容易
- **劣势**: 本质仍是预定义属性的排列组合; 无法处理"像暴怒的王子"等高层指令
- **成熟度**: 高

### 路径 3: 自由文本描述 (Freestyle NL Description)
- **做法**: 允许自由格式自然语言描述风格/情感, 通过专用 style encoder 或 LLM 理解
- **代表**: InstructTTS (2023, RoBERTa 3-stage), EmoVoice (2025, Qwen2.5 LLM), CapSpeech (2025, BERT/CLAP), Parler-TTS (2024), HiStyle (2025, hierarchical diffusion predictor), MOSS-VoiceGenerator (2026)
- **指标**: InstructTTS MOS 4.35 / RMOS 4.22; EmoVoice Emo_Sim 0.9118; MOSS-VoiceGenerator DSD 82.0%
- **优势**: 表达力强; 用户友好; 可覆盖训练未见风格
- **劣势**: 需要大量 NL-speech 配对数据; 评估困难; 控制精度不如结构化标签
- **成熟度**: 中高

### 路径 4: 开放词汇 + 推理链 (Open-Vocabulary + Reasoning Chain)
- **做法**: 接受来自叙事上下文的高层开放指令, 通过 LLM CoT 推理分解为可执行的声学属性
- **代表**: OV-InstructTTS (2026, LALM reasoning chain), BatonVoice (2025, LLM → vocal features JSON)
- **指标**: OV-InstructTTS Gemini Score 70.42 / MOS 4.28; BatonVoice Emotion Acc 57.6%
- **优势**: 覆盖面最广; 可处理从未见过的高层指令; 可解释中间推理
- **劣势**: 依赖强 LLM; 推理链增加延迟; 链条中错误累积
- **成熟度**: 低 (前沿探索)

### 路径 5: 参考音频 (Reference Speech Prompt)
- **做法**: 从参考音频中提取 style embedding, 注入目标合成
- **代表**: GST (2018), CosyVoice 系列 (speech tokens as style prompt), Spotlight-TTS (voiced-aware RVQ), FC-TTS (dual-reference), AutoStyle-TTS (RAG 检索参考)
- **指标**: FC-TTS UTMOS 4.22; CosyVoice 3 SS 0.775
- **优势**: 最直观; 不需要标注; 可传递细粒度韵律
- **劣势**: 需要找到合适参考; 容易泄漏说话人信息; 不可解释
- **成熟度**: 高

### 路径 6: 多模态指令 (Multimodal Prompts)
- **做法**: 接受视觉/音频/文本多模态输入, 通过对比学习对齐为统一情感表示
- **代表**: UMETTS (2024, 视觉+音频+文本 → EP-Align → VITS/FS2), ImmersiveTTS (2026, MM-DiT + CLAP 环境文本)
- **指标**: UMETTS ESMOS 4.37 (ESD); ImmersiveTTS WER 8.06% / CLAP 0.308
- **优势**: 可从图像/视频中获取情感线索; 适合影视配音场景
- **劣势**: 跨模态对齐难度大; 数据稀缺; 评估体系不成熟
- **成熟度**: 低

### 路径 7: 隐式推断 (从文本内容/对话上下文自动推断)
- **做法**: 不需要显式风格指令, 模型从待合成文本或对话历史自动推断合适的韵律/情感
- **代表**: FireRedTTS-2 (2025, text-speech interleaved format 隐式上下文), SASLM (2026, VIB 自蒸馏), Chain-Talker (2025, chain understanding), ControllingEmotionTTSNLPrompts (2024, 用文本自身作为情感 prompt)
- **指标**: SASLM F0-Var 63.44 / EmoAlign 35.61%; FireRedTTS-2 Emotion Acc 83-93%
- **优势**: 零用户负担; 最符合有声书/对话场景; 上下文连贯
- **劣势**: 不可控 (用户无法覆盖推断结果); 需要大量上下文理解训练; 隐式推断不可解释
- **成熟度**: 中

### 路径 8: 可量化声学特征 (Operationalized Vocal Features)
- **做法**: 将抽象指令分解为可量化的声学特征 (pitch Hz, energy dB, spectral centroid Hz), 作为中间表示
- **代表**: BatonVoice (2025, operationalism 框架), MAGIC-TTS (2026, token-level duration/pause 数值)
- **指标**: BatonVoice Emotion Acc 57.6%; MAGIC-TTS C-MAE 10.56ms / C-Corr 0.918
- **优势**: 精确可验证; LLM 和 TTS 各做擅长的事; 中间表示可调试
- **劣势**: 特征维度有限; 并非所有风格都可量化; 需要额外 LLM 调用
- **成熟度**: 低

## 二、控制实现机制

### 路径 A: LLM 隐式编码 (LLM as Implicit Controller)
- **做法**: 将风格/情感信息作为文本 token 输入 LLM, 让 LLM 在自回归过程中隐式编码到生成的 speech tokens 中
- **代表**: CosyVoice 2/3 (instruct mode), EmoVoice (Qwen2.5 backbone), OV-InstructTTS (LALM)
- **指标**: CosyVoice 3 CER 0.71% / SS 0.775; EmoVoice Emo_Sim 0.9118
- **优势**: 架构简单; 利用 LLM 文本理解能力; 端到端训练
- **劣势**: 控制精度依赖训练数据; 可解释性差; 指令遵循率有天花板
- **成熟度**: 高

### 路径 B: 独立 Style Encoder (BERT/CLAP/RoBERTa)
- **做法**: 用预训练语言模型编码 NL description 为 style embedding, 通过 cross-attention 或 AdaLN 注入 TTS
- **代表**: InstructTTS (RoBERTa 3-stage), HiStyle (BERT + diffusion predictor), CapSpeech (CLAP embedding), ControllingEmotionTTSNLPrompts (DistilRoBERTa)
- **指标**: InstructTTS RMOS 4.22; HiStyle Style-MOS 3.71
- **优势**: 可利用预训练语义知识; 模块化易替换; 训练数据需求适中
- **劣势**: 跨模态对齐质量受限; 固定 encoder 表达力有上限; 通常 utterance-level 粒度
- **成熟度**: 中高

### 路径 C: 分层 Preference Tokens (HD-PPT)
- **做法**: 将 speech tokens 分解为 content-preference 和 prompt-preference 两种中间表征, LLM 分层级预测
- **代表**: HD-PPT (2026, ASR + CLAP 双监督 FSQ)
- **指标**: MOS-N 4.108 / MOS-S 4.167; EMO-SIM 0.753 (vs CosyVoice 2 的 0.714)
- **优势**: 结构化解耦使控制更精准; CLAP 监督让 preference token 与指令语义对齐
- **劣势**: 多组件设计复杂; RTF 0.952 较慢; 需要额外 codec 训练
- **成熟度**: 低

### 路径 D: Cross-Attention 注入
- **做法**: 用 cross-attention 将 style/context embedding 注入 decoder 各层
- **代表**: Chain-Talker (BERT caption → cross-attention → OT-CFM), DiffCSS (diffusion prosody emb → cross-attention → ParlerTTS), FC-TTS (Style Adapter via cross-attention)
- **指标**: Chain-Talker DMOS-E 4.239; FC-TTS UTMOS 4.22
- **优势**: 灵活; 可多层注入不同粒度信息; 成熟技术
- **劣势**: 增加计算量; 需要精心设计 query/key/value; 容易过拟合
- **成熟度**: 高

### 路径 E: Adapter/LoRA 切换
- **做法**: 为不同风格训练不同的 adapter/LoRA 参数, 推理时切换
- **代表**: FlexSpeech (DPO 微调 duration predictor), EmoShift (learnable steering 10M params)
- **指标**: FlexSpeech WER 1.20% / SMOS 3.93; EmoShift 超越全参数微调的情感表现力
- **优势**: 参数高效; 不影响基座模型; 可组合多个 adapter
- **劣势**: 需要每种风格单独训练; 组合效果不可预测; 不支持连续控制
- **成熟度**: 中

### 路径 F: Classifier-Free Guidance (CFG)
- **做法**: 训练时随机 mask style condition, 推理时用条件/无条件 logits 差异放大控制信号
- **代表**: InstructTTS (discrete diffusion + CFG), MAEStyle-RichTTS (AR LM logit CFG), CosyVoice 系列, CodecLMSpontaneousStyle (dual-stage CFG)
- **指标**: MAEStyle-RichTTS Aro 78.0% / Dom 80.9% (CFG=2.0/3.0)
- **优势**: 训练简单; 推理时可调节强度; 适用于 diffusion/flow/AR 多种架构
- **劣势**: 推理变慢 (需两次 forward); 高 guidance scale 损害自然度; 对细粒度控制不够精准
- **成熟度**: 高

### 路径 G: Multi-Agent 闭环反馈
- **做法**: 多个 agent 协作 (生成/评估/纠正), 通过推理时反馈循环迭代改进
- **代表**: AgentSteerTTS (2026, ADM + DAC + Fast-Slow Feedback, ICML)
- **指标**: E-SIM 0.955 / S-SIM 0.841 / CSR 0.78
- **优势**: 可处理 composite instruction; 闭环校准提升精度; 解耦使各组件可独立优化
- **劣势**: 推理延迟大; 依赖外部 MLLM; 组件组合复杂; prototype library 维护成本
- **成熟度**: 低

### 路径 H: FiLM / Conditional Layer Normalization (AdaLN)
- **做法**: 将 style embedding 通过 affine transformation (scale + shift) 注入各层 normalization
- **代表**: InstructTTS (SALN Adaptor), FC-TTS (Timbre Adapter via AdaLN), SASLM (VIB → AdaLN 注入), FineGrainedStyleControl (embedding 方向向量注入)
- **指标**: SASLM Overall 4.33; FC-TTS UTMOS 4.22
- **优势**: 计算开销小; 全局条件化有效; 不改变序列长度
- **劣势**: 通常仅支持全局条件; 不适合帧级精细控制; scale/shift 表达力有限
- **成熟度**: 高

### 路径 I: Contrastive Learning 对齐 (CLIP-style)
- **做法**: 用对比学习对齐 text description 和 speech 的 embedding 空间
- **代表**: InstructTTS (Stage 3 cross-modal metric learning), HD-PPT (CLAP 监督), UMETTS (EP-Align), HiStyle (contrastive loss), SelfTTS (MPCL)
- **指标**: HD-PPT EMO-SIM 0.753; UMETTS SECS 0.896
- **优势**: 不需要 one-to-one 标注; 学到的空间可泛化; 与文本对齐直观
- **劣势**: 负样本选取影响大; batch size 要求高; 对连续属性不如回归
- **成熟度**: 中高

### 路径 J: AdaLN-Zero / DiT 条件注入
- **做法**: 在 Diffusion/Flow Transformer (DiT) 中使用 AdaLN-Zero (零初始化的自适应层归一化)
- **代表**: FC-TTS (CFM Decoder DiT + adaLN-Zero), TTS-CtrlNet (emotion → ControlNet DiT blocks), ImmersiveTTS (MM-DiT + AdaLN)
- **指标**: TTS-CtrlNet Emo-SIM 0.751; ImmersiveTTS SN-MOS 4.20
- **优势**: DiT 架构原生支持; 零初始化保证训练稳定; 每层独立调制
- **劣势**: 仅适用于 DiT 架构; 增加参数量; 通常需要全量训练
- **成熟度**: 中高

### 路径 K: Training-free Attention Manipulation
- **做法**: 推理时修改 attention mask/KV-cache/attention weights, 不改模型参数
- **代表**: TED-TTS (2D causal mask + MSA), FineGrainedStyleControl (KV-cache swap + sliding-window mask), DUET (hidden space steering + mel-space guidance)
- **指标**: TED-TTS SMOS 4.00-4.22 / Duration error 3.21-3.39%; FineGrainedStyleControl gender 转换 99-100%
- **优势**: 零训练成本; 即插即用; 跨模型迁移; 保留原始模型质量
- **劣势**: 控制范围受限于原始模型能力; 需要理解内部表征; 不稳定
- **成熟度**: 中

### 路径 L: Activation Steering (Difference-in-Means)
- **做法**: 从情感/中性语音对中提取激活差异向量, 推理时注入中间层
- **代表**: EmoSteer-TTS (2025, flow-matching DiT), CoCoEmo (2026, SLM attn_output), EmoShift (2026, learnable steering), DUET (2026, dual-space)
- **指标**: CoCoEmo E-SIM 0.862 / TEP 0.504; DUET Avg 75.5%; EmoShift 超越全参数微调
- **优势**: Training-free (EmoSteer/CoCoEmo/DUET) 或极轻量 (EmoShift 10M); 可组合混合情感; 方向可解释
- **劣势**: 仅支持有限类别; 高强度时质量退化; 需要情感标注数据做 probing
- **成熟度**: 中

### 路径 M: ControlNet 旁挂
- **做法**: 冻结原始模型, 训练可学习副本作为控制旁路, 通过 zero-conv 注入
- **代表**: TTS-CtrlNet (2025, F5-TTS + ControlNet + emotion)
- **指标**: Emo-SIM 0.751 / Aro-Val SIM 0.742 (超越 EmoCtrl-TTS); WER 0.6%
- **优势**: 不影响原始模型; 低数据量 (~400h); 保留 zero-shot 能力; 可选择性连接
- **劣势**: 参数翻倍; 仅验证 F5-TTS; emotion-specific flow step 发现可能不通用
- **成熟度**: 中

### 路径 N: Two-Stage Pipeline (Control → Generation)
- **做法**: 第一阶段从控制信号生成中间 style tokens, 第二阶段从 style tokens 生成声学特征
- **代表**: MAEStyle-RichTTS (2025, Style LM → Acoustic LM), HD-PPT (content-pref → prompt-pref → speech), HiStyle (speaker predictor → style predictor)
- **指标**: MAEStyle-RichTTS UTMOS 3.63 / SIM 0.90; HD-PPT EMO-SIM 0.753
- **优势**: 数据解耦 (控制阶段可用低质量大数据, 生成阶段用高质量小数据); 中间表示可调试
- **劣势**: 级联错误; 训练复杂; 推理慢
- **成熟度**: 中

### 路径 O: VIB 自蒸馏 (Variational Information Bottleneck)
- **做法**: 从 LLM 自身 hidden state 通过信息瓶颈蒸馏出 expressive intent, 再通过 AdaLN 注入
- **代表**: SASLM (2026, VIB + OU prior + self-reward alignment)
- **指标**: F0-Var 63.44 (vs Qwen3-Omni-30B 49.76), EmoAlign 35.61%
- **优势**: 不需要任何外部情感标注; proxy-free; 自闭环验证一致性
- **劣势**: 仅 3B 参数验证; WER 有退化 (4.56%); 训练复杂 (VIB + UAPO)
- **成熟度**: 低 (极前沿)

### 路径 P: GRL 对抗解耦 (Gradient Reversal Layer)
- **做法**: 用双向 GRL + 正交约束分离 speaker 和 emotion 子空间
- **代表**: AgentSteerTTS (ADM 双编码器), SelfTTS (cosine-based GRL), IndexTTS2 (CE-based GRL)
- **指标**: AgentSteerTTS E-SIM 0.955; SelfTTS EECS 0.8423 / CKA 0.0139
- **优势**: 显式解耦; 数学动机清晰; 可验证正交性
- **劣势**: 训练不稳定; GRL 超参敏感; 需要平衡重建和对抗损失
- **成熟度**: 中

## 三、上下文建模方式

### 路径 alpha: 无上下文 (单句独立)
- **做法**: 每句独立合成, 不利用前后文信息
- **代表**: 大多数 zero-shot TTS (CosyVoice, VALL-E, MaskGCT)
- **优势**: 简单; 可并行; 无上下文泄露风险
- **劣势**: 语篇连贯性差; 无法自然渐变; 不适合长文本
- **适用**: 短文本 / 独立句子 / 语音助手单轮回复

### 路径 beta: Text-Speech Interleaved 格式
- **做法**: 将多轮对话的文本和语音 token 交织为单一序列, LLM 自回归建模
- **代表**: FireRedTTS-2 (2025, [S1]text+audio[S2]text+audio...), Moshi (2024), Spirit-LM (2024)
- **指标**: FireRedTTS-2 Emotion Acc 83-93%; CER 1.14% (ZH)
- **优势**: 天然支持多说话人; LLM 可从前文学习韵律模式; 支持流式
- **劣势**: 序列极长 (需 12.5Hz 压缩); 上下文窗口有限; 前文错误传播
- **成熟度**: 中

### 路径 gamma: Plug-and-play Context Encoder
- **做法**: 独立的上下文编码器从对话历史提取 embedding, 注入当前句 TTS
- **代表**: MFCIG-CSS (2025, 双图 SIG+PIG GraphSAGE), M2-CTTS (多粒度), CCATTS (GRU), ChatGPT-EDSS (LLM 生成 context words → BERT embedding)
- **指标**: MFCIG-CSS N-DMOS 3.980; ChatGPT-EDSS MOS 3.52
- **优势**: 模块化; 可与不同 TTS backbone 组合; 上下文粒度可控
- **劣势**: 额外组件增加复杂度; 编码质量是瓶颈; 通常仅支持固定轮数
- **成熟度**: 中

### 路径 delta: LLM CoT 推理链
- **做法**: LLM 先从上下文推理出应有的情感/风格描述, 再条件化 TTS 生成
- **代表**: OV-InstructTTS (2026, </think/> reasoning chain), Chain-Talker (2025, empathetic caption → semantic codes → rendering), BatonVoice (2025, LLM → vocal features)
- **指标**: OV-InstructTTS Gemini Score 70.42; Chain-Talker DMOS-E 4.239
- **优势**: 可解释; 推理过程可调试; 充分利用 LLM 语义理解能力
- **劣势**: 推理延迟大; 依赖外部 LLM; 错误累积
- **成熟度**: 低

### 路径 epsilon: RAG 检索增强 (Retrieval-Augmented Generation)
- **做法**: 从知识库中检索与当前文本匹配的 style prompt 或 acoustic prototype
- **代表**: AutoStyle-TTS (2025, 三维 embedding 检索 style prompt), AgentSteerTTS (DAC prototype retrieval), RADKA-CSS (RAG + 多粒度异构图)
- **指标**: AutoStyle-TTS SM-MOS 3.85/3.90 (vs CosyVoice 3.35/3.38)
- **优势**: 动态适配; 可不断扩充知识库; 无需重训模型; 多样性好
- **劣势**: 检索质量是瓶颈; 知识库构建成本; 检索延迟; 覆盖不足时退化
- **成熟度**: 中

### 路径 zeta: Diffusion 多样性采样
- **做法**: 用 diffusion model 从对话上下文条件分布中采样韵律嵌入, 实现 one-to-many
- **代表**: DiffCSS (2025, diffusion prosody embedding generator)
- **指标**: DiffCSS 在 ParlerTTS backbone 上实现韵律多样性
- **优势**: 自然处理 one-to-many mapping; 韵律多样性好; 避免 mode collapse
- **劣势**: 训练复杂; 生成不确定性可能导致不一致; 需要对话韵律数据
- **成熟度**: 低

### 路径 eta: GNN/图编码器
- **做法**: 将对话历史建模为图结构, 用 GNN 传播词级/句级交互信息
- **代表**: MFCIG-CSS (2025, 双图 SIG+PIG, GraphSAGE), MSRGCN-CSS (多尺度关系图), ECSS (异构图)
- **指标**: MFCIG-CSS N-DMOS 3.980 / P-DMOS 3.899
- **优势**: 显式建模交互关系; 可捕捉长距离依赖; 多粒度灵活
- **劣势**: 图构建开销; 仅在小数据集验证; 不适合流式; 与 LLM-TTS 集成困难
- **成熟度**: 中低

### 路径 theta: VIB 自蒸馏 (Self-Distillation)
- **做法**: 从 LLM 自身语义生成动态中蒸馏表达意图, 无需外部上下文编码器
- **代表**: SASLM (2026, VIB + OU temporal prior)
- **指标**: F0-Var 63.44; EmoAlign 35.61%
- **优势**: 零外部依赖; 内生意图建模; OU prior 建模时序平滑
- **劣势**: 极度前沿; 训练复杂; 仅英文验证; 规模有限
- **成熟度**: 极低

### 路径 iota: 多模态上下文 (文本+音频历史)
- **做法**: 同时利用文本和语音历史的多模态信息建模上下文
- **代表**: Chain-Talker (text+speech unified tokenization), MFCIG-CSS (TOD-BERT text + Wav2Vec2.0 speech), I3-CSS (模态内+模态间交互)
- **指标**: Chain-Talker SSIM 0.862 / DMOS-E 4.239
- **优势**: 信息更完整; 语音历史提供真实韵律参照; 多模态互补
- **劣势**: 对齐困难; 音频编码增加计算; 需要 aligned 数据
- **成熟度**: 中

### 路径 kappa: 三阶段课程学习 (Curriculum Learning)
- **做法**: 先在大规模独白数据预训练 → 对话数据后训练 → SFT 微调
- **代表**: FireRedTTS-2 (mono pretraining → dialogue post-training → SFT)
- **指标**: FireRedTTS-2 podcast 56% win/even vs GT
- **优势**: 充分利用独白数据; 逐步引入上下文能力; 训练稳定
- **劣势**: 三阶段训练成本; 需要大量对话数据; 灾难性遗忘风险
- **成熟度**: 中

## 五、数据构建路径

### LLM 合成标注
- **做法**: 用 GPT-4o/Qwen3/DeepSeek 等生成 style description/emotion label/instruction
- **代表**: OV-InstructTTS (Qwen3-32B 生成开放指令), EmoVoice (GPT-4o-audio 蒸馏), Chain-Talker (CSS-EmCap Gemini pipeline), ChatGPT-EDSS (ChatGPT 生成 IES 词), MOSS-VoiceGenerator (LLM 生成影视角色描述)
- **规模**: EmoVoice 40h; OV-InstructTTS 476.8h; MOSS-VoiceGenerator 18K+7Kh

### 人工精标
- **做法**: 人工标注 emotion/style 标签或 NL description
- **代表**: ESD (5 emotions, 10 speakers), TextrolSpeech, EmoVoice-DB
- **规模**: 通常数十到数百小时

### 自动特征提取 (SER/Prosody Tools)
- **做法**: 用 emotion2vec/wav2vec/CLAP 等工具自动提取声学属性
- **代表**: EmoSphere-TTS (wav2vec 2.0 SER → AVD 伪标签), MAEStyle-RichTTS (自动 pitch/energy/SNR 标注), CapSpeech (自动 9 维风格属性), HiStyle (统计阈值 + 人类感知迭代)
- **优势**: 可大规模获取; 无需人工标注
- **劣势**: 伪标签噪声; 维度有限; 准确性受限于工具

### Self-supervised / 自监督
- **做法**: 从语音自身学习风格表征, 无需标注
- **代表**: Spotlight-TTS (voiced-aware RVQ 自动学习 style tokens), MAEStyle-RichTTS (MAE mask-reconstruction), GST (无监督 style token bank)
- **优势**: 零标注成本; 表征不受标签限制
- **劣势**: 不可解释; 无法指定具体控制维度

### 弱监督 / 半监督
- **做法**: 用少量标注 + 大量无标注数据
- **代表**: WeSCon (self-training from 500h), FlexSpeech (DPO ~50 对), EmoShift (ESD 5 epochs)
- **优势**: 标注成本低; 可迁移到新域

### 合成数据 (VC/TTS-generated)
- **做法**: 用已有 TTS/VC 系统生成训练样本
- **代表**: SelfTTS (self-augmentation via VC), EmoVoice (GPT-4o-audio 合成), Affectron (NV 增强样本构造)
- **优势**: 可无限扩展; 可控制属性
- **劣势**: domain gap; 合成伪影; 需要高质量种子系统

### 影视/真实世界数据挖掘
- **做法**: 从影视/播客/自发语音中采集 + 去噪过滤
- **代表**: MOSS-VoiceGenerator (影视数据 + style-guided mining), Audiobook-CC
- **优势**: 真实多样; 含自然韵律变化; 覆盖面广
- **劣势**: 噪声大; 去噪可能引入伪影; 版权问题

## 七、关键观察 (仅事实总结, 非推荐)

1. **趋势分裂**: 控制方式从 "固定标签" 向两端分化 -- 一端是 "完全隐式" (SASLM, FireRedTTS-2), 另一端是 "高层开放指令 + 推理链" (OV-InstructTTS, BatonVoice)
2. **Training-free 路线崛起**: 2025-2026 涌现大量 training-free 方法 (EmoSteer/CoCoEmo/DUET/TED-TTS/FineGrainedStyleControl), 通过操控预训练模型内部表征实现控制
3. **上下文建模仍是瓶颈**: 大多数系统仍是句级独立合成, 篇章级连贯性系统 (FireRedTTS-2, Chain-Talker) 尚处早期
4. **数据构建 > 模型创新**: 2025-2026 年多篇论文的核心贡献在数据工程而非架构 (OV-InstructTTS, CapSpeech, MOSS-VoiceGenerator, EmoVoice)
5. **CosyVoice 系列成为事实标准 backbone**: HD-PPT, EmoVoice, BatonVoice, CoCoEmo, TED-TTS, EmoShift 等均基于 CosyVoice/CosyVoice2 构建

# 效率优化: 路径全景

> 调研来源: PaperWiki 本地 KB (529 篇论文笔记 + 96 实体页) + 网络搜索
> 生成日期: 2026-06-09
> 不做推荐,不做排序,仅列出所有可行路径

---

## A. 帧率压缩路径 (降低 AR 序列长度)

### 路径 1: 监督式 ASR encoder 降采样 (CosyVoice 路线)

- **做法**: 在预训练 ASR encoder (如 SenseVoice/Whisper/MinMo) 的中间层插入 VQ/FSQ 量化模块,利用 ASR 训练目标保证语义信息;帧率由 encoder 下采样率决定 (典型 25Hz)
- **代表系统/论文**: CosyVoice 2 (FSQ-SenseVoice, 25Hz, 6561 codes); CosyVoice 3 (FSQ-MinMo, 25Hz); FireRedTTS 2 (Whisper + RVQ, 12.5Hz)
- **已知指标**: CosyVoice 2: WER 2.45%, SIM 0.751, codebook utilization 100%; CosyVoice 3: WER 1.45%, SIM 0.775; FireRedTTS 2: CER 1.14%, SIM 0.736
- **优势**: 语义一致性强 (ASR loss 保证); 帧率可控 (改变 encoder stride); codebook 利用率高 (FSQ)
- **劣势**: 依赖预训练 ASR 模型; tokenizer 与 ASR 模型耦合; 不同语言 ASR 质量差异导致 TTS 质量差异
- **成熟度**: 高 (工业级验证,CosyVoice 系列已广泛部署)

### 路径 2: 自监督降采样 (HuBERT/W2V-BERT + k-means)

- **做法**: 取 SSL 模型中间层 (如 HuBERT layer 9) 的连续表征,按固定宽度分段做均值池化,再用 k-means 聚类得到离散 token
- **代表系统/论文**: GSLM (50Hz); SpeechTokenizationforSLM (2025, 系统探索 N=20-280ms, K=128-16384); NAST (2024, Gumbel-Softmax 端到端可学习); BASE TTS (WavLM speechcodes + BPE)
- **已知指标**: SpeechTokenizationforSLM: N=80ms (12.5Hz), K=16384 为最佳配置, 训练时间 -70%; BASE TTS: BPE 将 speechcode 序列长度减少 40%
- **优势**: 不依赖标注数据; BPE 可进一步压缩序列; 可灵活选择层和帧率
- **劣势**: k-means 不可微,无法端到端优化; 对噪声敏感 (NAST 尝试解决); 重建需要额外声学模型
- **成熟度**: 中 (学术验证充分,工业应用少)

### 路径 3: 大码本单码本 (K=8K-131K, 消除多层 RVQ)

- **做法**: 用极大的单层 codebook (8192-131072) 替代多层 RVQ,通过 model scaling (大 encoder/decoder) 补偿单码本的表达力不足
- **代表系统/论文**: BigCodec (K=8192, 80Hz, 159M params, 1.04kbps); WavTokenizer (K=4096, 40Hz/75Hz); Llasa/X-Codec2 (K=65536, FSQ, 50Hz); UniTTS/DistilCodec (K=32768, 多码本→单码本蒸馏)
- **已知指标**: BigCodec: MUSHRA 92.33 (>GT 91.84), SIM 0.84, RTF 1.1x; Llasa: WER 2.499%, SIM 0.575; UniTTS: codebook usage 98-99.9%
- **优势**: LM 只需预测一层 token,序列结构简单; 与标准 NLP LM 完全对齐; 无 delay pattern 等复杂设计
- **劣势**: 大码本→大 embedding table→显存开销; 帧率仍可能偏高 (50-80Hz); 重建质量可能不如 RVQ
- **成熟度**: 高 (Llasa/Spark-TTS 已开源验证)

### 路径 4: 极低帧率 + Diffusion Decoder (TaDiCodec 6.25Hz)

- **做法**: 将帧率压到极低 (6.25Hz),用 diffusion/flow matching decoder 补偿极端压缩带来的信息损失;解码时需要文本条件辅助
- **代表系统/论文**: TaDiCodec (6.25Hz, BSQ K=16384, 0.0875kbps, DiT decoder + text conditioning); HALL-E (低帧率 hierarchical codec LM)
- **已知指标**: TaDiCodec: 重建 WER 2.73, SIM 0.69, UTMOS 3.73; TTS-AR: WER 2.28(en)/1.19(zh); RTF 0.12-0.29
- **优势**: 极端压缩 (10秒音频仅~63 tokens); LM 建模极其轻量; 理论上最短 AR 序列
- **劣势**: Diffusion decoder 多步推理带来解码延迟; 需要 text 输入做 de-tokenization (不再是纯 codec); 仅验证了 TTS,未验证 understanding
- **成熟度**: 低 (2025.05 发表,尚无后续验证)

### 路径 5: 连续 VAE Latent + Patchification (DiTAR 路线)

- **做法**: 用 VAE 将语音编码为连续 latent (不做离散量化),再对 latent 序列做 patchification (P 个 token 聚合为一个 patch),LM 在 patch 级别做 AR 预测,每个 patch 内用 bidirectional DiT 做 diffusion 生成
- **代表系统/论文**: DiTAR (40Hz continuous latent, patch size 4-8, LocDiT); LatentLM/CLEAR (per-token continuous LM); VibeVoice; SwanVoice (25Hz VAE + Flow Matching DiT)
- **已知指标**: DiTAR: WER 1.78%, SIM 0.64 (LibriSpeech), WER 1.685%, SIM 0.735 (Seed-EN 280Kh, 1B); TFLOPs ~2.75 vs NAR 37-117 TFLOPs
- **优势**: 连续 latent 避免了 VQ 的量化损失; patchification 将 LM 序列缩短为原始的 1/P; bidirectional DiT 在 patch 内利用局部双向依赖; 计算量远低于全序列 diffusion
- **劣势**: 连续 LM 的采样比离散 LM 更复杂 (需要 ODE solver); VAE 训练细节敏感; 流式推理不明确
- **成熟度**: 中 (ByteDance Seed 内部大规模验证)

### 路径 6: 变帧率 / 动态密度 (VARSTok 思路)

- **做法**: 根据语音内容的信息密度动态分配 token 数量 — 高信息区域 (音素边界/辅音) 用更多 token,低信息区域 (静音/元音延续) 用更少 token
- **代表系统/论文**: VARSTok (Variable-Rate Speech Tokenizer); TASTE-Streaming (text-aligned, token 数=text token 数)
- **已知指标**: TASTE-Streaming: WER 4.1%, UTMOS 4.11, SPK SIM 0.88, Enc RTF 0.002 (~59x faster than TASTE); FCL 0.311s vs 12.29s (~40x faster)
- **优势**: 信息效率理论最优; text-aligned 版本使 LM 序列长度与文本等长; 对 SLM 下游任务有利
- **劣势**: 需要外部信息 (文本对齐/VAD) 确定分配策略; 变长 token 对 batch 处理不友好; text-aligned 依赖 ASR
- **成熟度**: 低-中 (概念验证阶段)

### 路径 7: Multi-Scale RVQ (SNAC/CoFi-Codec)

- **做法**: RVQ 不同层在不同时间分辨率量化: 第一层帧率最低 (编码全局结构),后续层帧率递增 (编码局部细节)
- **代表系统/论文**: SNAC (3-4层, [8,4,2,1] 下采样因子, 4096 codebook); CoFi-Codec (3尺度: 120ms/40ms/20ms); VoXtream/Mimi (Kyutai, 多尺度 CSM codec)
- **已知指标**: SNAC: 0.98 kbps (24kHz), competitive PESQ/VISQOL vs EnCodec at higher bitrate; CoFi-Speech SoS: NMOS 4.42, SMOS 3.90 (超越 CosyVoice)
- **优势**: 最粗层序列极短 (天然 coarse-to-fine); 不同层捕获不同粒度信息; 可单独优化各层
- **劣势**: LM 需要建模多层 token 的联合分布; 多尺度训练复杂; interleave/delay pattern 设计困难
- **成熟度**: 中-高 (SNAC 在 NeurIPS 2024 发表)

### 路径 8: Product Quantization / Cross-Scale RVQ

- **做法**: 用 product quantization (将 latent 分组,每组独立量化) 或 cross-scale residual 结构,在保持低码率的同时提高码本利用率
- **代表系统/论文**: DS-Codec (product quantization); ESC (Efficient Speech Codec, cross-scale residual VQ, EMNLP 2024); MBCodec (multi-band disentangle)
- **已知指标**: ESC: lightweight + parameter-efficient; 具体指标待确认
- **优势**: 在固定比特率下提高信息密度; 分组结构利于并行解码
- **劣势**: 分组后各组独立性假设可能不成立; 实际加速效果依赖实现
- **成熟度**: 低-中 (学术探索)

### 路径 9: Dual-Stream 解耦 (语义+声学独立码本)

- **做法**: 将一个 codec 拆成两个独立量化流: 语义流 (冻结 SSL 编码) + 声学流 (可训练 encoder); 各自用单码本; LM 建模 interleaved tokens
- **代表系统/论文**: SAC (Semantic-Acoustic Codec, dual-stream, 各 16384 codes); SpeechTokenizer (RVQ 第一层蒸馏 HuBERT, 后续层声学); Mimi (Kyutai, 语义 VQ + 声学 RVQ)
- **已知指标**: SAC: semantic-only WER 3.99 (vs SemantiCodec 30.67); 重建 UTMOS/PESQ SOTA
- **优势**: 最干净的语义-声学分离; LM 只需处理语义流 (声学流可并行/非自回归生成); 各流可独立优化
- **劣势**: 双流 interleave 增加序列长度 (2x); 解码端融合模块设计关键; 两套 embedding
- **成熟度**: 中 (2025 年多篇论文验证)

### 路径 10: BPE / Byte-Pair Encoding on Speech Tokens

- **做法**: 对离散 speech token 序列做 BPE (类似文本 tokenization 中的 subword),将高频 token 组合压缩为更大粒度的 token,缩短序列
- **代表系统/论文**: BASE TTS (speechcode BPE, 序列长度 -40%); Impact of Frame Rates on Speech Tokenizer (arXiv 2505.17076, 系统性研究帧率影响)
- **已知指标**: BASE TTS: 序列长度减少 40%, WER 6.5%, SIM 92.7%
- **优势**: 后处理,不改模型架构; 压缩比可通过词表大小调节; 概念简洁
- **劣势**: BPE 合并可能破坏 token 的声学语义; 不保证最优压缩; 可能影响流式推理
- **成熟度**: 中 (BASE TTS 验证,但后续跟进有限)

### 路径 11: Grouped FSQ / GFSQ (分组标量量化)

- **做法**: 将 latent vector 分为多组,每组独立做 FSQ (Finite Scalar Quantization),多组 token 可并行预测
- **代表系统/论文**: Fish-Speech (GFSQ, 100% codebook utilization, Dual-AR: Slow+Fast Transformer); Koel-TTS (LFSC, 21.5 FPS, 8 独立 codebook, 并行预测)
- **已知指标**: Fish-Speech: WER 6.89%, SIM 0.914; Koel-TTS: CER 0.55%, WER 1.41%, SSIM 0.740
- **优势**: 分组独立性使并行预测可行 (每步生成 N 组 token); 100% codebook 利用率; 无 codebook collapse
- **劣势**: 独立性假设不完全成立; 并行预测需要额外架构设计 (Dual-AR/depth transformer)
- **成熟度**: 高 (Fish-Speech 已大规模开源部署)

### 路径 12: Codec-Free 连续表征 (SimpleSpeech 2 路线)

- **做法**: 不用离散 token,直接在连续 mel/latent 空间做 flow matching/diffusion 生成; 用 sentence-level duration predictor 确定总长度
- **代表系统/论文**: SimpleSpeech 2 (SQ-Codec + flow matching on scalar space); F5-TTS (speech infilling FM); ZipVoice (Zipformer FM, 123M, 4NFE distill)
- **已知指标**: ZipVoice: WER 1.64, SIM 0.668, RTF 0.0125 GPU (4NFE); F5-TTS: WER ~2%, SIM ~0.7, NFE=32
- **优势**: 无量化损失; 可利用 diffusion/FM 的强大分布建模能力; 支持 teacher-student 蒸馏到少步
- **劣势**: NFE 步数决定速度 (需蒸馏才实时); 不支持流式 (需知道总长度); mel 空间维度高
- **成熟度**: 高 (F5-TTS/ZipVoice 已开源)

## B. 流式生成路径 (降低首包延迟 FPL)

### 路径 A: Chunk-based Streaming (AR 完成后分块送 decoder)

- **做法**: LM 完整生成全部 token 后,将 token 序列切成 chunk,逐 chunk 送入 FM/vocoder 解码; decoder 使用 causal 或 chunk-aware mask 支持流式输出
- **代表系统/论文**: CosyVoice 2 (chunk-aware causal flow matching, 4 种 mask 统一训练: non-causal/full-causal/chunk-M/chunk-2M); Seed-TTS (streaming 变体)
- **已知指标**: CosyVoice 2 streaming: WER 2.45%, NMOS 3.90, SS 0.751 (几乎无损于 non-streaming)
- **优势**: LM 端不需修改; decoder 端独立优化; 质量损失小 (chunk 内可双向 attention)
- **劣势**: FPL 受限于 LM 生成延迟 (需等 LM 完成整个 utterance 或至少一个完整 chunk); 不是真正的逐 token 流式
- **成熟度**: 高 (CosyVoice 2 工业验证)

### 路径 B: Full-stream AR (逐 token 边生边送)

- **做法**: AR LM 每生成一个 (或几个) speech token 就立即送入流式 decoder 输出波形; 需要 LM、tokenizer、decoder 全链路支持因果推理
- **代表系统/论文**: VoXtream 2 (三层 Transformer: PT/TT/DT, FPL 74ms); Llasa+ (MTP + XCodec2-S causal decoder); LiveSpeech 2
- **已知指标**: VoXtream 2: FPL 74ms, RTF 0.256, WER 1.32%, SIM 0.656; Llasa+ XCodec2-S: WER 3.239%, SIM 0.795, UTMOS 4.029
- **优势**: 真正的 token-level 流式, 最低 FPL; 适合实时对话
- **劣势**: 因果 decoder 质量通常低于非因果; 需要整套流式基础设施; tokenizer 必须因果
- **成熟度**: 中-高 (VoXtream 2 已验证)

### 路径 C: Text-Speech Interleaved Generation

- **做法**: 在 LM 输入中将文本和语音 token 交错排列 (如 "[S1]text+audio[S2]text+audio..."), LM 逐句生成; 当前句文本输入后立即开始生成对应语音 token
- **代表系统/论文**: FireRedTTS 2 (interleaved format, dual-transformer); TASTE-Streaming (N:M text-unit interleaving); GLM-4-Voice (interleaved text-speech); Qwen2.5-Omni
- **已知指标**: FireRedTTS 2: CER 1.14% (zh), WER 1.95% (en), SIM 0.736
- **优势**: 天然支持流式逐句生成; 文本和语音共享上下文; 适合对话场景
- **劣势**: 需要精确的 text-speech 对齐/分段; 单一 LM 同时建模两种模态增加训练难度
- **成熟度**: 中 (多系统验证但部署经验有限)

### 路径 D: Prefix-to-Speech (部分文本即开始)

- **做法**: 不等整句文本输入完成,LM 在接收到前几个词后就开始生成对应的 speech token; 后续文本以 streaming 方式追加
- **代表系统/论文**: VoXtream/VoXtream 2 (word-by-word 文本输入, PT 有 25 look-ahead); BASETTS (streamable speechcode decoder)
- **已知指标**: VoXtream 2: 每个 word 可立即触发生成, FPL ~74ms
- **优势**: 最低 text-to-first-audio 延迟; 适合 LLM chat (LLM 逐 token 输出文本)
- **劣势**: 需要处理文本不完整时的预测不确定性; 可能需要回退/修正机制; 韵律建模受限
- **成熟度**: 中 (VoXtream 系列验证)

### 路径 E: Inner Monologue / Text Prefix (先生成文本再生成音频)

- **做法**: Omni 模型先内部生成完整文本响应 (hidden text tokens), 然后基于完整文本生成音频 token; 文本生成极快,主要延迟在音频生成
- **代表系统/论文**: GLM-4-Voice (inner monologue); Qwen2.5-Omni (text-first-then-audio); LLaMA-Omni
- **已知指标**: 具体 TTS 专项指标较少公开; 主要优势在理解准确性
- **优势**: 文本质量有保证 (完整推理); 音频生成有完整语义条件; 避免了 "边想边说" 的不流畅
- **劣势**: 等待文本生成完成增加延迟; 不适合极低延迟实时对话; 文本和音频两次前向计算
- **成熟度**: 中 (多个 Omni 模型采用)

### 路径 F: Causal Codec Decoder (因果卷积解码器)

- **做法**: 将 codec decoder (通常是非因果的 CNN + 双向 attention) 改为纯因果实现, 使 decoder 可以流式输出波形而无需等待完整 token 序列
- **代表系统/论文**: Llasa+ XCodec2-S (仅解冻 decoder 改因果); Mimi (Kyutai, streaming neural codec, 完全因果)
- **已知指标**: XCodec2-S: WER 3.239% / SIM 0.795 / UTMOS 4.029 (vs XCodec2 non-causal: 2.470/0.821/4.127)
- **优势**: 配合 full-stream AR 实现端到端流式; 改动局限于 decoder
- **劣势**: 因果约束牺牲质量 (典型 WER +0.7%, SIM -0.03, UTMOS -0.1); 需要重新训练或微调
- **成熟度**: 中 (Llasa+/Mimi 验证)

### 路径 G: Transducer-based 单调对齐

- **做法**: 用 neural transducer (RNNT) 替代 decoder-only LM, 利用 transducer lattice 的单调对齐约束实现流式生成; 每个文本输入帧天然对应若干输出 token
- **代表系统/论文**: TTS-Transducer (NVIDIA, RNNT 预测第一层 RVQ + NAR 预测剩余层)
- **已知指标**: SIM 0.868-0.881, WER competitive with VALL-E (仅用 464h 训练)
- **优势**: 天然单调对齐,无跳字/重复; 支持流式; 不需要大规模预训练
- **劣势**: Transducer 内存开销大; 对长序列扩展性有限; 零样本能力弱于 LM-based 方案
- **成熟度**: 低 (学术验证)

## C. 推理加速路径 (降低 RTF)

### 路径 i: Multi-Token Prediction (MTP)

- **做法**: 在 LM backbone 上附加多个轻量 prediction head, 每步预测 N 个未来 token (而非 1 个); 推理时用 verification 机制确认预测正确性
- **代表系统/论文**: Llasa+ (2个 MTP 模块, 冻结 backbone, verification 算法, 1.48x 加速); DeepSeek-V3 MTP (NLP 原始方法)
- **已知指标**: Llasa+: LM speed-up 1.48x; WER 2.499% (vs baseline 3.220%, 反而更好!); SIM 0.575 vs 0.572
- **优势**: 不改 backbone 架构; 可插拔模块,训练成本极低 (LibriTTS 960h, 4xA800); 不降质量甚至提升; 与 speculative decoding 互补
- **劣势**: 加速比有上限 (第二个 MTP 仅 +15%); verification 开销; 最佳加速比依赖 acceptance rate
- **成熟度**: 中 (2025.05 发表, 仅 Llasa-1B 验证)

### 路径 ii: Speculative Decoding

- **做法**: 用小 draft model 快速生成 Ld 个候选 token, 再用大 target model 并行验证; 引入 tolerance factor beta 适配 speech token 的连续分布特性
- **代表系统/论文**: Speech Speculative Decoding (SSD, 2025, Interspeech; 8L draft + 24L target, tolerance factor beta=0.4, 基于 CosyVoice 2)
- **已知指标**: LM-RTF 0.360 vs 0.504 (1.4x 加速); NMOS 3.94 vs 3.96; WER 5.70% vs 3.67% (有退化)
- **优势**: 不改 target model; 理论上无损 (beta=0 时); 与现有部署直接兼容
- **劣势**: 加速比受限于 draft model 质量和 speech token 的高熵; WER 退化 55% (beta>0); 需要单独训练 draft model; 仅加速 LM 部分 (占总时间 70%)
- **成熟度**: 低-中 (概念验证, 加速比有限)

### 路径 iii: 模型量化 (INT8/INT4/FP8/GPTQ)

- **做法**: 将 LM 和/或 decoder 的权重和激活从 FP16/FP32 量化到更低精度; 减少显存和计算量
- **代表系统/论文**: 通用 LLM 量化技术 (GPTQ, AWQ, SmoothQuant, FP8); 在 TTS 中尚无系统性研究但 Llasa/CosyVoice 等基于标准 LLM 可直接适用
- **已知指标**: 通用 LLM INT8 量化: 通常 <1% 精度损失, 1.5-2x 推理加速; INT4: 2-4x 加速但精度损失更大
- **优势**: 与架构无关; 成熟工具链 (vLLM, TensorRT-LLM, llama.cpp); 可叠加其他加速方法
- **劣势**: speech token 对量化误差的敏感度未充分研究; 极端压缩 (INT4) 可能影响韵律; 需要校准数据
- **成熟度**: 高 (工具成熟,但 TTS 专项验证少)

### 路径 iv: KV Cache 优化

- **做法**: 优化自回归推理中的 KV cache: Paged Attention, Sliding Window Attention, GQA/MQA, KV cache 压缩/量化
- **代表系统/论文**: vLLM (Paged Attention); WAND (Windowed Attention + Knowledge Distillation for TTS, 1.55x 加速 + KV cache 减少)
- **已知指标**: WAND: 1.55x 加速 (vs CosyVoice 2), KV cache 显著减少
- **优势**: 降低显存瓶颈; 对长文本合成 (audiobook/podcast) 效果显著; 支持更大 batch size
- **劣势**: 过于激进的窗口大小可能丢失长距离依赖; 需要重训 (WAND); GQA 需要从预训练加入
- **成熟度**: 中 (WAND 验证, 通用 LLM 工具成熟)

### 路径 v: 架构替换 — Mamba/SSM/RWKV (线性复杂度)

- **做法**: 用 Mamba (Selective State Space Model) 或 RWKV (RNN-based) 替换部分/全部 Transformer attention 层, 获得 O(L) 推理复杂度 (vs Transformer O(L^2))
- **代表系统/论文**: MamTra (2026, Mamba-Transformer 混合, 基于 CosyVoice 2: 结构化权重转移 Q→C, K→B, V→x + 蒸馏, VRAM -34%); RWKVTTS (RWKV-7 完全替换 CosyVoice 2 Transformer); Llamba (Mamba 蒸馏 from Llama, NLP); Lina-Speech (gated linear attention for TTS)
- **已知指标**: MamTra 1:1: WER 2.28% (teacher 2.03%), NMOS 3.66 vs 3.68, VRAM -34%, 仅用 2% 训练数据; RWKVTTS: 质量评估不充分
- **优势**: 线性推理复杂度; 无 KV cache (恒定显存); 长序列处理更高效; 可从预训练 Transformer 蒸馏
- **劣势**: 全局建模能力弱于 attention (纯 Mamba); 1:11 比例质量明显下降; 预训练生态不如 Transformer; 代码优化不如 Flash Attention 成熟
- **成熟度**: 低-中 (MamTra 2026 验证,尚无工业部署)

### 路径 vi: 模型蒸馏 (大→小)

- **做法**: 用大模型 (teacher) 的 logits/hidden states 训练更小的模型 (student); 保留大模型的生成质量同时大幅降低参数量和推理成本
- **代表系统/论文**: MamTra (CosyVoice 2 → 混合架构, multi-level KD: CE + logits KL + embedding MSE); Llamba (Llama-3 → Mamba, MOHAWK 框架); ZipVoice (flow distillation: 32NFE→4NFE)
- **已知指标**: ZipVoice distill: 4NFE, RTF 0.0125 GPU (vs F5-TTS 32NFE RTF 0.2958), ~24x 加速; MamTra: 2% 训练数据恢复接近 teacher 性能
- **优势**: 学生模型可以任意小; 可结合架构替换 (蒸馏到 Mamba); 训练数据需求低
- **劣势**: 需要 teacher model 的训练数据 (或合成数据); 存在 student-teacher 分布 gap; 蒸馏过程的超参敏感
- **成熟度**: 中-高 (广泛应用于 NLP/TTS)

### 路径 vii: MoE 稀疏化

- **做法**: 将 FFN 层替换为 Mixture of Experts,每次推理仅激活部分 experts (如 2/8),保持模型容量同时降低每步 FLOPs
- **代表系统/论文**: DiaMoE-TTS (MoE for TTS); Time-MoE (SimpleSpeech 2, 不同去噪阶段用不同 expert); 通用 LLM MoE (Mixtral, DeepSeek-V3)
- **已知指标**: SimpleSpeech 2 Time-MoE: 不同去噪步骤使用专用专家,性能提升 (具体数值见论文)
- **优势**: 在不增加推理成本的前提下扩大模型容量; 与 AR 和 NAR 模型均兼容; 可部分激活
- **劣势**: 显存占用仍等于全部参数; 通信开销 (分布式); routing 策略需要优化; 负载均衡问题
- **成熟度**: 低 (TTS 中探索极少)

### 路径 viii: Parallel Decoding / Consistency Model (少步 Non-AR)

- **做法**: 不使用逐步 ODE sampling,而是训练一步或少步直接生成模型 (consistency model/distillation); 或使用 DMD (Distribution Matching Distillation) 将多步 teacher 蒸馏为少步 student
- **代表系统/论文**: DMOSpeech 2 (DMD distillation: 32步→4步, RTF 0.032); ZipVoice-Distill (32NFE→4NFE, RTF 0.0125); Seed-TTS (consistency distillation); VoiceFlow (ReFlow); Shallow Flow Matching (从 coarse 中间状态开始,跳过早期步骤, +48% ODE 加速)
- **已知指标**: DMOSpeech 2: RTF 0.032, 5.2x faster than F5-TTS, WER 1.752, SIM 0.698; ZipVoice-Distill: RTF 0.0125 GPU (24x faster than F5-TTS)
- **优势**: 推理速度接近单步; 可与标准 FM/diffusion 模型兼容 (蒸馏即可); 质量损失可控
- **劣势**: 蒸馏过程需要 teacher 模型; consistency model 训练不稳定; 极端少步可能影响韵律多样性 (mode shrinkage)
- **成熟度**: 中-高 (DMOSpeech 2 已投 AAAI 2026)

### 路径 ix: 流水线并行 (AR + FM 重叠执行)

- **做法**: AR LM 生成 token 和 FM/diffusion decoder 渲染同时进行; LM 生成前 N 个 token 后, decoder 就开始处理, 两者流水线并行
- **代表系统/论文**: CosyVoice 2 (chunk streaming 使 LM 和 FM 可 overlap); 通用 pipeline parallelism 思路
- **已知指标**: 理论上可将 end-to-end 延迟从 T_LM + T_FM 降至 max(T_LM, T_FM) + chunk_latency
- **优势**: 不改模型本身; 纯系统优化; 加速效果与模型结构无关
- **劣势**: 需要 streaming infrastructure; chunk 划分引入额外延迟; 复杂度在工程端
- **成熟度**: 高 (标准工程优化)

### 路径 x: CUDA Graphs / torch.compile / 算子融合

- **做法**: 使用 CUDA Graphs 消除 kernel launch overhead; torch.compile 做图优化和算子融合; Flash Attention 减少 HBM 访问
- **代表系统/论文**: Flash Attention 2/3; torch.compile (PyTorch 2.0+); CUDA Graphs (NVIDIA); TensorRT-LLM
- **已知指标**: Flash Attention: 2-4x attention speedup; torch.compile: 通常 10-30% 端到端加速; CUDA Graphs: 消除 Python overhead
- **优势**: 与模型结构无关; 成熟工具; 可叠加所有其他优化
- **劣势**: 动态序列长度 (TTS AR) 对 CUDA Graphs 不友好; 编译时间长; 兼容性问题
- **成熟度**: 高 (标准工程实践)

### 路径 xi: Grouped Code Modeling (多 token 一步)

- **做法**: 将多个相邻 speech token 组合为一个 "group",LM 每步预测一个 group (包含多个 token); 类似于增大 stride
- **代表系统/论文**: VALL-E 2 (Grouped Code Modeling, 需要重训 backbone)
- **已知指标**: VALL-E 2: 具体加速比未详细报告,但序列长度直接减半/更短
- **优势**: 直接减半/减少 AR 步数; 概念简洁
- **劣势**: 需要从头重训; group 内部 token 的条件独立假设可能不成立; 可能影响生成质量
- **成熟度**: 中 (VALL-E 2 验证)

### 路径 xii: Non-Autoregressive 完全并行生成

- **做法**: 完全抛弃 AR, 使用 NAR 模型 (masked prediction / diffusion / flow matching) 一次性生成所有 speech token 或 mel
- **代表系统/论文**: MaskGCT (masked generative codec transformer); F5-TTS (NAR FM speech infilling); SimpleSpeech 2 (NAR FM on scalar space); NAST (non-autoregressive speech tokenization)
- **已知指标**: MaskGCT: WER ~2%, SIM 0.7+; F5-TTS: WER ~2%, SIM ~0.7, NFE=32, RTF ~0.3
- **优势**: 生成速度理论上与长度无关 (仅取决于 NFE); 天然支持并行
- **劣势**: NFE 步数仍是瓶颈 (需蒸馏); 质量通常略低于 AR; 不支持真正流式; 需要知道目标长度
- **成熟度**: 中-高 (MaskGCT/F5-TTS 已开源)

### 路径 xiii: Depth Transformer (多码本并行预测)

- **做法**: 主 backbone transformer (temporal) 预测第一层 token 后, 由轻量 depth transformer 并行/少步预测剩余 RVQ 层
- **代表系统/论文**: VoXtream 2 (depth transformer, 16 codebooks, 冻结 CSM 权重); FireRedTTS 2 (dual-transformer: backbone 预测 layer-1 + decoder 预测 layer 2-16); GPST (global + local transformer)
- **已知指标**: VoXtream 2: RTF 0.256; FireRedTTS 2: 比 delay pattern 更好利用上下文
- **优势**: 主 AR 只需处理一层 token (短序列); 深度方向并行化; 避免多层 token 展开为长序列
- **劣势**: 需要额外 depth model; 层间依赖可能不完美; 两个 model 的联合调度复杂
- **成熟度**: 中 (多系统验证)

## D. Codec Decoder 加速路径

### 路径 alpha: Non-causal FM/Diffusion Decoder (高质量但不流式)

- **做法**: 标准 bidirectional attention FM decoder,对完整 token 序列做 flow matching 生成 mel; 多步 ODE solver
- **代表系统/论文**: CosyVoice (non-streaming CFM); Seed-TTS (diffusion acoustic model); DiTAR (LocDiT, NFE=10)
- **已知指标**: CosyVoice 2 non-streaming: 质量最优 (WER 2.03%, NMOS 4.0+); DiTAR: NFE=10, TFLOPs 2.75
- **优势**: 质量上限最高; bidirectional attention 充分利用全局信息; 成熟
- **劣势**: 不支持流式; NFE 步数增加延迟; 需等 AR 完全结束
- **成熟度**: 高

### 路径 beta: Causal Conv Decoder (纯因果CNN, 流式)

- **做法**: 使用纯因果卷积 decoder (如 causal HiFi-GAN/BigVGAN/Vocos),逐帧输出波形
- **代表系统/论文**: Mimi (Kyutai streaming codec, fully causal); XCodec2-S (Llasa+, 因果 Transformer decoder); Vocos (causal mode)
- **已知指标**: XCodec2-S: WER 3.239%, SIM 0.795, UTMOS 4.029 (vs non-causal 2.470/0.821/4.127)
- **优势**: 真正逐帧流式; 延迟最小; 与 full-stream AR 完美配合
- **劣势**: 质量损失明显 (看不到未来帧); 高频细节和语音边界处理困难
- **成熟度**: 中-高 (Mimi 已部署)

### 路径 gamma: Chunk-aware Causal FM (CosyVoice 2)

- **做法**: FM decoder 使用 chunk-aware causal mask — chunk 内部可双向 attention,chunk 之间因果; 训练时随机切换多种 mask 实现隐式自蒸馏
- **代表系统/论文**: CosyVoice 2 (4种 mask 统一训练: non-causal/full-causal/chunk-M/chunk-2M)
- **已知指标**: CosyVoice 2 chunk streaming: WER 2.45% vs non-streaming 2.03%; 几乎无损
- **优势**: chunk 内双向 attention 保持质量; 训练无需额外数据; 可运行时切换 streaming/non-streaming
- **劣势**: chunk size 决定延迟-质量 trade-off; 需要预先确定 chunk 边界; 比纯因果 decoder 延迟略高
- **成熟度**: 高 (CosyVoice 2 工业验证)

### 路径 delta: 少步 Flow Matching (1-4步 蒸馏)

- **做法**: 通过 consistency distillation / DMD / ReFlow 将 multi-step FM decoder 蒸馏为 1-4 步生成
- **代表系统/论文**: DMOSpeech 2 (4步 DMD, RTF 0.032); ZipVoice-Distill (4NFE, RTF 0.0125); VoiceFlow (ReFlow, 加速 ODE); Shallow Flow Matching (从 coarse 出发,减少有效步数, +48% ODE 加速)
- **已知指标**: DMOSpeech 2: 4步, RTF 0.032, WER 1.752; ZipVoice-Distill: 4步, RTF 0.0125; SFM: adaptive solver 加速 48%
- **优势**: decoder 阶段速度提升 5-10x; 与多步 teacher 质量接近; 可叠加流式
- **劣势**: 蒸馏需要 teacher; 极端少步 (1步) 可能引入 artifact; mode shrinkage 问题 (DMOSpeech 2 用 teacher-guided sampling 解决)
- **成熟度**: 中-高 (多论文验证)

### 路径 epsilon: GAN Vocoder (单步, HiFi-GAN 系列)

- **做法**: 完全跳过 diffusion/FM, 使用 GAN-based vocoder 从 mel/token 直接单步合成波形
- **代表系统/论文**: HiFi-GAN; BigVGAN; Vocos; FF-GAN (Fish-Speech FireFly-GAN); BASE TTS (Conv + BigVGAN speechcode decoder, 3x faster than diffusion)
- **已知指标**: BigVGAN: 近实时; Vocos: RTF < 0.01; BASE TTS: 3x faster than diffusion decoder
- **优势**: 单步,速度最快; 成熟稳定; 天然支持流式 (causal conv)
- **劣势**: 从离散 token 到波形的 vocoder 质量通常低于 FM; 需要额外训练; 对 token 质量依赖高
- **成熟度**: 高 (工业标准)

### 路径 zeta: Teacher-Guided Sampling (早期步用 teacher, 后期步用 student)

- **做法**: 在少步推理中,前几步使用 teacher model 建立整体结构 (韵律/能量),后几步切换为 student model 细化声学细节
- **代表系统/论文**: DMOSpeech 2 (teacher-guided sampling: 早期步 teacher 建立韵律, 后期步 student 细化)
- **已知指标**: DMOSpeech 2: 显著改善蒸馏后的韵律多样性和自然度
- **优势**: 解决蒸馏模型的 mode shrinkage; 兼顾速度和多样性; 可调节 teacher/student 步比
- **劣势**: 需要同时加载 teacher 和 student; 增加显存; 步比超参需要调节
- **成熟度**: 低 (DMOSpeech 2 首创)

## E. 综合系统路径 (端到端效率最优化)

### 路径 I: 低帧率单码本 + MTP + 少步 decoder

- **做法**: 组合多个优化: (1) 低帧率单码本 tokenizer (如 25Hz FSQ) 降低序列长度; (2) MTP 加速 AR; (3) 4步蒸馏 decoder
- **代表系统/论文**: Llasa+ + ZipVoice 思路的组合; CosyVoice 系列 (低帧率 + chunk FM)
- **理论极限**: 25Hz x 10s = 250 tokens; MTP 1.5x → ~167 有效步; 4步 decoder → 接近实时
- **优势**: 各维度独立优化可叠加; 不需要从零设计
- **劣势**: 多个优化的交互效应未知; 工程复杂度高; 需要联合调优
- **成熟度**: 低 (尚无完整系统验证)

### 路径 II: 极低帧率 continuous + 单步 decoder

- **做法**: TaDiCodec 级别的极低帧率 (6.25Hz) + GAN 单步 decoder (但目前 TaDiCodec 用 diffusion decoder)
- **理论极限**: 6.25Hz x 10s = ~63 tokens; 如能用 GAN 单步解码 → 极致效率
- **挑战**: 极端压缩下单步 decoder 能否保持质量是未解决问题
- **成熟度**: 极低 (理论路径)

### 路径 III: NAR FM + 4步蒸馏 + 小模型

- **做法**: ZipVoice 路线 — 123M 小模型 + NAR flow matching + 4步蒸馏; 完全跳过 AR
- **代表系统/论文**: ZipVoice (123M, 4NFE, RTF 0.0125 GPU); DMOSpeech 2 (300M, 4步, RTF 0.032)
- **已知指标**: ZipVoice: RTF 0.0125 (GPU), WER 1.64, SIM 0.668; CPU RTF 1.22 (可在端侧运行)
- **优势**: 无 AR 瓶颈; 参数量极小; CPU 实时可行; 单一模型架构
- **劣势**: 不支持流式 (需知道总长度); speaker similarity 不如大模型; average upsampling 粗糙
- **成熟度**: 中 (ZipVoice 已开源)

### 路径 IV: Mamba/RWKV backbone + streaming codec

- **做法**: 用线性复杂度模型 (Mamba/RWKV) 做 backbone + 因果 codec decoder,实现全链路 O(L) 复杂度流式系统
- **代表系统/论文**: MamTra + XCodec2-S; RWKVTTS
- **理论优势**: O(L) 推理 + 恒定显存 + 流式 = 理想的部署模型
- **挑战**: 质量是否能达到 Transformer 级别; Mamba 对语音长距离依赖建模有限
- **成熟度**: 低 (概念组合,无完整验证)

## F. 补充路径

### 路径 F1: 动态 Early Exit

- **做法**: 对简单 token (如静音/重复) 提前退出 (fewer layers),对复杂 token (如辅音/声调变化) 使用全部层
- **代表系统/论文**: NLP 领域 early exit; TTS 中尚无系统研究
- **理论优势**: 平均层数减少 → 平均延迟降低; 适配 speech token 的非均匀复杂度
- **成熟度**: 极低 (TTS 待探索)

### 路径 F2: Batch Speculative Decoding (多用户共享 draft)

- **做法**: 多个推理请求共享同一个 draft model,提高 GPU 利用率
- **成熟度**: 极低 (理论路径)

### 路径 F3: Token Merging / Token Pruning

- **做法**: 在推理过程中合并相似的 KV cache entries 或裁剪不重要的 token,减少有效序列长度
- **代表系统/论文**: NLP 领域 token merging (ToMe); TTS 中待探索
- **理论优势**: 动态降低有效序列长度; 与 attention 机制直接配合
- **成熟度**: 极低 (TTS 待探索)

### 路径 F4: 异构推理 (LM GPU + Decoder NPU/DSP)

- **做法**: LM 在 GPU 运行,decoder/vocoder 卸载到 NPU 或 DSP 硬件加速器; 流水线并行
- **成熟度**: 中 (工程路径,云+端协同)

### 路径 F5: Prefix Caching (相同 speaker prompt 复用)

- **做法**: 对同一说话人的多次 TTS 请求,缓存 speaker prompt 对应的 KV cache,避免重复计算
- **代表系统/论文**: vLLM prefix caching; RadixAttention
- **优势**: zero-shot TTS 中 speaker prompt 通常不变; 可减少首次推理延迟
- **成熟度**: 高 (标准工程优化)

## 关键 Trade-offs 总结 (不做推荐)

1. **帧率 vs 重建质量**: 更低帧率 → 更短序列 → 更快 AR, 但重建质量可能下降 (需更强 decoder 补偿)
2. **离散 vs 连续**: 离散 token → 标准 LLM 兼容但有量化损失; 连续 latent → 无量化损失但采样复杂
3. **AR vs NAR**: AR → 流式友好/质量上限高/速度慢; NAR → 并行快/不支持流式/需要 duration
4. **因果 vs 非因果 decoder**: 因果 → 流式/低延迟/质量损失; 非因果 → 高质量/不流式
5. **步数 vs 质量 (FM/Diffusion)**: 步数少 → 快但可能 artifact; 步数多 → 质量好但慢
6. **模型大小 vs 质量**: 小模型快但质量低; 大模型质量高但推理慢和显存大
7. **Transformer vs Linear (Mamba/RWKV)**: Transformer 全局建模强/显存大; Linear O(L)/恒定显存/局部建模

# Tokenizer / 表示层: 路径全景

> 基于 PaperWiki 知识库 529 篇论文笔记 + 13 个概念页的全面梳理。
> 更新日期: 2026-06-09

---

## 一、量化方式

### 路径 1: RVQ (Residual Vector Quantization, 多层残差)

- **做法**: 递归量化残差。第 i 层量化前一层残差 r_i,最终重建 z_hat = sum(q_1...q_N)
- **码本**: 通常 N_q=2-32 层, 每层 K=1024 entries
- **训练**: 端到端 RVQ-GAN; EMA codebook 更新; dead code replacement
- **优势**: 重建指标最优 (Survey ablation); 可变比特率 (quantizer dropout); 层级信息结构天然适合 hierarchical generation
- **劣势**: Token rate 高 (frame_rate x N_q); 需要多流建模 (AR+NAR / delay pattern / interleaving); 后层码本贡献递减
- **代表论文**: SoundStream (2021), EnCodec (2022), DAC (NeurIPS 2023)
- **指标**: EnCodec@8Q 6kbps MUSHRA 76.8; DAC@9Q 8kbps ViSQOL 4.18 bitrate efficiency 99%

### 路径 1a: GVQ (Group Vector Quantization)

- **做法**: 将输入特征沿 channel 维分为 G 组, 每组独立 VQ (非残差)
- **码本**: G 组, 每组独立 codebook
- **训练**: 与 RVQ 类似的 GAN 训练
- **优势**: 增强第一层表达力 (非逐层递减); 组间独立有利于并行
- **劣势**: 码本数仍多; 组间缺乏信息交互
- **代表论文**: HiFi-Codec (Yang 2023a), FACodec (NaturalSpeech 3), FunCodec
- **指标**: FACodec 将语音分解为 content/prosody/timbre/detail 四组

### 路径 1b: MSRVQ (Multi-Scale RVQ)

- **做法**: 不同 RVQ 层在不同时间分辨率上量化; 高层降采样→量化→上采样
- **码本**: 多层, 不同帧率 (如 [8x, 4x, 2x, 1x] 下采样)
- **训练**: RVQ-GAN + noise blocks + depthwise conv
- **优势**: 天然 coarse-to-fine 结构; 大幅减少总 token 数; 比特率极低
- **劣势**: 不同层帧率不同增加 LM 建模复杂度; 音乐场景未超越 DAC
- **代表论文**: SNAC (Siuzdak 2024, ICLR 2025), LLM-Codec
- **指标**: SNAC@0.98kbps Speech MUSHRA 88.4 vs DAC@2.5kbps 85.0; 开源

### 路径 1c: CSRVQ (Cross-Scale RVQ)

- **做法**: 在 encoder/decoder 不同层级间做残差量化; coarse-to-fine 多分辨率
- **码本**: 多层多分辨率
- **代表论文**: ESC (Gu & Diao 2024), Disen-TF-Codec

### 路径 1d: EG-GRVQ (Entropy-Guided Grouped RVQ)

- **做法**: 用信道方差作为信息量代理, 不等分组使每组信息量均衡
- **优势**: 改善 codebook 利用率, 比标准 GRVQ 更高效
- **代表论文**: EntropyGRVQ (Ren et al. 2026)

### 路径 2: SVQ (Single Vector Quantization, 大码本)

- **做法**: 单层 VQ, 每帧仅产生 1 个 token; 需大码本补偿
- **码本**: K=4096-131072, 1 层
- **训练**: GAN / 多阶段 (AE→VQ→Vocoder) / 端到端
- **优势**: 极低 token rate → LM 序列短 → 推理快; 单流 = 标准 LM; 无多码本同步问题
- **劣势**: 单码本难覆盖高维空间; 大码本 softmax 计算量增加; Survey ablation 中 SVQ 重建指标最差
- **代表论文**: BigCodec (2024, K=8192), WavTokenizer (ICLR 2025, K=4096), MagiCodec (2025, K=131072), TS3-Codec, DS-Codec
- **指标**: BigCodec@1.04kbps MUSHRA 92.33; WavTokenizer@0.98kbps UTMOS 4.05; MagiCodec@850bps WER 3.16

### 路径 3: FSQ (Finite Scalar Quantization)

- **做法**: 无 codebook; 将连续表征投影到 d 维 (d<10), 每维独立 round 到有限 level
- **码本**: 隐式, |C| = prod(L_i); 例 d=8, L=[8,8,8,5,5,5] → |C|=2^16=65536
- **训练**: STE 梯度; 无需 commitment loss / EMA / reseeding
- **优势**: 100% codebook 利用率 (天然无 collapse); 训练简单稳定; 大码本扩展性好
- **劣势**: Survey ablation: 44.1kHz 下部分退化; 在纯重建指标上不如 RVQ
- **代表论文**: CosyVoice 2/3 (FSQ-SenseVoice/MinMo), Llasa (X-codec2), Spark-TTS (BiCodec), Fish-Speech (GFSQ)
- **指标**: CosyVoice 2 codebook 利用率 100% (vs VQ 仅 23%); Llasa X-codec2 UTMOS 4.13

### 路径 4: BSQ (Binary Scalar Quantization)

- **做法**: 将 latent 投影到 L 维后 sign binarization; token index = binary code 的十进制值
- **码本**: 隐式, |C| = 2^L
- **训练**: STE; diffusion loss (TaDiCodec) 或 GAN
- **优势**: 无需码本维护; 端到端训练与 diffusion loss 兼容; 适合极低帧率
- **劣势**: 二值化信息损失大; 需配合强 decoder 补偿
- **代表论文**: TaDiCodec (2025, L=14, 6.25Hz, 0.0875kbps), StableToken (Voting-LFQ, L=13)
- **指标**: TaDiCodec 重建 WER 2.73, TTS-AR WER 2.28 (en) / 1.19 (zh)

### 路径 5: PQ (Product Quantization)

- **做法**: 将高维向量分为多个子空间, 每个子空间独立 VQ, 最终组合
- **码本**: G 组 x K entries; 有效码本 = K^G
- **训练**: 端到端; 可配合 nested dropout 学习有序表示
- **优势**: 小码本组合出大有效空间; nested dropout 实现有序信息层级
- **劣势**: 多流仍需多流 LM 策略; 组间缺乏残差联系
- **代表论文**: SoCodec (SLT 2024, OPQ), DS-Codec (PQ 4x16), Best-RQ, SOCODEC
- **指标**: SoCodec-40 NMOS 3.83/CER 2.37%; DS-Codec PQ4x16 UTMOS 4.218

### 路径 6: K-means 聚类 (Post-hoc Quantization)

- **做法**: SSL 模型 (HuBERT/WavLM) 提取连续表征后, 离线 k-means 聚类离散化
- **码本**: K=50-16384 cluster centers
- **训练**: SSL 预训练 (masked prediction) + 独立 k-means
- **优势**: 概念简单; 与文本类似的离散表示; 已有成熟 SSL 生态
- **劣势**: 硬聚类信息损失大 (WER 从 2.5% 恶化到 6%); 不可微; 不 end-to-end
- **代表论文**: GSLM (2021), AudioLM (w2v-BERT tokens), Discrete WavLM, SpeechTokenization for SLM (2025)
- **指标**: 最佳配置 (80ms, K=16384) SLU 平均准确率 0.67

### 路径 7: 无量化 (连续 VAE Latent)

- **做法**: 完全绕过离散化; 用 VAE 编码为连续 latent vectors; LM 用 diffusion/flow head 建模连续分布
- **表征**: 连续向量, 通常 64-128 维, 25-50 Hz
- **训练**: VAE (sigma-VAE / beta-VAE) + AR Transformer + per-token diffusion/flow head
- **优势**: 无量化信息损失; 无 codebook collapse 问题; 理论信息保留最大
- **劣势**: 无法直接用 cross-entropy; 需特殊采样机制; 推理多步 (diffusion steps)
- **代表论文**: LatentLM (2024, sigma-VAE + diffusion head), CLEAR (2025, shortcut-VAE + rectified flow), MELLE (2024, 直接 mel AR), HoliTok (2026, progressive VAE), Cont-SPT (2024, NAACL 2025)
- **指标**: CLEAR WER 1.88% RTF 0.18; MELLE WER 1.98 SIM 0.508; LatentLM WER 3.36; HoliTok TTS WER 1.33%

### 路径 8: Gumbel-Softmax 可微量化

- **做法**: 将硬 argmax 替换为 Gumbel-Softmax 采样, 实现可微的离散选择
- **训练**: 端到端梯度传播; temperature annealing
- **优势**: 所有 codes 获得梯度 (解决 collapse); 可与任何目标组合
- **劣势**: 引入额外计算; 温度退火需调参
- **代表论文**: CosyVoice 3 (DiffRO 中用 Gumbel-Softmax 做可微 reward), VQ-VAE-2
- **用途**: 主要在 RL 后训练/特殊训练策略中使用

### 路径 9: LFQ (Look-up Free Quantization) / Voting-LFQ

- **做法**: 将 latent 通过线性投影到 d 维, sign binarization 得到 2^d 个隐式 code; 多分支并行投影 + bit-wise majority vote 提升鲁棒性
- **码本**: 隐式, 2^d entries (StableToken: d=13 → 8192)
- **训练**: CTC loss + consensus loss; 多分支 clean/perturbed input
- **优势**: 噪声鲁棒性极强 (UED 降低 >60%); 适合嘈杂真实环境的 SpeechLLM
- **劣势**: 仅关注语义, 无声学重建; 多分支推理开销
- **代表论文**: StableToken (2026)
- **指标**: UED 10.17% (vs CosyVoice2 38.66%); 下游 ASR WER CHiME-4 35.90% (vs CV2 54.63%)

## 二、信息组织方式

### 路径 A: 纯语义 Token (ASR / SSL 监督)

- **做法**: Tokenizer 仅编码语义/语言信息, 声学细节由下游 vocoder/CFM 补充
- **监督方式**: ASR 多任务 (CosyVoice S3); SSL masked prediction (HuBERT k-means); 对比学习 (wav2vec 2.0)
- **优势**: 短序列 (25Hz); 与文本对齐好; speaker-independent; CFM 可独立控制音色
- **劣势**: 缺乏高频声学细节; 需 CFM/diffusion 二阶段恢复; 韵律可能丢失
- **代表系统**: CosyVoice 3 (FSQ-MinMo, 25Hz), CosyVoice 2 (FSQ-SenseVoice), SPEAR-TTS, AudioLM (w2v-BERT)
- **下游**: LLM AR → semantic tokens → CFM (DiT) → mel → vocoder

### 路径 B: 纯声学 Token (重建监督)

- **做法**: Tokenizer 编码全部声学信息 (content + prosody + timbre + detail)
- **监督方式**: 波形重建 + GAN adversarial + feature matching
- **优势**: 高保真重建; 无需二阶段; decoder 直接输出波形
- **劣势**: 语义对齐差; 对 LM 建模不友好; 序列可能很长
- **代表系统**: EnCodec, SoundStream, DAC, WavTokenizer, BigCodec, MagiCodec
- **下游**: LM → acoustic tokens → codec decoder → waveform

### 路径 C: 语义+声学分层 (AudioLM 范式)

- **做法**: 两个独立 tokenizer, 先生成 semantic tokens 再生成 acoustic tokens
- **架构**: Semantic stage (SSL encoder + k-means/VQ) + Acoustic stage (codec RVQ)
- **优势**: 分治简化各阶段; 语义阶段保证连贯性; 声学阶段保证保真度
- **劣势**: 两个独立系统; 串联序列极长; 接口对齐困难
- **代表系统**: AudioLM (w2v-BERT → SoundStream), VALL-E (phoneme → EnCodec 8层), SoundStorm

### 路径 D: 混合 Token (语义+声学统一)

- **做法**: 单一 tokenizer 同时编码语义和声学; 通过蒸馏/特殊训练注入语义信息
- **子路线**:
  - **RVQ 第一层蒸馏 SSL**: SpeechTokenizer (RVQ-1 蒸馏 HuBERT, 后续层声学残差)
  - **Split RVQ**: Mimi (1 VQ semantic + 7 RVQ acoustic, WavLM 蒸馏), LM-SPT (reconstruction-driven distillation)
  - **双流 encoder**: FireRedTTS 2 (Whisper + acoustic encoder → 16层 RVQ), OmniCodec (Qwen3-Omni-AuT + SEANet)
  - **Dual-stream codec**: FlexiCodec (ASR encoder FSQ + waveform RVQ), DualCodec, X-Codec2
  - **语义蒸馏到 RVQ-1**: Fish Audio S2 (蒸馏 w2v-BERT 2.0)
- **优势**: 统一框架; 单码本流也含语义; 利于 LM 建模
- **劣势**: 设计复杂; 蒸馏可能引入瓶颈; 不同属性间仍可能泄漏
- **代表系统**: SpeechTokenizer, Mimi/Moshi, X-Codec2, LM-SPT, OmniCodec, Fish Audio S2
- **指标**: LM-SPT 在 TTS 下游全面超越 SpeechTokenizer/Mimi; Mimi@12.5Hz 配合 Moshi 实现全双工

### 路径 E: 属性分解 Token (content/prosody/timbre/detail)

- **做法**: 显式将语音分解为多个正交属性子空间, 每个子空间独立量化和生成
- **解耦方式**: GRL 对抗训练 + 信息瓶颈 + detail dropout (NaturalSpeech 3); 级联残差隐式解耦 (MSR-Codec)
- **优势**: 属性独立控制; 降低各子空间建模复杂度; 零样本属性迁移
- **劣势**: 分解正交性缺乏理论保证; GRL 训练不稳定; 推理多步 (factorized diffusion)
- **代表系统**: NaturalSpeech 3 (FACodec, 4 子空间), MSR-Codec (4 流级联残差)
- **指标**: NS3 LibriSpeech CMOS=0.00 (与人类持平); MSR-Codec 424bps SIM 0.83

### 路径 F: Text-aware Token (文本条件编码/解码)

- **做法**: 编码或解码时引入文本信息, 使 token 不必承载全部内容信息
- **实现方式**: Diffusion decoder conditioned on text (TaDiCodec); 文本作为 prefix 条件
- **优势**: 极端压缩率 (token 只需编码 text 之外的信息); 端到端训练
- **劣势**: De-tokenization 时需文本输入; 不适用于 speech understanding
- **代表系统**: TaDiCodec (6.25Hz, 0.0875kbps, text-conditioned DiT decoder)
- **指标**: TaDiCodec TTS-AR WER 2.28 (en) / 1.19 (zh)

### 路径 G: Disentangled Token (GRL/MI 最小化)

- **做法**: 通过对抗训练或信息瓶颈显式排除特定信息 (如 speaker identity)
- **技术**: Gradient Reversal Layer; 互信息最小化; Clip&Shuffle 数据增强
- **优势**: Token 只包含目标信息 (如 content+prosody); speaker 由外部 embedding 注入
- **劣势**: 训练不稳定; 解耦可能不完全; 需额外 speaker encoder
- **代表系统**: Spark-TTS (BiCodec: semantic VQ + global FSQ 分离音色), SoCodec (Clip&Shuffle 防 content 泄漏), FireRedTTS (ECAPA-TDNN + Clip&Shuffle)

### 路径 H: 内在正则化 Token (无外部监督的语义增强)

- **做法**: 不依赖外部 SSL/ASR 模型, 通过训练策略内在增强 token 语义
- **技术**: Gaussian noise injection 频域正则化 (MagiCodec); decoder attention 增强语义 (WavTokenizer); progressive training (HoliTok)
- **优势**: 无外部模型依赖; 系统简洁; end-to-end
- **劣势**: 语义增强程度有限; 理论基础薄弱 (仅 MagiCodec 有推导)
- **代表系统**: MagiCodec (Gaussian noise → Zipf distribution), WavTokenizer (decoder attention), HoliTok (渐进式 AE→VAE→downstream)
- **指标**: MagiCodec ASR PER 7.7, Emotion ACC 0.70; WavTokenizer ARCH分类准确率显著提升

## 七、训练策略

| 策略 | 原理 | 代表系统 |
|---|---|---|
| **端到端 RVQ-GAN** | Encoder + RVQ + Decoder + Discriminator 联合训练 | SoundStream, EnCodec, DAC, SNAC |
| **多阶段训练** | AE预训练 → VQ训练 → GAN vocoder 训练 (解耦冷启动) | MagiCodec (3阶段), DS-Codec (镜像→非镜像) |
| **语义蒸馏** | 用外部 SSL/ASR 模型的表征作为训练目标对齐 | SpeechTokenizer (HuBERT蒸馏), Mimi (WavLM蒸馏), Fish Audio S2 (w2v-BERT 2.0) |
| **监督式多任务** | ASR + LID + SER + AED + SA 等多任务联合训练 tokenizer | CosyVoice 3 (MinMo, 530K h) |
| **对比学习** | 对比损失强制 codebook 区分性 | w2v-BERT, wav2vec 2.0 |
| **Diffusion loss (流匹配)** | 用 flow matching 作为重建目标,替代 GAN | TaDiCodec, HoliTok (下游 DiT) |
| **知识蒸馏** | Reconstruction-driven distillation (不直接对齐特征) | LM-SPT (Whisper ASR encoder 对比原始与重建) |
| **渐进式训练** | Stage-I: AE → Stage-II: VAE (冻结两端训练 bottleneck) → Stage-III: 联合+语义蒸馏 | HoliTok |
| **Quantizer Dropout** | 随机使用前 n 层训练, 实现可变比特率 | SoundStream (always), DAC (p=0.5), MOSS (p=1.0) |
| **RL 后训练** | DPO/GRPO/DiffRO 优化下游质量 | CosyVoice 3 (DiffRO), Fish Audio S2 (GRPO), Qwen3-TTS (DPO+GSPO) |
| **Noise injection 正则化** | Gaussian noise 替换帧, 频域高频衰减 | MagiCodec (Bernoulli mask + Gaussian) |
| **Noise-aware consensus training** | 多分支 clean/perturbed 输入 + consensus loss | StableToken |

## 九、关键 Trade-off 总结

### 9.1 比特率公式

$$\text{Bitrate (bps)} = \text{Frame Rate} \times N_q \times \log_2 K$$
$$\text{Token Rate (tokens/s)} = \text{Frame Rate} \times N_q$$

### 9.2 核心发现 (来自 Survey ablation)

1. **重建最优 =/= 下游最优**: 增加 codebook 数量改善重建但常降低下游任务性能
2. **RVQ > FSQ > SVQ** (纯重建指标); FSQ@16kHz 在 UTMOS/DNSMOS 上可超 RVQ
3. **中等 bitrate 通常是最优平衡点**: 非越高越好
4. **采样率与量化方法存在交互**: 44.1kHz 利于 RVQ 但不利于 FSQ
5. **没有单一 tokenizer 全面领先**: 语义任务 SSL tokenizer 优; 声学任务 acoustic codec 优

### 9.3 2025-2026 趋势

1. **单码本回归**: 从 RVQ (8-32层) 向 SVQ/FSQ (1层) 演进, 换取 LM 建模简化
2. **极低帧率**: 从 75Hz 向 6.25-25Hz 演进, 适应长序列 LLM
3. **连续表征兴起**: LatentLM → CLEAR → HoliTok, 绕过离散化的信息损失
4. **监督式语义 tokenizer**: CosyVoice S3 路线用 ASR 多任务监督替代 SSL + k-means
5. **混合 tokenizer 成熟**: Mimi/LM-SPT/X-Codec2/Fish Audio S2 等验证了混合路线
6. **Text-aware codec**: TaDiCodec 开辟了文本条件解码路线
7. **Variable frame rate**: VARSTok/FlexiCodec 探索内容自适应帧率
8. **Mega codebook**: MagiCodec (131072) 验证了超大单码本的可行性
9. **Token stability**: StableToken 揭示了被忽视的噪声脆弱性维度
10. **RL 后训练**: DiffRO/GRPO/DPO 用于优化 tokenizer 的下游友好性

## I. Post-training 优化方法

### 路径 1: GRPO (Group Relative Policy Optimization) — Audio-level

- **做法**: 策略模型对同一输入采样 G 组候选 (通常 G=8),将生成的语音解码为波形后用工具计算 reward,用 group-relative advantage normalization 更新策略。不需要 critic network 或 value model。
- **代表论文+团队**: Multi-Reward GRPO (Tencent, 2025), TTS-1 (Inworld AI, 2025), GRPO-TTS (USTC/iFLYTEK, 2025), Align2Speak (NVIDIA, 2025), F5R-TTS (2025)
- **数据需求**: 无配对偏好数据; 仅需文本+参考说话人。4000-10K 句即可见效。
- **已知效果**: CosyVoice2+GRPO CER 1.41→1.07; Llasa+GRPO CER 7.73→1.30; TTS-1 WER 相对降低 20-26%
- **已知问题/风险**: 超过 1500 步后可能退化 (Tongyi 发现); 韵律坍缩 (Channel Corp 证实); reward hacking
- **成熟度**: 高 — 多家工业团队验证,已用于生产系统

### 路径 2: DiffRO (Differentiable Reward Optimization) — Token-level

- **做法**: 在 codec token 空间直接计算 reward 并反向传播梯度。用 Gumbel-Softmax 使离散采样可微,Token2Reward Model (类 ASR 模型) 在 token 空间预测 reward,省去 FM+vocoder 推理开销。Token-level KL 约束防止策略偏离。
- **代表论文+团队**: DiffRO (Tongyi Lab / Gao et al., 2025), CosyVoice 3 (阿里通义, 2025)
- **数据需求**: 需预训练 Token2Reward Model (SenseVoice embedding 层改造)。无需偏好数据。
- **已知效果**: WER zh 1.56→0.78 (Seed-TTS-eval); 情感 accuracy HAPPY 1.00/0.92; 低资源语言韩语改进 68.7%
- **已知问题/风险**: Reward hacking — vanilla SER RM 的过度自信被解析梯度放大 (RRPO 发现); MTR 的 MOS/age/gender 控制受 FM+vocoder 去噪瓶颈限制; 与 GRPO 直接合并 loss 反而变差
- **成熟度**: 中高 — Tongyi Lab 核心方法,CosyVoice 3 已集成

### 路径 3: DPO (Direct Preference Optimization) — Utterance-level

- **做法**: 使用 golden vs synthetic tokens 构建偏好数据对,用 DPO loss 直接更新策略,无需 reward model 或 RL loop。
- **代表论文+团队**: SpeechAlign (复旦, 2024), RIO (2024), UNO (2024)
- **数据需求**: 需要配对偏好数据。SpeechAlign 通过 golden vs synthetic AR tokens 自动构建。
- **已知效果**: LibriSpeech WER 7.2→6.0, SIM 0.87→0.90; 迭代 DPO (3轮) 可持续改进
- **已知问题/风险**: 标注噪声敏感; utterance-level 信号粗糙; DPO 过拟合退化 (πθ(yl)→0)
- **成熟度**: 中 — TTS RL 的先驱工作,已被 GRPO/DiffRO 路线超越

### 路径 4: FPO (Fine-grained Preference Optimization) — Token-selective DPO

- **做法**: 将 DPO loss 从 utterance-level 下沉到 error segment tokens。对 TTS segmental errors 分类: temporal modeling errors (局部标注) vs semantic-phonetic alignment errors (从 error onset 级联到末尾)。仅在 error tokens 上计算 DPO loss。
- **代表论文+团队**: FPO (NWPU / Yao et al., 2025)
- **数据需求**: 需 fine-grained error segment 标注 (Whisper-timestamped + forced alignment)。200 utterances ≈ UNO 600 utterances 的效果。
- **已知效果**: CosyVoice CER 3.63→1.83 (-49.6%), bad case 21%→9%; 3-4x 数据效率优势
- **已知问题/风险**: 标注成本虽低数据量但每条更复杂; SECS 无显著提升; 仅验证 AR 模型
- **成熟度**: 中 — NWPU 团队验证,与 MPO 互补

### 路径 5: TKTO (Token-level KTO) — 无配对数据

- **做法**: 基于 prospect theory 的 token-level 优化。用 label-flipped KTO 训练 contrastive LLM pair (π+ 和 π-),其 log-ratio 自动估计 token-level importance weights,再做 token-level weighted KTO 优化。
- **代表论文+团队**: TKTO (SpiralAI / Kotoge & Sasaki, 2025)
- **数据需求**: 无需配对数据 — KTO 仅需 desirable/undesirable 单侧标签。可利用 6x 更多数据。
- **已知效果**: 日语歧义发音 Acc 0.668→0.958; CER 降低 54%; NMOS 4.09→4.21
- **已知问题/风险**: 仅 0.5B 模型验证; 需额外训练两个 contrastive LLMs; 仅覆盖发音歧义场景
- **成熟度**: 低-中 — 单篇论文验证

### 路径 6: MPO (Multidimensional Preference Optimization) — 多维度 DPO

- **做法**: 对 intelligibility/speaker similarity/prosody 三维度分别选 max/min 构建 preference set,加 CE loss 正则化防 DPO 退化。
- **代表论文+团队**: MPO (NWPU / Xia et al., 2025)
- **数据需求**: 每个输入生成 10 candidates,自动评分选极值。100h 中文数据。
- **已知效果**: CER 4.72→3.90, SIM 0.548→0.577, Prosody RMSE 0.337→0.279
- **已知问题/风险**: 规模偏小; 无 MOS 评价; 未与 SpeechAlign/UNO/RIO 直接对比
- **成熟度**: 低-中 — 单篇 Interspeech 格式论文

### 路径 7: Iterative DPO (Moving Reference + 人类偏好)

- **做法**: 每轮收集 ~200 人类偏好对,做 DPO 更新。πref 设为上一轮的 πθ (moving reference),不跨轮复用数据。
- **代表论文+团队**: No Verifiable Reward for Prosody (Channel Corp / Shin et al., 2026)
- **数据需求**: 每轮 ~200 human preference pairs (极少量)
- **已知效果**: Round 2 达 ELO 1190.1 (最高) + CER 3.60%; 修复了 GRPO 导致的韵律坍缩
- **已知问题/风险**: Round 3 收益递减; 需要人工标注; 仅单说话人韩语验证
- **成熟度**: 低-中 — 但提供了不可自动化 reward 时的最实用方案

### 路径 8: REINFORCE / PPO — Audio-level Policy Gradient

- **做法**: 经典 RL 算法直接应用于 TTS。生成完整音频后计算 reward (SIM+WER),用 REINFORCE 或 PPO 更新策略。
- **代表论文+团队**: Seed-TTS (ByteDance, 2024)
- **数据需求**: 需 value network (PPO) 或 baseline 估计 (REINFORCE)
- **已知效果**: 首次证明 RL 后训练对 TTS robustness/similarity/controllability 有效
- **已知问题/风险**: Reward hacking (WER 低但自然度降); PPO 训练复杂不稳定; 计算成本高
- **成熟度**: 中 — 先驱工作,已被 GRPO 取代

### 路径 9: W3AR (Word-level Whisper Attention Reward)

- **做法**: 利用 frozen Whisper 的 cross-attention map 提取 word-level reward: (1) Attention Purity — 注意力集中度,衡量发音清晰度; (2) Alignment Monotonicity — 注意力峰值单调前进,衡量韵律流畅性。用 word-level group-relative policy optimization 更新 TTS。
- **代表论文+团队**: W3AR (Melbourne/NJUPT / Wang & Sun, AAAI 2026)
- **数据需求**: 无需额外训练 reward model; 无需偏好数据标注。仅用 frozen Whisper。
- **已知效果**: OOD WER 8.92→4.54 (-49.1%); 泛化到 VoiceCraft/MaskGCT 均有效
- **已知问题/风险**: 完全依赖 Whisper attention 质量; 换 ASR 模型效果未知; 无韵律坍缩分析
- **成熟度**: 中 — AAAI 2026 接收,方法简洁可迁移

### 路径 10: MCLP (LALM Continuation Log-Probability as Style Reward)

- **做法**: 将 LALM 的 continuation log-probability 重新定义为风格一致性 reward。构造 [transcript, eval_audio, transcript] dual-turn context,计算 LALM 对 ground-truth audio tokens 的平均 log-probability。通过固定 transcript 消除 content 变量。与 CER 组合为 gated hybrid reward (CER>τ→R=0)。
- **代表论文+团队**: MCLP (StepFun/CASIA / Ren et al., ICML 2026)
- **数据需求**: 依赖预训练 LALM (Step-Audio-2 semantic tokenizer) 做 continuation。
- **已知效果**: MOS 3.178→3.576; CER 3.334%→1.130%; 首个 dense continuous style reward
- **已知问题/风险**: 仅中文验证; 依赖 Step-Audio-2 tokenizer; 纯 MCLP reward 导致 CER 暴涨至 61%
- **成熟度**: 中 — ICML 2026 接收

### 路径 11: Masked DPO (Step-Audio 系列)

- **做法**: Step-Audio 的 TTS 后训练中使用 DPO,但仅对特定 token 计算 loss (masked)。与 FPO 思路类似但实现细节不同。
- **代表论文+团队**: Step-Audio 系列 (StepFun, 2025-2026)
- **数据需求**: 偏好数据 + token-level mask
- **已知效果**: 集成在 Step-Audio-2.5 系统中
- **已知问题/风险**: 细节公开有限
- **成熟度**: 中高 — 工业系统已部署

### 路径 12: ARDM-DPO (连续 token 自回归扩散的 DPO)

- **做法**: 首次将 DPO 扩展到 ARDM (Autoregressive Diffusion Model)。将 ARDM 采样视为 (token index n, diffusion time t) 双重马尔可夫链,通过 Jensen 不等式近似将 DPO 目标分解为逐 token-timestep 的 denoising loss 比较。
- **代表论文+团队**: ARDM-DPO (CUHK-SZ + ByteDance / Liu et al., 2025)
- **数据需求**: 偏好数据通过 proxy reward (F0V, CTC NLL) 自动构建,免人工标注。
- **已知效果**: F0V 14.2→29.2 Hz (表现力翻倍); CER 8.37→6.32 (鲁棒性 25% 改善)
- **已知问题/风险**: 训练不稳定需 early stopping; winning/losing 双方 loss 均上升; 仅 DiTAR 验证
- **成熟度**: 低-中 — 单篇论文,填补连续 token 范式空白

### 路径 13: Component-level GRPO (仅 Duration Predictor)

- **做法**: 不对整个 TTS pipeline 做 RL,将 GRPO 精确靶向 duration predictor。利用 4-step DMD-distilled student 生成样本计算 SIM+WER reward。RL 问题空间极小。
- **代表论文+团队**: DMOSpeech 2 (Columbia/NewsBreak / Li et al., AAAI 2026)
- **数据需求**: 标准 TTS 训练数据; GRPO 仅需 1.5K steps。
- **已知效果**: WER 1.752 (超越 ground truth duration 的 1.821); SIM 0.698; RTF 0.032
- **已知问题/风险**: 训练窗口极窄 (>1.5K 步退化); 仅优化 duration predictor 一个组件
- **成熟度**: 中 — AAAI 2026 接收,方法精巧

### 路径 14: Self-reward (模型自评+对齐)

- **做法**: 模型自身生成评分 (rubric-based),用自评分数作为 reward signal 做对齐训练。无需外部 reward model。
- **代表论文+团队**: SASLM (Baidu/NUS / Wang et al., 2026)
- **数据需求**: 不需要外部评估模型; 模型自身 3B 参数做 rubric-based scoring。
- **已知效果**: EchoMind F0-Var 63.44 (vs Qwen3-Omni-30B 49.76), EmoAlign 35.61%
- **已知问题/风险**: 仅英文验证; 800h 训练数据导致偶发声学瑕疵; 自评偏差问题
- **成熟度**: 低-中 — 新颖的 proxy-free 路线

### 路径 15: RLAIF-SPA (Structured AI Feedback + GRPO)

- **做法**: LLM 自动标注 4 维韵律-情感标签 (Structure/Emotion/Speed/Tone),Qwen2-Audio 判断生成语音与标签的匹配度作为 reward,加 WER 惩罚后用 GRPO 更新。
- **代表论文+团队**: RLAIF-SPA (Qing Yang et al., 2025)
- **数据需求**: GPT-4o 标注情感标签 + Qwen2-Audio 自动判断 + 1000 条 LibriSpeech。
- **已知效果**: SIM-O 0.72 (最高); CMOS 7.23; SER Avg 30.08
- **已知问题/风险**: 仅 1000 条训练; SER 绝对准确率偏低 (30%); 未与 DiffRO/Emo-DPO 对比
- **成熟度**: 低 — 单篇论文

### 路径 16: DLPO (Diffusion Loss Policy Optimization)

- **做法**: 将 RLHF 直接应用于 DDPM 去噪 MDP。将 diffusion 原始训练 loss 嵌入 reward function 作为正则项,防止 RL 微调导致质量退化。
- **代表论文+团队**: DLPO (Ohio State / Chen et al., Interspeech 2025)
- **数据需求**: UTMOS 作为 reward; LJSpeech 数据集。
- **已知效果**: UTMOS 2.90→3.65; NISQA 3.74→4.02; 人类评估 67% 偏好
- **已知问题/风险**: 仅 WaveGrad 2R 单说话人; UTMOS 有 reward hacking 风险; 规模极小
- **成熟度**: 低 — 学术探索

### 路径 17: F5R-TTS (NAR Flow-Matching 的 GRPO)

- **做法**: 通过将 flow matching 最后一层从确定性预测改为高斯分布 (mu+sigma),使 NAR 模型输出具有概率语义,从而可计算 log-likelihood 做 GRPO。首次让 GRPO 兼容 NAR flow-matching TTS。
- **代表论文+团队**: F5R-TTS (2025)
- **数据需求**: 标准 TTS 数据 + WER/SIM 双 reward。
- **已知效果**: WER 2.10%→1.48% (29.5% reduction); SIM 0.698→0.730
- **已知问题/风险**: 仅中文验证; 仅 WER+SIM 两个 reward; 未报告 MOS
- **成熟度**: 低-中 — 方法论意义大,可推广到其他 NAR 模型

### 路径 18: Online RL + ICL (In-Context Learning 耦合)

- **做法**: AR prosody model 以 human-curated audio prompt 作为 ICL 条件,用 AES-CE (aesthetic quality) reward + CTC alignment loss 正则化,通过 KL-regularized policy gradient 在线优化。
- **代表论文+团队**: ConversationalTTS-RL (Meta AI / Ouyang et al., 2026)
- **数据需求**: Human-curated audio prompts + Monte Carlo lower-bound selection。
- **已知效果**: RL-AES-CTC vs SFT-only: CMOS net win rate +7.1%; ICL vs GPT-4o CVAD +5.6%
- **已知问题/风险**: 全 in-house 数据; 人工 prompt selection 仍需 human effort; 仅 AR model 验证
- **成熟度**: 低-中 — Meta 内部系统

### 路径 19: Self-consistency Rewards GRPO (语音编辑)

- **做法**: 用预训练 TTS 模型 (CosyVoice 3) 的条件 log-probability 作为编辑区与上下文融合质量的隐式评估。配合 ASR WER + duration 一致性的 gated reward aggregation。
- **代表论文+团队**: Edit Content, Preserve Acoustics (CASIA/Tsinghua, ICME 2026)
- **数据需求**: 无需 teacher signal; 用 TTS 模型自身 prior 做 consistency reward。
- **已知效果**: Insertion WER 4.97% (vs VoiceCraft 12.94%); MOS 4.06 (vs 3.64)
- **已知问题/风险**: 仅 speech editing 场景验证
- **成熟度**: 低-中 — ICME 2026

### 路径 20: Editing-Oriented GRPO (CosyEdit2)

- **做法**: Teacher-free outcome-level GRPO for speech editing。三维 editing-oriented reward: WER 指数衰减 + DTW-aligned MCD (非编辑区声学保持) + speaker embedding cosine similarity。乘性门控 + 加性排序的 coarse-to-fine 层次组合。
- **代表论文+团队**: CosyEdit2 (Nankai / Chen et al., 2026)
- **数据需求**: 3000 句 GigaSpeech-XL; target-speech-free 构造 (无需人工目标录音)。
- **已知效果**: SEED-TTS CER zh 1.36→1.16, WER en 3.10→1.95 (editing GRPO 反哺 TTS)
- **已知问题/风险**: 主要面向 editing 场景; audio-level reward 计算
- **成熟度**: 低-中

### 路径 21: Combined GRPO+DiffRO + Sample Filter

- **做法**: 直接合并 GRPO+DiffRO loss 反而变差; 通过 sample filter (仅对 positive samples 做 DiffRO) 解决兼容性问题。
- **代表论文+团队**: RL-for-Audio-LLM (Tongyi / Gao et al., 2025)
- **数据需求**: 同 GRPO + DiffRO
- **已知效果**: Combined+Filter R^{1,2,3} 达 WER 3.414 (优于单独 GRPO 3.710 或 DiffRO 3.418)
- **已知问题/风险**: 机制未深入分析; 仅 CosyVoice2-0.5B 验证
- **成熟度**: 低-中 — 实验性组合

### 路径 22: Vox-Evaluator DPO (评估驱动的 Segment-level DPO)

- **做法**: 统一评估器 (error localization + transcription + quality score) 检测 error segments 后,用 segment-level DPO 仅在错误段上计算 loss,同时驱动 inference-time 纠错。
- **代表论文+团队**: Vox-Evaluator (Tencent / Wang et al., AAAI 2026)
- **数据需求**: FGES 22K 样本训练 evaluator; DTW 自动对齐生成偏好对。
- **已知效果**: F5-TTS WER 1.73→1.55%, SIM 0.67→0.683; failure rate 12%→6%
- **已知问题/风险**: DPO 2000 步后 reward saturation; evaluator 仅 185M 参数; PCC 0.541
- **成熟度**: 中 — AAAI 2026 接收

## II. Reward Model 架构

### 路径 A: 确定性工具组合 (WER+SIM+DNSMOS)

- **做法**: 用现成 ASR (Whisper/SenseVoice) 计算 WER/CER, Speaker Verification (WavLM/WeSpeaker) 计算 SIM, DNSMOS/UTMOS 计算预测 MOS。加权求和或调和平均。
- **代表论文**: TTS-1, GRPO-TTS, Align2Speak, Seed-TTS
- **优势**: 无需训练; 可解释; 组件可替换
- **劣势**: 各指标与人类感知弱相关; WER 直接优化导致韵律坍缩; SIM 对 channel/noise 敏感; DNSMOS 领域不匹配
- **成熟度**: 最高 — 事实标准

### 路径 B: 判别式 RM (Bradley-Terry 标量)

- **做法**: 训练 Bradley-Terry reward model 从 pairwise preference 数据中学习标量 reward。
- **代表论文**: SpeechJudge-BTRM (72.7% accuracy)
- **优势**: 标准 RM 训练范式; 产出连续标量
- **劣势**: 被 GRM 路线超越 (SpeechJudge-GRM 77.2%); 缺乏可解释性; 无推理过程
- **成熟度**: 中

### 路径 C: 生成式 RM (GRM, CoT Reasoning)

- **做法**: 基于 Audio-LLM 的生成式 reward model,在 <think/> 中生成多维度推理,在 <answer/> 中输出偏好/评分。SFT + GRPO 两阶段训练。
- **代表论文**: GSRM (Meta?, 2026), SpeechJudge-GRM (ByteDance/CUHK-SZ, 2025), UniSRM (CUHK, 2026)
- **优势**: 可解释; 推理过程可验证; 超越判别式 RM
- **劣势**: 计算成本高; CoT 质量依赖 teacher (Gemini); GRPO 训练需 480 GPU-hours (UniSRM)
- **成熟度**: 中高 — 多篇独立验证

### 路径 D: 多头 RM / 多维度打分

- **做法**: 一个模型同时输出多个维度的分数 (naturalness, speaker similarity, prosody, emotion 等)。
- **代表论文**: TTS-PRISM (12 维), UniSRM (4 种任务), Multi-Reward GRPO (5 维 reward)
- **优势**: 一次推理多维诊断; 避免多个独立模型的不一致
- **劣势**: 维度间可能冲突; 需要多维标注数据
- **成熟度**: 中

### 路径 E: LALM-based (续写概率作为 reward)

- **做法**: 利用 Large Audio Language Model 的 continuation log-probability 作为 reward signal。固定 transcript 消除 content 变量,使 likelihood 仅反映 style 差异。
- **代表论文**: MCLP (StepFun/CASIA, ICML 2026)
- **优势**: Dense & continuous; 不需要额外训练; 自然捕捉风格连续性
- **劣势**: 依赖 LALM 质量; 仅验证中文; 单独使用导致 CER 暴涨
- **成熟度**: 低-中

### 路径 F: Whisper 内部特征 (Attention Purity/Monotonicity)

- **做法**: 从 frozen Whisper 的 cross-attention map 提取 word-level 的 attention purity (发音清晰度) 和 alignment monotonicity (韵律流畅性) 作为 reward。
- **代表论文**: W3AR (Melbourne/NJUPT, AAAI 2026)
- **优势**: 零额外训练; word-level 精度; 与 ASR 天然对齐
- **劣势**: 完全依赖 Whisper attention 可靠性; 换 ASR 效果未知
- **成熟度**: 中

### 路径 G: Contrastive LLM Pair (Token Importance Estimation)

- **做法**: 用 label-flipped KTO 训练 π+ 和 π-,其 log-ratio 估计 token-level importance weights。间接作为 reward 信号引导优化。
- **代表论文**: TKTO (SpiralAI, 2025)
- **优势**: 自动 token-level 重要性估计; 无需 error segment 标注
- **劣势**: 需额外训练两个 LLM; 信号间接性
- **成熟度**: 低

### 路径 H: 自评 (Self-reward)

- **做法**: 模型用自身能力做 rubric-based 评分,验证意图与实现的一致性,用自评分数做 RL。
- **代表论文**: SASLM (Baidu/NUS, 2026)
- **优势**: 零外部依赖; 闭环设计
- **劣势**: 自评偏差; 模型能力瓶颈; 仅小规模验证
- **成熟度**: 低

### 路径 I: Token2Reward Model (Token 空间的 ASR/SER/SQA)

- **做法**: 将 SenseVoice 的 embedding 层改造为可接受 Gumbel-Softmax soft token 输入的 reward model,直接在 token 空间计算 ASR/SER/SQA/AED 多维度 reward。
- **代表论文**: DiffRO (Tongyi, 2025), Multi-Task Reward (MTR)
- **优势**: 省去 FM+vocoder 推理; 支持端到端梯度传播
- **劣势**: 需预训练; token 空间 reward 可能与 audio-level 感知不完全对齐
- **成熟度**: 中

### 路径 J: Robust RM (三层正则化)

- **做法**: Label Smoothing + Energy-Adaptive Mixup + Adversarial Training 三层混合正则化 fine-tune SER RM,防止 reward hacking。
- **代表论文**: RRPO (Tongyi, 2026, ICASSP 2026)
- **优势**: 直接解决 DiffRO 的 RM 脆弱性; 不改 policy 算法
- **劣势**: 仅在 SER RM 上验证; 三层正则增加训练复杂度
- **成熟度**: 中 — ICASSP 2026 接收

### 路径 K: CTC Loss 作为正则 Reward

- **做法**: 将 CTC alignment loss 嵌入 reward function,约束 RL 优化不偏离文本对齐。防止 reward hacking 和 text hallucination。
- **代表论文**: ConversationalTTS-RL (Meta AI, 2026)
- **优势**: 简单有效; 与 AES reward 互补
- **劣势**: 仅间接约束; 可能限制韵律多样性
- **成熟度**: 低-中

### 路径 L: ASR NLL (Negative Log-Likelihood) 作为连续 Reward

- **做法**: 用 Whisper decoder 对 ground-truth text 的条件 NLL 作为连续 reward。在 CER=0 时仍提供区分度。
- **代表论文**: GRPO-TTS (USTC/iFLYTEK, 2025)
- **优势**: 连续信号; CER 的互补; 无需额外训练
- **劣势**: NLL 与感知质量的相关性有限 (r=0.3371)
- **成熟度**: 中

## III. 评价维度方案

### 方案 1: TTS-PRISM 12 维分层诊断

- **维度**: Basic Capability 8 维 (Pronunciation Accuracy, Tone Correctness, Intonation, Pauses, Speech Rate, Voice Quality, Timbre Consistency, Emotion Consistency) + Advanced Expressiveness 4 维 (Stress, Lengthening, Emotion Expression, Overall Quality)
- **评分**: Basic 1-5 分 + Advanced 0-2 分
- **方法**: Schema-driven instruction tuning on MiMo-Audio 7B; 交错 [Rationale, Score] 输出
- **代表论文**: TTS-PRISM (THU/MiMo, Interspeech 2026)
- **覆盖**: 中文; 仅 utterance-level

### 方案 2: SEED-TTS-Eval 标准三件套

- **维度**: WER/CER (内容准确性) + SIM (说话人相似度) + DNSMOS/UTMOS (预测音质)
- **方法**: ASR 转写 + Speaker Verification + MOS 预测器
- **代表论文**: Seed-TTS (ByteDance, 2024)
- **覆盖**: 中英文; 事实标准

### 方案 3: TTSDS/TTSDS2 分布级评估

- **维度**: Generic/Speaker/Prosody/Intelligibility (4 因子)
- **方法**: Wasserstein-2 距离比较合成与真实语音的特征分布; 噪声锚点归一化
- **代表论文**: TTSDS (2024), TTSDS2 (ICLR 2026)
- **覆盖**: 多语言 (14 语言); system-level (非 utterance-level)

### 方案 4: SpeechJudge Naturalness Pairwise

- **维度**: 单一 naturalness 维度的 pairwise preference
- **方法**: 99K pairwise 人类标注 + GRM (SFT+GRPO on Qwen2.5-Omni-7B)
- **代表论文**: SpeechJudge (ByteDance/CUHK-SZ, 2025)
- **覆盖**: 中英文 + code-switching; 仅 naturalness

### 方案 5: UniSRM 四任务统一评估

- **维度**: (1) Utterance-level A/B preference (2) MOS-style quality (3) Scenario-aware style coherency (4) Multi-turn dialogue evaluation
- **方法**: Qwen2.5-Omni-7B-thinker + SFT + RCR-GRPO; <think/> 多维推理 + <answer/>
- **代表论文**: UniSRM (CUHK, 2026)
- **覆盖**: 4 种任务类型; 中英文

### 方案 6: GSRM Acoustic-Feature-Grounded

- **维度**: Vowel-level pitch + intensity + duration → CoT reasoning → naturalness 判断
- **方法**: Forced alignment → acoustic feature extraction → GPT-4o CoT synthesis → SFT on Qwen2.5-Omni-7B
- **代表论文**: GSRM (2026)
- **覆盖**: 对话 TTS; naturalness 专项

### 方案 7: InstructTTSEval 指令遵循评估

- **维度**: APS (声学参数遵循) + DSD (描述性风格遵循) + RP (角色扮演)
- **方法**: 6K 测试用例; Gemini-as-Judge True/False 二分评估
- **代表论文**: InstructTTSEval (2025)
- **覆盖**: 中英文; 指令遵循能力

### 方案 8: MINT-Bench 结构化多语言 IF

- **维度**: 10 原子属性 x 4 轴 (难度/控制域/控制规格/细粒度模式)
- **方法**: LALM 指令遵循 1-3 分 + 条件感知质量奖励; 10 语言
- **代表论文**: MINT-Bench (NPU, 2026)
- **覆盖**: 多语言; 结构化

### 方案 9: ProsodyEval / DS-WED (韵律多样性专项)

- **维度**: Prosodic Diversity (韵律多样性)
- **方法**: SSL 模型 (HuBERT/WavLM) 离散化为 tokens → 加权 Levenshtein 编辑距离
- **代表论文**: ProsodyEval (ICASSP 2026)
- **覆盖**: 7 系统 x 1000 样本; 人类 PMOS r=0.77

### 方案 10: EchoMind (对话场景评估)

- **维度**: F0-Var + EmoAlign + Duration Control + WER + Overall
- **方法**: 多维人工评分; conversational expressiveness 专项
- **代表论文**: SASLM (2026)
- **覆盖**: 英文对话场景

### 方案 11: I2D (Iterate to Differentiate — 迭代评估协议)

- **维度**: 不引入新维度,而是放大现有指标的区分力
- **方法**: 递归合成 (model output → reference → model output) 利用差异化退化放大性能差距
- **代表论文**: I2D (2026)
- **覆盖**: 11 个开源 TTS 系统; UTMOS SRCC 0.118→0.464

### 方案 12: AudioMOS Challenge (MOS 预测竞赛体系)

- **维度**: Speech MOS + Music MOS + General Audio Quality (PQ/PC/CE/CU)
- **方法**: 竞赛式 benchmark; SSL 特征 + 集成
- **代表论文**: AudioMOS Challenge 2025
- **覆盖**: 语音/音乐/通用音频; 多采样率

### 方案 13: NV-Bench (副语言发声评估)

- **维度**: 14 类非语言发声 (Vegetative/Affect Bursts/Conversational Grunts); PCER + IMOS
- **方法**: 功能分类学 + 双维评估 (指令对齐 + 声学保真度)
- **代表论文**: NV-Bench (2026)
- **覆盖**: 中英双语; NV-capable TTS

### 方案 14: Responsible TTS Evaluation 三层框架

- **维度**: Level 1 Fidelity & Accuracy → Level 2 Comparability & Standardization → Level 3 Governance & Fairness
- **方法**: 框架性论文; 不提供具体模型
- **代表论文**: Yang et al. (ICML 2026)
- **覆盖**: 元框架

## IV. 偏好数据构建路径

### 路径 i: Golden vs Synthetic Tokens

- **做法**: 用真实语音编码得到 golden tokens 作为 preferred,模型生成的 synthetic tokens 作为 dis-preferred。
- **代表论文**: SpeechAlign (复旦, 2024)
- **优势**: 无需人工标注; 天然对比
- **劣势**: 71% 情况下人类偏好 golden (非 100%); 无法区分细粒度维度

### 路径 ii: RLAIF — LLM 自动标注属性匹配

- **做法**: LLM (GPT-4o) 标注 4 维属性标签, Audio-LLM (Qwen2-Audio) 自动判断匹配度。
- **代表论文**: RLAIF-SPA (2025)
- **优势**: 无需人工; 属性级结构化反馈
- **劣势**: LLM 标注质量依赖模型能力; 离散标签粒度粗

### 路径 iii: Self-play (模型自采样 + 工具打分)

- **做法**: 策略模型生成 G 组候选,用 ASR+SV+MOS 工具自动评分,group-relative 构建隐式偏好。
- **代表论文**: GRPO 系列 (TTS-1, Multi-Reward GRPO, GRPO-TTS 等)
- **优势**: 全自动; 无需配对; 数据量不受限
- **劣势**: 完全依赖自动指标质量; 韵律坍缩风险

### 路径 iv: Error Segment 精标

- **做法**: Whisper-timestamped + forced alignment 定位 error segments,对每条数据精确标注哪些 token 有问题。
- **代表论文**: FPO (NWPU, 2025)
- **优势**: 极高数据效率 (3-4x); 精确信号
- **劣势**: 标注复杂度高 (虽然数据量少); 需 ASR+alignment 工具链

### 路径 v: Proxy Reward 自动构建偏好对

- **做法**: 用可自动计算的 proxy (F0 方差、CTC NLL 等) 对候选排序,选 best/worst 构建对。
- **代表论文**: ARDM-DPO (2025)
- **优势**: 免人工; 可针对特定维度 (如表现力)
- **劣势**: Proxy 与人类偏好的相关性有限

### 路径 vi: 大规模 Pairwise 人工标注

- **做法**: 大量标注员做 A/B 偏好标注,获得高质量 naturalness preference 数据。
- **代表论文**: SpeechJudge-Data (99K pairs, 69 名标注员, 2+ 月)
- **优势**: 最高质量 ground truth
- **劣势**: 成本极高; 中文一致性高于英文

### 路径 vii: 少量人类偏好 (Iterative)

- **做法**: 每轮仅收集 ~200 对人类偏好,做 iterative DPO。
- **代表论文**: No Verifiable Reward for Prosody (Channel Corp, 2026)
- **优势**: Cost-effective; 适用于不可自动化 reward 的场景 (如韵律)
- **劣势**: 需要多轮; 收益递减; 人工介入

### 路径 viii: 合成偏好对 (TTS-PRISM 方式)

- **做法**: 用对抗扰动 (pitch shift, noise injection, speed change 等) 构造 degraded 版本作为负样本。
- **代表论文**: TTS-PRISM (2026)
- **优势**: 可控; 大规模; 维度明确
- **劣势**: 合成退化与真实模型错误分布不同

### 路径 ix: Multi-candidate 多维独立选极值

- **做法**: 每个输入生成 10+ 候选,在各维度独立选最优/最差构建 preference set。
- **代表论文**: MPO (NWPU, 2025)
- **优势**: 多维度对比更 sharp
- **劣势**: 维度间冲突时需选次优/次差; 信号可能稀释

### 路径 x: Gemini CoT Distillation (Teacher-Student 标注)

- **做法**: 用 Gemini-2.5-Flash 生成详细 CoT reasoning 评估,蒸馏到小模型做 reward。
- **代表论文**: SpeechJudge (2025), UniSRM (2026)
- **优势**: 高质量 CoT; 自动化
- **劣势**: Teacher 能力天花板; 成本

## V. 训练信号层级

### Level 1: Audio-level (完整语音)

- **信号来源**: ASR WER, Speaker SIM, DNSMOS, AES, Human preference
- **优势**: 直接对应最终产物; 工具链成熟
- **劣势**: 信号稀疏; 归因困难; 计算成本 (需 decode)
- **代表**: Seed-TTS REINFORCE, GRPO 系列, TTS-1

### Level 2: Token-level (离散 speech token)

- **信号来源**: Token2Reward Model, Gumbel-Softmax 梯度, Token importance weights
- **优势**: 精确归因; 省去 decode; 可微传播
- **劣势**: Token 空间与感知空间有 gap; 需额外 reward model
- **代表**: DiffRO, FPO, TKTO

### Level 3: Word-level (词级)

- **信号来源**: Whisper cross-attention (purity/monotonicity), ASR forced alignment
- **优势**: 自然的语言学粒度; word-level attribution
- **劣势**: 依赖 ASR attention 质量
- **代表**: W3AR

### Level 4: Component-level (组件)

- **信号来源**: Duration predictor 的 GRPO reward
- **优势**: 问题空间极小; 训练高效; 靶向精准
- **劣势**: 仅优化一个组件; 其他组件的问题无法覆盖
- **代表**: DMOSpeech 2

### Level 5: Frame-level / Timestep-level (帧/扩散步)

- **信号来源**: Denoising loss per timestep (ARDM-DPO); Diffusion loss regularization (DLPO)
- **优势**: 最细粒度; 直接操作生成过程
- **劣势**: 训练不稳定; 理论推导复杂
- **代表**: ARDM-DPO, DLPO

## VI. 关键发现与横向对比

### GRPO vs DiffRO (Tongyi 同框对比, 2025)

| 维度 | GRPO | DiffRO |
|------|------|--------|
| 操作空间 | Audio-level | Token-level |
| 降 WER | 较弱 (3.710) | 较强 (3.418) |
| Speaker SIM | 较好 (77.26) | 可能伤害 (77.00) |
| 训练稳定性 | >1500 步退化 | 保持稳定 |
| 额外依赖 | 无 (仅 ASR) | Gumbel-Softmax + Token2Reward |
| 组合 | 直接合并变差; Sample Filter 后有效 | — |

### 韵律坍缩问题 (No Verifiable Reward for Prosody, 2026)

- GRPO (CER/NLL reward) → logF0 分布显著收窄 → CER 最低 (2.20%) 但 ELO 最低 (753.7)
- 加 speaker-similarity reward → CER 暴涨至 42.63% + EOS 失败
- 修复方案: iterative DPO + 200 真人偏好对/轮 → ELO 最高 (1190.1)

### Reward Hacking (RRPO, 2026)

- DiffRO 的全可微优化放大 RM 缺陷
- Vanilla SER RM 的三个脆弱性: 过度自信, 脆弱决策边界, 扰动敏感性
- Policy 通过生成声学伪影 (嘴部咔嗒声) 骗取虚假奖励
- 解决: Label Smoothing + Energy-Adaptive Mixup + Adversarial Training

### 现有指标对 Naturalness 的判断力 (SpeechJudge, 2025)

- WER 仅 57.9% accuracy (接近随机)
- SIM 仅 44.5%
- UTMOS 仅 53.7%
- 最好的 AudioLLM (Gemini-2.5-Flash) 仅 69.1%
- 专门训练的 GRM 达 77.2%

## VIII. 未覆盖/前沿方向 (观察到但尚无完整论文)

1. **Process Reward Model (PRM) for TTS**: NLP 已有 step-level reward,TTS 可在 token 生成过程中给逐步反馈
2. **Constitutional AI for TTS**: 用规则/原则约束生成而非学习 reward
3. **Multi-agent RL for TTS**: 多个 agent 分别负责不同维度的优化
4. **Curriculum RL**: 从简单文本到困难文本逐步增加 RL 难度
5. **Offline RL (IQL/CQL) for TTS**: 利用大量离线数据做保守策略优化
6. **Reward Model Ensemble**: 多个 RM 投票/加权减少 reward hacking
7. **Active Preference Learning**: 主动选择最有信息量的样本请求人类标注
8. **Cross-lingual Reward Transfer**: 用高资源语言训练的 RM 迁移到低资源语言

# 播客 / 多人对话合成: 路径全景

> 调研日期: 2026-06-09
> 来源: 本地知识库 (529 篇论文笔记 + 96 实体页) + arXiv 检索
> 不含推荐或结论,仅列出所有已知实现路径

---

## 一、生成架构

### 路径 1: Pipeline (独立 TTS + 对话调度器)

- **做法**: LLM 生成对话脚本 (含说话人标签 + 情感/韵律标注) → 调用现有零样本 TTS 逐句合成 → 后处理拼接/混音 → 输出
- **代表系统/论文**:
  - DialogueAgents (Li et al., 2025) — GPT-4o 写剧本 + CosyVoice 合成 + Qwen2-Audio 评审,迭代 2 轮
  - Google NotebookLM Audio Overviews — 推测为 pipeline 架构 (无论文)
  - KE-Omni (2025) — 顺序协作的 agent 方案
- **支持时长/说话人数**: 理论无限 (逐句拼接),说话人数不受限
- **已知指标**: DialogueAgents: MOS 3.75, EMOS 3.96, TMOS 3.78, WER(EN) 4.07%
- **优势**: 最简实现,复用现有 TTS,可控性最强 (情感/速度/停顿均可独立调),说话人数不受限
- **劣势**: 跨句韵律不连贯,无法建模真实重叠/backchannel,拼接处可能有不自然间隙,需要外部 LLM 做脚本
- **成熟度**: 工业可用 (已有多个商业产品)
- **数据需求**: 低 (复用现有 TTS 数据,只需高质量参考音频)

### 路径 2: 统一 AR LLM (单模型 + speaker-tagged sequence)

- **做法**: 对话脚本 + per-speaker voice prompts → 单一大 LLM backbone → 自回归生成全部 speech tokens (按时间顺序,speaker-tagged)
- **代表系统/论文**:
  - MOSS-TTSD (Zhang et al., 2026) — Qwen3-8B + MOSS-Audio-Tokenizer 16层 RVQ + multi-head delay pattern,60min/5spk
  - MoonCast (Ju et al., 2025, Microsoft) — Qwen2.5 backbone,零样本 podcast 生成
  - Parakeet (同期,未公开论文) — speaker-labeled chronological format
- **支持时长/说话人数**: MOSS-TTSD: 60 min / 5 speakers; MoonCast: 长对话 / 2+ speakers
- **已知指标**: MOSS-TTSD: ACC 0.9587 (ZH), SIM 0.7949 (ZH), WER 4.85% (ZH); MoonCast: CER 3.81 (dialogue-zh benchmark)
- **优势**: 端到端建模对话动态,全上下文建模保证跨 turn 一致性,支持 voice clone + continuation 融合
- **劣势**: 推理慢 (RTF>0.5),需 7B+ 模型,需大量多说话人数据,长上下文受 token limit 制约
- **成熟度**: 研究前沿,开源可用 (MOSS-TTSD)
- **数据需求**: 高 (需数十万小时多说话人对话数据 + 三阶段 curriculum)

### 路径 3: Text-Speech Interleaved AR (流式友好)

- **做法**: 对话按轮次交错排列 "[S1]<text/><audio/>[S2]<text/><audio/>...",backbone LM 在 interleaved 序列上做 next-token prediction,decoder LM 补充剩余 RVQ 层
- **代表系统/论文**:
  - FireRedTTS-2 (Xie et al., 2025, 小红书) — Dual-transformer (Qwen2.5 backbone + smaller decoder), 12.5Hz streaming tokenizer
- **支持时长/说话人数**: 3 min / 4 speakers (当前); 理论可扩展
- **已知指标**: Podcast-zh: CER 2.08, SIM 0.753, CMOS 0.0 (anchor); Podcast-en: WER 3.16, SIM 0.703; Emotion acc 86.1%
- **优势**: 天然支持流式逐句生成 (不需提前获取完整对话文本),dual-transformer 比 delay-pattern 首帧延迟更低,上下文保留完整 text+speech 允许隐式推断情感
- **劣势**: 当前仅 3 min,非开源,英文 SIM 较低 (0.665)
- **成熟度**: 接近产品化 (小红书内部使用)
- **数据需求**: 高 (1.1M h monologue + 300K h dialogue + SFT)

### 路径 4: Speech LLM 原生多通道对话 (Codec LM 直接建模)

- **做法**: 直接在多通道 audio token 上做 next-token prediction,不需文本中间表示 (或仅用 inner monologue)
- **代表系统/论文**:
  - CSM / Sesame (SesameAILabs, 2025) — Llama backbone + Mimi codec + 多轮上下文
  - dGSLM (Nguyen et al., 2023) — 首个全双工 SpeechLM,dual-tower DLM + cross-attention + HuBERT tokens
  - Moshi (Defossez et al., 2024, Kyutai) — Multi-stream RQ-Transformer + Inner Monologue + Mimi codec, 160ms 理论延迟
- **支持时长/说话人数**: CSM: 多轮 / 2 spk; dGSLM: ~数分钟 / 2 spk; Moshi: 实时流式 / 2 spk
- **已知指标**: CSM: 无公开指标; Moshi: sWUGGY 74.8, spoken QA WebQ 26.6, streaming TTS WER 4.7%
- **优势**: 最接近真实对话交互,可扩展到实时全双工,自然建模重叠/backchannel/打断
- **劣势**: 可控性差 (无法精确指定对话内容),训练数据需求极大,audio-only quality 低于 text-conditioned
- **成熟度**: 研究阶段 (CSM 开源但无论文; Moshi 开源但仅英文)
- **数据需求**: 极高 (万小时级真实对话音频, Fisher 2000h 等)

### 路径 5: 双通道混合生成 (CoVoMix 路线)

- **做法**: 单一 flow-matching/diffusion 模型同时生成双通道 mel spectrogram/waveform,两个通道分别对应两个说话人
- **代表系统/论文**:
  - CoVoMix (NeurIPS 2024, Microsoft) — 双通道零样本混合语音生成
  - CoVoMix2 (Zhang et al., 2025) — 改进版,需要预定义 timestamps
- **支持时长/说话人数**: 短 (数十秒级) / 2 spk
- **已知指标**: CoVoMix 英文 WER ~9.71% (对照)
- **优势**: 自然建模重叠语音,不需分离,单次生成两通道
- **劣势**: 仅支持双人,需要预定义时序,短对话,scale up 困难
- **成熟度**: 研究阶段
- **数据需求**: 中 (需双通道对话数据)

### 路径 6: Multi-head Delay Pattern (MOSS-TTSD 路线)

- **做法**: 在 LLM backbone 上用 MusicGen 式 multi-head delay pattern 并行预测多层 RVQ tokens
- **代表系统/论文**:
  - MOSS-TTSD (Zhang et al., 2026) — 16 层 RVQ, multi-head delay pattern
  - MOSS-TTS (前作) — 全层建模
- **支持时长/说话人数**: 60 min / 5 spk
- **已知指标**: 同路径 2 (MOSS-TTSD)
- **优势**: 单 pass 生成多层 token,避免两阶段管线复杂性,跨时间步一致性好
- **劣势**: 每步仅能访问前面 token 的部分层级,首帧需 N 步
- **成熟度**: 研究前沿 (已开源)
- **数据需求**: 同路径 2

### 路径 7: Dual-Transformer (Backbone + Decoder)

- **做法**: 大 backbone transformer 预测第一层 RVQ (语义最丰富) + 小 decoder transformer 基于 backbone hidden states 补充剩余 N-1 层
- **代表系统/论文**:
  - FireRedTTS-2 (Xie et al., 2025) — Backbone (Qwen2.5 large) + Decoder (Qwen2.5 small)
- **支持时长/说话人数**: 3 min / 4 spk
- **已知指标**: 同路径 3
- **优势**: 每 timestep 可完整访问之前所有 speech tokens,首帧仅需 1 步 backbone + (N-1) 步 decoder (vs delay pattern 需 N 步),分工明确 (语义 vs 声学细节)
- **劣势**: 两个 transformer 训练/维护复杂度高
- **成熟度**: 接近产品化
- **数据需求**: 同路径 3

### 路径 8: Dual-Track Parallel (DialoSpeech 路线)

- **做法**: LLM 在每个时间步同时预测双通道 semantic tokens (两个 prediction head) + chunked flow matching 分别重建双通道波形
- **代表系统/论文**:
  - DialoSpeech (Xie et al., 2025, APSIPA ASC 2025) — LLaMA + causal cross-attention + dual prediction head + chunked CFM + BigVGAN
  - dGSLM (2023) — Dual-tower DLM + cross-attention
- **支持时长/说话人数**: 短对话 / 2 spk
- **已知指标**: DialoSpeech: CER 2.27% (zh), Spontaneity MOS 3.96 (zh), SIM-O 0.67-0.69
- **优势**: 显式建模两通道交互 (causal cross-attention),自然表示重叠语音 (<SIL/> + 双通道 token),block-wise guided attention 解决长序列内存
- **劣势**: 仅双人,长对话因内存限制未探索,SIM 偏低
- **成熟度**: 研究阶段 (承诺开源)
- **数据需求**: 中 (10K h + 双通道处理 pipeline)

### 路径 9: NAR Flow Matching + Dialogue Conditioning

- **做法**: 非自回归 flow matching 模型 + curriculum learning (单人→对话) + speaker-turn embeddings 实现对话 TTS
- **代表系统/论文**:
  - ZipVoice-Dialog (Zhu et al., 2025) — Zipformer 123M + CFM + speech infilling + learnable speaker-turn embeddings + speaker exclusive loss
- **支持时长/说话人数**: 数十秒 / 2 spk (立体声)
- **已知指标**: WER 3.25%, cpWER 3.27%, cpSIM 0.437, UTMOS 3.07, RTF 0.063 (15x faster); CMOS +1.17 vs MoonCast; SMOS 3.86 vs MoonCast 2.35
- **优势**: 极快推理 (RTF 0.063, 比 AR 快 15x),极小模型 (123M),无 exposure bias
- **劣势**: 表达力受限 (MoonCast expressiveness 更好),仅双人,stereo 模型弱于 mono
- **成熟度**: 研究阶段 (含开源数据集 OpenDialog 6.8K hrs)
- **数据需求**: 中 (6.8K h OpenDialog)

### 路径 10: Next-Token Diffusion (VibeVoice 路线)

- **做法**: LLM backbone 预测 hidden states → token-level diffusion head 生成连续 acoustic VAE features → VAE decoder 重建波形
- **代表系统/论文**:
  - VibeVoice (Peng et al., 2025, Microsoft) — Qwen2.5 1.5B/7B + sigma-VAE 3200x causal tokenizer (7.5Hz) + DPM-Solver++ diffusion head
- **支持时长/说话人数**: 90 min / 4 spk
- **已知指标**: Preference MOS 3.75/3.71 (1.5B/7B), Realism 3.59, Richness 3.44/3.75; vs Gemini 2.5 Pro TTS 3.55/3.78/3.65; WER 1.16 (zh), 3.04 (en) at 7.5fps
- **优势**: 极低帧率 (7.5Hz) 使 90 min 仅需 ~40K tokens,连续 latent 避免量化损失,主观评测超越 Gemini/ElevenLabs
- **劣势**: 不处理重叠语音,仅中英,diffusion head 增加推理计算
- **成熟度**: 研究前沿 (无开源)
- **数据需求**: 高 (curriculum from 4K→64K context, 需大规模多说话人数据)

### 路径 11: Agentic Pipeline (LLM 生成 + 批判 + 迭代)

- **做法**: LLM 生成对话脚本 → TTS 合成 → 多模态 LLM (audio-understanding) 评审 → 反馈修改脚本 → 迭代 → 最终输出
- **代表系统/论文**:
  - DialogueAgents (Li et al., 2025) — GPT-4o (script writer) + CosyVoice (synthesizer) + Qwen2-Audio (critic), 迭代 2 轮最优
- **支持时长/说话人数**: 理论无限 / 多人 (Character Pool 机制)
- **已知指标**: MOS 3.75, EMOS 3.96, TMOS 3.78; MultiTalk 4437 utterances / 32441s
- **优势**: 可利用各领域最强模型,灵活替换组件,情感通过迭代改善
- **劣势**: 依赖闭源 LLM (GPT-4o),推理成本高,3+ loops 过优化退化,跨句韵律仍不连贯
- **成熟度**: 研究阶段
- **数据需求**: 低 (无需训练数据,但依赖强力预训练模型)

### 路径 12: SoulX-Podcast (方言 + 副语言 多样性)

- **做法**: 专注于长播客中的方言多样性和副语言丰富度,基于对话 TTS 架构扩展副语言建模
- **代表系统/论文**:
  - SoulX-Podcast (Xie et al., 2025, 同 DialoSpeech 团队) — 面向真实长播客,强调方言多样性和副语言
- **支持时长/说话人数**: 长播客 (数十分钟级)
- **已知指标**: 论文详情待查
- **优势**: 关注真实播客的核心差异化要素 (方言/副语言/自然口语)
- **劣势**: 论文细节有限
- **成熟度**: 研究阶段
- **数据需求**: 需方言数据 + 副语言标注

### 路径 13: Full-Duplex 全双工对话 (实时交互)

- **做法**: 模型同时处理用户输入和生成输出,支持打断/backchannel/重叠,非预编排脚本
- **代表系统/论文**:
  - Moshi (Kyutai, 2024) — Multi-stream RQ-Transformer, 160ms 延迟
  - PersonaPlex (NVIDIA, 2026) — 基于 Moshi + voice/role conditioning
  - Freeze-Omni (2024) — Chunk-level state prediction (State 0/1/2)
  - Raon-SpeechChat (KRAFTON, 2026) — SIL/BOW/BC 三状态建模
- **支持时长/说话人数**: 实时流式 / 2 spk (用户+系统)
- **已知指标**: PersonaPlex: DMOS 3.90, SSIM 0.57; Moshi: 160ms 延迟; Raon: interruption TOR 0.980
- **优势**: 真正的实时交互,自然处理打断/backchannel
- **劣势**: 不适合预编排播客 (无法精确控制内容),可控性差,音质低于 script-conditioned
- **成熟度**: 研究前沿 (Moshi 开源)
- **数据需求**: 极高 (需真实双工对话数据)

## 二、说话人控制方式

### 方式 A: Speaker Prompt (Voice Clone + In-Context)

- **做法**: 每个说话人提供 3-30s 参考音频,作为 prompt 输入条件化生成
- **代表**: MOSS-TTSD (voice_clone mode), VibeVoice, FireRedTTS-2, PersonaPlex
- **优势**: 零样本,无需 fine-tune,灵活换声
- **劣势**: SIM 受 prompt 质量影响,长时生成可能漂移

### 方式 B: Continuation (自回归续写)

- **做法**: 前文已生成的同一说话人音频自然作为后续的 condition
- **代表**: MOSS-TTSD (continuation mode), CSM
- **优势**: 天然保持一致性,无需额外模块
- **劣势**: 需要同一说话人有足够前文,首轮无法使用

### 方式 C: Voice Clone + Continuation 融合

- **做法**: 同时使用参考音频 (显式 slot) + 前文续写 (AR continuation),互补
- **代表**: MOSS-TTSD (最优配置)
- **优势**: ACC 和 SIM 全面提升 (SIM: 0.6828 vs 0.6075/0.6579 单独使用)
- **劣势**: 需要 chat template 设计支持

### 方式 D: Speaker ID Token / Speaker Tag

- **做法**: 在词表中添加 [S1]/[S2]/... 等 speaker tag token,模型学习关联 tag 与音色
- **代表**: MOSS-TTSD, FireRedTTS-2, MoonCast, ZipVoice-Dialog
- **优势**: 实现简单,与文本 LM 框架一致
- **劣势**: 需要训练数据中有标注,tag 数受限

### 方式 E: Learnable Speaker-Turn Embeddings

- **做法**: 学习 2 个可训练 embedding (speaker A / speaker B),加到 text condition 上
- **代表**: ZipVoice-Dialog
- **优势**: 极简 (仅 2 个 embedding),效果显著 (cpWER: 37.82% → 3.27%)
- **劣势**: 仅支持有限说话人数 (2)

### 方式 F: ECAPA-TDNN Speaker Embedding

- **做法**: 预训练 speaker encoder 提取说话人表征,作为全局条件
- **代表**: DialoSpeech (ECAPA-TDNN per-speaker embedding)
- **优势**: 支持任意新说话人,与 TTS backbone 解耦
- **劣势**: 可能不如 in-context prompt 保真

### 方式 G: Hybrid System Prompt (Text + Voice)

- **做法**: 文本角色描述 + 短音频样本拼接为 system prompt
- **代表**: PersonaPlex (NVIDIA)
- **优势**: 同时控制 voice timbre 和 persona/role
- **劣势**: 需要全双工架构支持

## 三、对话格式表示

### 格式 1: Chronological Speaker-Tagged

- **结构**: `[S1] text1 tokens1 [S2] text2 tokens2 [S1] text3 tokens3 ...`
- **代表**: MOSS-TTSD, MoonCast, Parakeet
- **特点**: 最直观,按时间线排列,speaker tag 标识轮次
- **限制**: 需提前获取完整对话文本,不支持流式逐句

### 格式 2: Text-Speech Interleaved

- **结构**: `[S1]<text><speech_tokens>[S2]<text><speech_tokens>...`
- **代表**: FireRedTTS-2
- **特点**: 每轮次的文本和音频紧挨,天然支持流式逐句生成
- **限制**: 单一序列长度增长快

### 格式 3: Dual-Channel / Dual-Track

- **结构**: 两个并行序列 (Channel A tokens / Channel B tokens),时间对齐
- **代表**: DialoSpeech, dGSLM, CoVoMix, Parrot
- **特点**: 自然建模重叠语音,每个时间步双通道各有状态 (active / <SIL/>)
- **限制**: 仅支持 2 人,需双通道分离数据

### 格式 4: Multi-Stream RQ

- **结构**: 多路并行 (user semantic + user acoustic + system text + system semantic + system acoustic)
- **代表**: Moshi (17 sub-sequences: text + 2x(1 semantic + 7 acoustic))
- **特点**: 完全移除显式 speaker turn 概念,可同时说听
- **限制**: 序列结构复杂,训练困难,仅 2 人

### 格式 5: Next-Token-Pair Prediction

- **结构**: 每个时间步同时预测双通道 token pair
- **代表**: NTPP (Wang et al., 2025), Parrot
- **特点**: 单模型简洁架构,比 dual-tower 更统一
- **限制**: 仅 2 人

## 四、长程一致性方案

### 方案 A: Curriculum Learning (短→长渐进)

- **做法**: 从短音频/单人 → 长音频/多人 渐进训练
- **代表**: MOSS-TTSD (Stage1: 32K→65K tokens; Stage2: DNSMOS≥3.4; Stage3: +多人), FireRedTTS-2 (mono→dialogue→SFT), ZipVoice-Dialog (monologue pretrain → dialogue finetune)
- **效果**: ZipVoice-Dialog 无 curriculum: WER 116.10% → 有 curriculum: WER 3.25%

### 方案 B: 低帧率 Tokenizer 压缩

- **做法**: 降低帧率以在固定 context window 内覆盖更长音频
- **代表方案**:
  - VibeVoice: 7.5Hz (3200x), 90min → ~40K tokens
  - FireRedTTS-2: 12.5Hz, 3min → ~2250 tokens (first layer)
  - MOSS-TTSD: 12.5Hz + 仅 16 层 RVQ = 2kbps, 60min → 65K tokens
  - Mimi (Moshi): 12.5Hz, 1.1kbps
- **trade-off**: 帧率越低,每帧编码越多信息,需更大 codebook/更多 RVQ 层补偿

### 方案 C: Voice Clone + Continuation 融合

- **做法**: 参考音频 (显式) + 前文续写 (隐式) 双重约束说话人一致性
- **代表**: MOSS-TTSD
- **效果**: SIM 提升 10-15% (消融实验)

### 方案 D: Context Window 扩展

- **做法**: 扩展 LLM context window (32K→65K→128K)
- **代表**: MOSS-TTSD (Qwen3-8B 65K), VibeVoice (Qwen2.5 64K)
- **限制**: 有硬上限,超过需分块

### 方案 E: Chunked Flow Matching (分块解码)

- **做法**: Flow matching 分块推理,每块仅条件化 prompt + 最近 N 块
- **代表**: DialoSpeech (block-wise guided attention: causal/history/future mask), FireRedTTS-2 (generation_chunk_buffer_size=6)
- **优势**: 固定内存,可处理任意长度
- **劣势**: 块间可能有不连续

### 方案 F: 合成多说话人数据增强

- **做法**: 用高质量单人段拼接模拟多人对话 (DNSMOS≥3.4 + 同采样率),扩充训练中见过的多人场景
- **代表**: MOSS-TTSD (Stage 3)
- **效果**: 弥补真实 3-5 人数据稀缺

## 五、重叠/副语言建模

### 策略 1: 不处理重叠

- **做法**: 所有系统假设每个时间步只有一个说话人活跃,轮次严格不重叠
- **代表**: MOSS-TTSD, MoonCast, FireRedTTS-2, VibeVoice
- **局限**: 真实对话 10-20% 时间存在重叠

### 策略 2: 双通道自然建模重叠

- **做法**: 两个通道独立生成,同一时间步两个通道都可有 active token
- **代表**: DialoSpeech (</SIL/> token + dual-stream), dGSLM, CoVoMix, Parrot
- **优势**: 自然表示重叠,符合物理实际
- **劣势**: 仅 2 人,数据获取困难

### 策略 3: Multi-Stream 隐式建模

- **做法**: 多路 token 流并行,模型自行学会何时双方同时活跃
- **代表**: Moshi (multi-stream 17 sub-sequences)
- **优势**: 端到端学习,最自然
- **劣势**: 训练极其困难,可控性低

### 策略 4: 显式副语言/回传 Token

- **做法**: 词表中添加 backchannel/情感/停顿等特殊 token
- **代表**:
  - Raon-SpeechChat: SIL (silence) + BOW (beginning of word) + BC (backchannel) 三状态
  - Mini-Omni2: irq/n-irq 打断标记
  - Freeze-Omni: State 0/1/2 chunk-level prediction
  - FireRedTTS-2: CosyVoice instruct 模式的 `[breath]`, `<strong>` 等副语言标记
- **优势**: 可控,可独立调节 backchannel 频率
- **劣势**: 需要标注数据,离散化可能损失连续韵律细节

### 策略 5: 隐式上下文推断

- **做法**: 模型从对话历史 (text + speech context) 自行推断适当的情感/副语言
- **代表**: FireRedTTS-2 (隐式情感推断 83-93% accuracy), Chain-Talker (CoT reasoning)
- **优势**: 无需显式标注,降低使用门槛
- **劣势**: "正确"风格主观,难以验证

### 策略 6: Speaker Exclusive Loss

- **做法**: 训练时增加 penalty 惩罚双通道同时活跃帧 (非重叠假设)
- **代表**: ZipVoice-Dialog
- **优势**: 保证说话人分离清晰
- **劣势**: 无法生成真实重叠

## 六、数据构建路径

### 路径 I: 真实对话录制 + 分离

- **做法**: 专业录制 (多通道麦克风) 或电话录音 → 说话人分离 → 转写 → 质量过滤
- **代表数据集**:
  - Fisher Corpus (~2000h, 英文电话对话) — 经典但受限
  - Seamless Interaction (4K h, 人工录制) — 高质量但成本高
  - VoxHear (1206h, BeyondMonologue 构建) — 视频清洗 + MossFormer2 分离
- **优势**: 最真实的对话动态
- **劣势**: 成本高,规模受限,标注困难

### 路径 II: 现有公开数据集

| 数据集 | 规模 | 语言 | 特点 | 开源 |
|--------|------|------|------|------|
| OpenDialog | 6.8K h | ZH+EN | 首个大规模对话 TTS 数据 (ZipVoice-Dialog) | 开源 |
| DailyTalk | ~20h | EN | 高质量录制,CSS benchmark | 开源 |
| InteractSpeech | 150h | EN | 多轮英文,交互标注 | 开源 |
| Fisher | ~2000h | EN | 电话对话,经典 | 受限 |
| J-CHAT | 76K h | JP | YouTube+Podcast 自动构建 | 开源 |
| MultiTalk | 9h | ZH+EN | DialogueAgents 构建 | 开源 |
| Emilia (对话子集) | 可筛选 | 多语言 | VAD+diarization+LLM 分类器 | 开源 |
| NCSSD | 236h | ZH | 自然对话,GPT-Talker | 开源 |

### 路径 III: LLM 生成脚本 + TTS 合成

- **做法**: LLM (GPT-4o/Qwen) 生成多角色对话脚本 (含情感/风格标注) → 多声音 TTS 合成 → 拼接 → 质量过滤
- **代表**:
  - MOSS-TTSD: 合成拼接数据 (单人段聚类后交错)
  - PersonaPlex: Qwen-3-32B/GPT-OSS-120B 生成文本 → Dia/ChatterboxTTS 合成
  - DialogueAgents: GPT-4o → CosyVoice → 迭代
- **优势**: 规模无上限,可控制场景/情感/话题分布
- **劣势**: 合成数据可能无法完全模拟真实对话韵律交互,质量天花板受 TTS 限制

### 路径 IV: 从 In-the-Wild 数据挖掘对话子集

- **做法**: 从大规模音频数据 (YouTube/Podcast/影视) 中自动提取对话段
- **代表**:
  - J-CHAT: YouTube+Podcast → Whisper LangID → PyAnnote diarization → 对话提取 → Demucs 降噪
  - Emilia: 从 101K+h 中筛选对话子集
  - MOSS-TTSD: 数据管线含 MOSS Transcribe Diarize + DNSMOS 过滤
- **处理步骤**: Download → Language ID → Speaker Diarization → Dialogue Extraction (5s gap 切分 + 80% 单人过滤) → Denoising → ASR Transcription
- **优势**: 规模大,多样性高,成本低
- **劣势**: 噪声多,需大量过滤,标注质量不可靠 (尤其 3+ 人)

### 路径 V: 单人语音拼接模拟多人

- **做法**: 选取高质量单人段 (DNSMOS≥3.4, 同采样率) → 按规则交错拼接 → 模拟多人对话
- **代表**: MOSS-TTSD (Stage 3)
- **优势**: 解决 3-5 人真实数据极稀缺问题,音质可控
- **劣势**: 无法模拟真实对话的韵律交互 (回应关系/情感呼应)

### 路径 VI: 影视/播客抓取 + 语音分离

- **做法**: 从影视/播客中抓取 → 语音增强 (MossFormer2/SepFormer) → Speaker Diarization → 切分为对话单元
- **代表**:
  - MOSS-TTSD: 电影+电竞数据用 MossFormer2 降噪
  - J-CHAT: Podcast 通道 (880K 文件)
  - VoxHear (BeyondMonologue): MossFormer2 分离 + SyncNet 验证
- **优势**: 数据多样 (话题/风格/说话人),规模大
- **劣势**: 版权问题,背景音乐/音效混入,分离质量不稳定

### 路径 VII: 双通道分离数据 Pipeline

- **做法**: VAD → ASR → Speaker Diarization → OSD (Overlapped Speech Detection) → Speech Separation (SpatialNet) → 双通道对齐
- **代表**: DialoSpeech (完整 pipeline 描述)
- **优势**: 获得干净的双通道数据,适合 dual-track 训练
- **劣势**: 依赖各组件质量 (diarization/separation error 累积)

## 七、评价方案

### 指标 1: cpWER (Concatenated minimum-Permutation WER)

- **做法**: 按说话人最优排列计算 WER,解决多说话人归属问题
- **依赖**: Speaker Diarization 模型
- **代表使用**: ZipVoice-Dialog, CoVoMix
- **局限**: Diarization 误差随说话人数增加而恶化

### 指标 2: cpSIM (Concatenated minimum-Permutation Speaker Similarity)

- **做法**: 按最优排列计算每段与 GT 说话人的余弦相似度
- **代表使用**: ZipVoice-Dialog
- **局限**: 同 cpWER,依赖 diarization

### 指标 3: TTSD-eval (MOSS-TTSD 提出)

- **做法**: 用 MMS-FA (Forced Alignment) 获取词级对齐 → 按标点切分 → 从脚本 speaker tags 直接分配身份 → 计算 ACC/SIM/WER
- **代表使用**: MOSS-TTSD (开源工具)
- **指标**:
  - ACC (Speaker Attribution Accuracy): 说话人归属正确率
  - SIM (Speaker Similarity): 与参考说话人余弦相似
  - WER: 基于 Whisper-large-v3
- **优势**: 完全绕过 diarization 误差 (利用已知脚本)
- **局限**: 仅适用于 script-to-dialogue (非交互式) 场景

### 指标 4: Spontaneity MOS

- **做法**: 主观评测,评价"是否像真实对话"
- **代表使用**: DialoSpeech (3.96 vs CosyVoice2 3.44)
- **局限**: 主观,需足够评测人数

### 指标 5: Realism MOS / Preference MOS / Richness MOS

- **做法**: 多维度主观评测 (播客真实感/偏好/丰富度)
- **代表使用**: VibeVoice (3.59/3.75/3.44-3.75)
- **局限**: 主观

### 指标 6: EMOS / TMOS (DialogueAgents 提出)

- **做法**: EMOS = 情感匹配 MOS; TMOS = 轮次切换自然度 MOS
- **代表使用**: DialogueAgents (EMOS 3.96, TMOS 3.78)
- **局限**: 需要人工评测

### 指标 7: Elo Rating (对战排名)

- **做法**: 多模型对战 (A vs B preference), Elo 排名
- **代表使用**: MOSS-TTSD (ZH Overall Elo ~1044)
- **优势**: 相对排名稳定
- **劣势**: 需大量对比样本

### 指标 8: Turn-Timing 分布统计

- **做法**: 统计 turn-gap 分布,与真实对话对比 (200-500ms 自然间隙)
- **代表使用**: dGSLM (turn-taking event 统计)
- **局限**: 仅适用于有自动 turn-taking 的系统

### 指标 9: Full-Duplex-Bench / Service-Duplex-Bench

- **做法**: 面向全双工系统的标准化评测 (打断处理率/backchannel 质量/response latency)
- **代表使用**: PersonaPlex (DMOS 3.90), FDB v1.0
- **适用**: 交互式对话系统

### 指标 10: 客观自动指标组合

- **MCD** (Mel Cepstral Distortion): FireRedTTS-2 使用 (7.99 zh / 9.06 en)
- **UTMOS**: 感知音质 (ZipVoice-Dialog: 3.07)
- **DNSMOS**: 噪声质量 (数据过滤用)
- **PESQ/STOI**: 信号级 (Tokenizer 评估用)

## 十二、开放问题与未探索方向

1. **3+ 说话人重叠建模**: 当前所有支持重叠的方案仅限 2 人,3+ 人重叠如何表示和生成?
2. **真实副语言学习**: 现有系统的"自然度"多为 LLM 风格描述驱动,真实对话中的犹豫/笑声/叹息等如何从数据中学习?
3. **Script-free 长播客**: 当前最强系统 (MOSS-TTSD/VibeVoice) 需要完整文本脚本,如何从 topic/outline 直接生成?
4. **跨模态同步**: 播客 + 虚拟人同步 (如 BeyondMonologue 解决的 listening 行为)
5. **评价标准化**: 当前无统一 benchmark (各系统自建测试集,不可比)
6. **实时交互 + 高质量 TTS 的统一**: 全双工系统 (Moshi) 音质低于 script-conditioned (MOSS-TTSD),如何兼得?
7. **多语言/方言混合**: SoulX-Podcast 方向,真实播客中说话人可能切换语言
8. **背景音乐/音效**: 真实播客含 jingle/过渡音效,当前系统不支持
9. **可编辑性**: 生成后修改某一句/重新生成某段,不影响其他
10. **版权与伦理**: 声音克隆用于播客的法律边界
