# TTS 方向规划 — 讨论记录

> 2026-06-08 session 总结，供下次继续

---

## 一、现有版本的诊断

已有 4 个版本：V1(汇报版)、V2(快稳好三角)、V3(论文实证+竞品追踪)、整合版(个人规划×行业)

**共同不足**：
1. **缺少个人亲历叙事** — 报告的说服力来自"经历过整个周期的人的判断"，但目前读起来像综述
2. **缺少应用层分析** — 全文聚焦模型架构，但 VoiceAgent/播客/配音等场景才是定义"什么是好 TTS"的力量
3. **缺少模型-应用共演化叙事** — 两者不是独立方向，是互相驱动的飞轮
4. **太长/太密** — V3 有 500+ 行，没有一个 5 分钟能讲清楚的故事

## 二、用户的核心构思

用户的个人思考框架：

- **双轴结构**：模型层（基础能力提升）× 应用层（边界拓展）
- **模型层**：codec 演进（离散语义/声学、连续）、架构（AR vs NAR、transformer vs diffusion）
- **应用层**：VoiceAgent、播客、视频配音、长语音、双工对话、Omni、语音创作、歌声、方言、情感、副语言、音效
- **串联方式**：从 Tokenizer 视角将不同阶段串起来——每个阶段反映遇到的问题和选择的解法
- **共演化**：TTS 发展催生应用场景，应用场景反向 push 基础模型
- **身份定位**：以个人身份发表对 TTS 及泛语音行业趋势的洞察，不是组内规划
- **个人经历**：完整经历了 0→1 的 TTS-LLM 周期（SoundStream→AudioLM→Encodec→VALL-E→DAC→CosyVoice→VoxCPM）

## 三、讨论中形成的洞察

### Tokenizer 三阶段叙事

每个阶段本质是回答"语音的哪些信息值得用序列模型来建模"：

```
阶段 1 (2022-2023): "所有信息都值得" → RVQ 全量 + AR
  教训: 全量信息 + AR = 自由度太高，模型管不住

阶段 2 (2024-2025): "只有语义信息值得序列建模" → 监督语义 token + FM/DiT 渲染
  教训: 压缩带来稳定，但扔掉的信息再也补不回来

阶段 3 (2025-2026): "所有信息都值得，但不该用 AR" → 全量信息 + mask/diffusion/patch
  教训: 问题不在"保留多少信息"，在于"用什么范式去生成"
```

核心洞察：不是"codec 选什么"在变，是"谁来承担建模难度"在变。

### 应用层的三个 demand vectors

```
需求向量 1: "实时交互" (VoiceAgent/双工/打断)
  Push 模型层 → 流式架构, 低延迟, SSM/因果

需求向量 2: "长程一致性" (播客/有声书/配音/长对话)
  Push 模型层 → 上下文建模, 低帧率, 多说话人追踪

需求向量 3: "精准控制" (情感/方言/副语言/歌声/品牌音色)
  Push 模型层 → 可控性, RL对齐, 分层 conditioning
```

### 共演化飞轮

模型突破使应用成为可能 → 应用暴露新需求 → 新需求驱动下一轮模型突破

### 关于深度行业判断的来源

用户认同：真正有深度的行业判断来自：
1. **论文 related work 的措辞** — 各团队对前作的批评/肯定暗含战略判断
2. **一线团队的技术选择本身** — 选了什么、放弃了什么
3. **闭门分享** — 公开搜索中找不到

用户现有工作（论文库 257 篇 + 行业全景报告）已部分覆盖 1 和 2，但：
- 目前更多是**描述性**的（谁做了什么）
- 需要升级为**判断性**的（这些选择暗示了什么战略共识/分歧）
- V3 的"竞品演进追踪"已在做这件事，可以更尖锐

### 关于外部视角

- 外部视角的价值在于**提供非技术人不容易自己产生的 framing**
- 但如果理解不透彻，会引入杂音
- 有效的外部视角示例：竞争三阶段（像不像人→多维能力→Agent就绪）
- 无效的外部视角：市场规模数字、泛泛的趋势报告

## 六、终局形态判断（已讨论）

用户判断：**语音 OS**（ElevenLabs 定义）— 不同任务分流到不同 pipeline，强模型逐步 merge。但 merge 的瓶颈不在模型能力，在训练数据：专用场景（影视配音/音色克隆/歌声）的数据通用模型拿不到。半年维度下，TTS 基础能力（快稳好）还没解好，被 LLM 吞掉不是当前主矛盾。

## 七、定稿大纲（2026-06-08 第二轮讨论）

### 叙事主线
技术突破 → 应用打开 → 新问题暴露 → 路线转向 → 再打开应用 → 再暴露问题。最后的"判断与规划"像是顺着因果链自然落下来。

### PPT 大纲

```
═══════════════════════════════════════════════
  2026 下半年 TTS 方向思考
  —— 从快稳好三角看技术路线的选择
═══════════════════════════════════════════════

P1  开场：我经历了什么
    标题: 从 SoundStream 到 VoxCPM，我经历了一整轮 TTS-LLM 周期
    • 个人经历线: SoundStream → AudioLM → Encodec → VALL-E → DAC → CosyVoice → VoxCPM
    • 这个周期的核心命题始终没变: 快、稳、好，能不能同时要？
    • 今天想从这条亲历线出发，讲讲我对下半年方向的思考

P2  核心框架：快稳好三角
    标题: TTS 的永恒三角 — 快、稳、好
    • 快: 推理延迟、流式能力、实时交互
    • 稳: 不跳词不幻觉、prompt 鲁棒、大规模可用
    • 好: 音质、表现力、情感、音色相似度、上下文韵律
    • 每一代技术本质上都在这个三角里做 trade-off

═══ 第一部分: 三个阶段，三次选择 ═══

P3  阶段1：GPT 范式迁移 — 把语音当文本来建模 (2022-2023)
    • 起点: 文本 LLM 的 next-token prediction 已经证明强大
    • 核心想法: 语音也能离散化成 token → 复用 GPT 的建模能力
      SoundStream/EnCodec 提供离散表征, AudioLM/VALL-E 证明走得通
    • 这个阶段没人纠结"信息量"问题 — 兴奋的是语音终于能用 LM 来做了
    • 引领工作: EnCodec, AudioLM, VALL-E

P4  问题暴露：RVQ 全量建模的代价
    • 实际部署后问题集中爆发: 幻觉、跳词、不稳定、prompt 敏感
    • 根因分析:
      - RVQ 码本层级多 → 序列太长
      - 帧率偏高 → 冗余信息多
      - 全量信息噪声大 → AR 自由度太高，管不住
    • 核心认知转变: 不是所有语音信息都适合交给 AR 建模

P5  阶段2：信息解耦，稳定优先 (2024-2025)
    • 诊断后提出多种解耦方案: SSL 表征、ASR 表征、解耦表征
    • 共识路线: AR 只管语义 → Flow/DiT 渲染声学，稳定性大幅提升
    • 引领工作: CosyVoice, Seed-TTS, Fish-Speech, GLM-4-Voice

P6  解耦方案自身的代价
    • 表现力被压缩: 情感/副语言/音量在拆分时丢失，下游补不回来
    • 一句话 prompt 只能克隆音色，克隆不了说话风格
    • 海量用户: 对 prompt 质量不鲁棒，很多音色崩溃或不像
    • 核心矛盾: 稳定性和表现力在当前架构下是跷跷板

P7  阶段3：从两个结构性缺陷出发的新探索 (2025-2026)
    缺陷 1: 分阶段训练复杂
      → 统一端到端 (DiTAR, WavTTS, VoxCPM)
    缺陷 2: codec 表征有上限
      → 连续表征 / 全量信息建模 (LatentLM, MELLE, CLEAR)
    应用侧新需求进一步推动分化:
      → Post-training 对齐 (SpeechJudge, DiffRO, GRPO)
      → 上下文/双工/Omni (FireRedTTS2, VibeVoice, ELLSA)
    路线还没收敛，各家在为不同问题选不同解法

═══ 第二部分: 业界怎么下注 ═══

P8  各家的策略选择
    标题: 不同团队在快稳好三角里选了不同的突破点
    • 先求稳: 阿里 CosyVoice、智谱 GLM-TTS
    • 先求好: 字节 DiTAR/DiSTAR、X-LANCE WavTTS
    • 先求快: Cartesia 40ms SSM、Qwen3-TTS 97ms
    • 押可控/对齐: 字节 SpeechJudge、阿里 DiffRO、阶跃三模式 RLHF

P9  已饱和 vs 正在拉开差距的方向
    已饱和: 零样本克隆、多语言支持、基本流式
    新战场: Post-training 对齐、全双工、Codec 创新、长语音一致性

P10 独立 TTS vs LLM-native（半年维度: 不是主矛盾）
    • 趋势存在: Qwen-Omni, Gemini Flash TTS
    • 但专用场景数据通用模型拿不到，短期不会 merge
    • 更远图景: 语音 OS — 不同任务分流，强模型逐步 merge
```

## 八、第二轮讨论补充（2026-06-08 下半场）

### 叙事顺序最终定稿：结论前置

```
0. 开场：三个结论先亮出来
1. 今天的 TTS 行业，已经不是一个赛道（行业分化现状）
2. 它是怎么走到这里的（历史作为解释 + 两段亲历案例）
3. 下一阶段，竞争会转向哪里（趋势判断 + 空白地带）
4. 我们的机会在哪里（三个判断 + 动作 + 优先级）
```

### 个人工作经历嵌入方式

两块工作内容作为"行业主线的内部验证"嵌入第 2 节：
1. **VALL-E → PilotTTS 2.0**：semantic tokenizer LLM 升级，2025 年初基础模型 SOTA → 映射阶段 1→2 的行业收敛
2. **方言/情感/VoiceAgent**：下游任务暴露三个问题（情感音色跑偏、发音稳定性下降、多场景自适应），根因都是数据缺失 → 映射阶段 2→3 的再发散动因

### 关键洞察

- **终局形态**：语音 OS（ElevenLabs），merge 的瓶颈是数据不是模型能力，半年维度不是主矛盾
- **数据是共同根因**：情感/方言/VoiceAgent 三个下游问题本质上都是数据缺失，算法弥补数据缺口是下一阶段核心竞争
- **三个判断的因果链**：基础模型 SOTA → 下游碰壁 → 数据缺失 → 保稳提好(判断1) + 上下文交互(判断2) + 对齐标注(判断3)
