## 一、为什么评测是最优先的基础设施

### 1.1 行业共识: 没有评测就没有闭环

字节 SpeechJudge 的核心发现:

> "所有现有客观指标在自然度判断上接近随机 — WER 57.9%, SIM 44.5%, UTMOS 53.7%"
> — SpeechJudge Table 2

这意味着我们日常评估 TTS "好不好" 的指标，其实什么都没告诉我们。没有可靠评测:
- 模型迭代靠"听 demo" → 不可规模化
- RL/DPO 的 reward 信号失真 → reward hacking (Seed-TTS §4.2, RRPO Table 1)
- 无法量化可控表达的进展 → "好"停留在主观感受

### 1.2 我们的定位: "可控的好" 而非 "随机的好"

汇报版 v3 的核心差异化:

```
通用表现力 (字节/阿里追求的)      可控表现力 (我们要做的)
──────────────────────         ──────────────────────
"随机地好听"                    "精确地好听"
评估靠 MOS                     评估靠属性匹配度
RL 目标: 通用偏好                RL 目标: instruct following
```

**评测体系直接决定这个差异化能否成立。** 如果我们没有属性级评测,就没法衡量"精确",也没法训练 instruct-following 的 reward model。

## 二、当前评测生态全景

### 2.1 TTS 评估: 四条主线

详见 [[Survey-TTSEvaluation2025]]。2025.6–2026.6 共 23 篇工作,分为:

| 主线 | 代表工作 | 我们能用什么 |
|---|---|---|
| **综合 Benchmark** | EmergentTTS-Eval, MINT-Bench, InstructTTSEval, NV-Bench, SwanBench-Speech | 直接跑,建立 baseline |
| **LLM-as-Judge** | TTS-PRISM, SpeechJudge, AnyAudio-Judge, CalibrationReasoningSQA | 借鉴框架,训练自有 judge |
| **MOS 预测** | UrgentMOS, DistilMOS, MOS-Reward, GSRM | 作为 RM 基础 |
| **韵律/细粒度** | ProsodyEval, IterateDifferentiate, CAST-Benchmark, CodecMOS-Accent | 补充维度 |

**关键趋势判断:**

1. **LLM-as-Judge 正在取代传统 MOS** — TTS-PRISM 7B 在 12 维评估上超过 Gemini-2.5-Pro
2. **评估器 → Reward Model 的双向转化** — SpeechJudge/GSRM 既做评估又做 RL reward
3. **MOS 本身的问题暴露** — MOS-Bias 发现性别偏差,IterateDifferentiate 发现 SOTA 系统分不开
4. **Instruction-Following 评估是空白** — InstructTTSEval 是唯一评测集但没有训练好的 RM

### 2.2 LALM 评估: 与 TTS 评测的交叉

详见 [[Survey-SpeechAudioLLMEvaluation2025]]。对我们有直接影响的:

| LALM 评估发现 | 对 TTS 评测的影响 |
|---|---|
| VoxParadox/DEAF: Audio LLM 可能不真正"听"音频 | 用 LALM 做 TTS judge 时需验证声学忠实度 |
| AllThatGlitters: 不听音频也能答对 → benchmark 本身有问题 | 我们设计评测时要避免文本先验泄漏 |
| HalluAudio: LALM 会幻觉 | LALM-as-Judge 的可靠性需要校准 |
| AU-Harness: 统一评测工具包 | 参考其框架设计我们的评测 pipeline |

**核心结论: LALM-as-Judge 是趋势,但不能盲目信任。** 需要:
1. 验证 judge 的声学忠实度 (DEAF 的方法)
2. 对抗性负样本防止捷径 (TTS-PRISM 的经验: 去掉负样本 LCC 从 0.717 暴跌至 0.150)
3. 人类标注校准

## 三、评测体系架构

### 3.1 三层评测框架

```
┌──────────────────────────────────────────────────────┐
│  第三层: 闭环层 — Reward Model + RL/DPO               │
│  "让模型按评测信号自动变好"                             │
│  Instruct-Following RM → RL → 更好的 TTS → 新样本 → ...│
└────────────────────────┬─────────────────────────────┘
                         │ reward 信号
┌────────────────────────┴─────────────────────────────┐
│  第二层: 诊断层 — 多维属性级评估                        │
│  "哪里好,哪里不好,为什么不好"                           │
│  情感匹配度 / 韵律多样性 / 风格一致性 / 指令遵循度       │
└────────────────────────┬─────────────────────────────┘
                         │ 属性维度
┌────────────────────────┴─────────────────────────────┐
│  第一层: 基线层 — 通用质量 + 标准 Benchmark              │
│  "整体好不好,跟别人比怎么样"                             │
│  WER/CER + SIM + MOS/UTMOS + SEED-TTS-Eval + MINT-Bench│
└──────────────────────────────────────────────────────┘
```

### 3.2 各层职责和落地计划

#### 第一层: 基线层 (Q3 建成)

**目标**: 自动化跑标准 benchmark,建立可复现的 baseline 比较体系。

| 模块 | 具体内容 | 参考 | 优先级 |
|---|---|---|---|
| **通用指标** | WER/CER (Whisper-large-v3), SIM (WavLM/ECAPA), UTMOS, DNSMOS | 行业标配 | P0 |
| **标准 Benchmark** | SEED-TTS-Eval (必跑), LibriSpeech test-clean/other | 字节定义的行业标准 | P0 |
| **Instruction-Following** | MINT-Bench, InstructTTSEval | 唯二的 instruct 评测集 | P0 |
| **自动化 Pipeline** | 一键跑全套指标 + 对比表生成 | 参考 AU-Harness 设计 | P0 |

**交付物**: 评测脚本 + 自动报告生成 + 历史版本对比 dashboard

#### 第二层: 诊断层 (Q3–Q4 逐步建设)

**目标**: 从"整体分数"到"知道哪里好哪里不好"。

| 评估维度 | 为什么需要 | 参考方案 | 建设方式 |
|---|---|---|---|
| **情感匹配度** | 可控表达的核心指标 — 指定了"开心"就要真的开心 | TTS-PRISM 的 Expression + Consistency 双维度 | 情感分类器 + LALM judge |
| **韵律多样性** | 避免"千篇一律的正确" | ProsodyEval 的 DS-WED 指标 (与人类 r=0.77) | 直接复用 DS-WED |
| **指令遵循度** | 差异化核心 — "精确地好" | InstructTTSEval 框架 + 自建 rubric | LALM judge + 二值 rubric (参考 AnyAudio-Judge) |
| **风格一致性** | 多句/段落级不退化 | 无成熟方案,需自建 | 跨句 SIM + 情感一致性 |
| **发音正确性** | "稳"的细粒度版 | Vox-Evaluator 的 error localization | DTW 对齐 + 时间戳错误定位 |
| **声学质量** | 底线保障 | DNSMOS + FAD | 直接复用 |

**关键技术选型: LALM-as-Judge**

参考 TTS-PRISM 的方案但做简化:

```
合成语音 → Audio Encoder → LALM (7B)
                            ↓
                  [R₁, S₁, R₂, S₂, ..., Rₙ, Sₙ]
                   推理₁ 分数₁  推理₂ 分数₂  ...
```

TTS-PRISM 的关键经验:
- 12 维评估,7B 模型即可超过 30B+ 通用模型
- **对抗负样本是必须的** — 去掉后 LCC 暴跌至 0.150 (比不训练还差)
- rationale-score 交错输出比直接打分更稳定

**我们的简化版本: 聚焦 4-6 个与可控表达直接相关的维度**,不做通用 12 维:

| 维度 | 对应 TTS-PRISM | 我们的定义 |
|---|---|---|
| 情感表达准确度 | Expression | 与目标情感标签的匹配程度 |
| 情感强度适配 | Consistency | 情感强度是否合适(不过度不缺失) |
| 韵律自然度 | Prosody | 重音/节奏/语调的自然程度 |
| 语速适配 | Speed | 是否匹配指令的语速要求 |
| 指令总体遵循度 | — (新增) | 综合判断是否遵循了全部控制指令 |

#### 第三层: 闭环层 (Q4 启动)

**目标**: 评测信号 → Reward Model → RL/DPO → 模型提升。

这层依赖第二层的成熟度。分三步:

**Step 1: Reward Model 训练** (Q4)

| RM 类型 | 输入 | 输出 | 训练数据 | 参考 |
|---|---|---|---|---|
| **Instruct-Following RM** | (指令, 合成音频) | 遵循度分数 | 自建偏好对 (P1 标注) | AnyAudio-Judge 的 rubric 分解 |
| **属性匹配 RM** | (目标属性, 合成音频) | 属性匹配度 | 属性标注数据 | TTS-PRISM 简化版 |

关键防 hack 措施 (从同行教训学习):
- **多维度 Pareto** — 不用单一 reward,避免 Seed-TTS 的 WER-自然度冲突
- **RRPO 三层正则化** — KL + 负奖励惩罚 + 梯度裁剪,避免 DiffRO 的 N-MOS 下降问题
- **对抗样本** — 负样本必须覆盖"指标好但实际差"的 case

**Step 2: RL/DPO 应用** (Q4–次年 Q1)

```
优先级排序:
1. Instruct-Following DPO — 最安全,对"稳"影响最小
2. 情感属性 RL — 需要精细的 reward 设计
3. 通用质量 RL — 最后做,reward hacking 风险最高
```

**Step 3: 闭环迭代** (持续)

```
评测发现问题 → 标注偏好数据 → 训练/更新 RM → RL/DPO → 新模型 → 评测 → ...
```

## 四、标注体系

评测和 RM 都需要标注数据。这是整个体系的"燃料"。

### 4.1 标注维度设计

| 层级 | 标注内容 | 标注方式 | 数据量目标 | 用途 |
|---|---|---|---|---|
| **音频级** | 整体质量 A/B 偏好 | 成对对比 | 10K+ 对 | RM 训练 |
| **属性级** | 情感类别/强度/语速/风格 | 分类+Likert | 5K+ 样本 x 4-6 维 | 属性 RM |
| **指令级** | 指令遵循 pass/fail | 二值判断 | 5K+ (指令,音频) 对 | Instruct RM |
| **时间戳级** | 错误定位/情感边界 | 时间区间标注 | 1K+ 样本 | Error localization |

### 4.2 标注效率优化

**参考 SpeechJudge 的经验**: 99K 偏好对,69 名标注员。核心效率手段:
- A/B 偏好对比 >> 绝对分数标注 (MOS-Reward 验证: 偏好对更稳定)
- 先用 LALM 预筛选,只把"难判"的给人标 (Active Learning)
- rubric 分解: 复杂判断拆成多个二值问题 (AnyAudio-Judge 的方法)

### 4.3 标注工具需求

| 功能 | 说明 | 优先级 |
|---|---|---|
| A/B 对比播放 | 支持同步/交替播放两段音频 | P0 |
| 多维度标注面板 | 同一样本标注多个属性 | P0 |
| 指令显示 + 遵循判断 | 显示控制指令,判断是否遵循 | P0 |
| 时间戳标注 | 标记错误/情感变化的时间点 | P1 |
| 标注一致性监控 | 实时 Krippendorff α 计算 | P1 |

## 五、竞对评测能力对标

| 团队 | 评测能力 | 我们的差距 | 我们的机会 |
|---|---|---|---|
| **字节** | SpeechJudge (99K 偏好 RM) + SEED-TTS-Eval (行业标准 bench) | 没有自己的 RM,没有定义 bench | Instruct-Following 维度他们没做 |
| **小米** | TTS-PRISM (12 维诊断) + MiMo-Audio (7B 理解基座) | 没有多维诊断框架 | 可直接参考 TTS-PRISM 架构 |
| **阿里** | DiffRO (token 级 reward) | 没有 token 级优化能力 | DiffRO 自己发现了 MOS 控制瓶颈 |
| **阶跃** | GRM (生成式 reward) + EditX (属性编辑) | 没有 GRM | EditX 的属性编辑思路可借鉴 |
| **学术界** | EmergentTTS-Eval, MINT-Bench, InstructTTSEval | 可直接跑 | InstructTTSEval 有评测无 RM = 我们的空位 |

**我们的差异化机会: Instruct-Following 评测 + RM**

- 全行业没有训练好的 Instruct-Following Reward Model
- InstructTTSEval / MINT-Bench 只有评测集,没有可训练的 RM
- 字节 SpeechJudge 只做自然度偏好,不做指令遵循
- 这恰好是我们"可控的好"定位的核心评测需求

## 七、风险和应对

| 风险 | 来源 | 应对 |
|---|---|---|
| **Reward Hacking** | Seed-TTS: 过度优化 WER 牺牲自然度; RRPO: DiffRO 的 N-MOS 下降 | 多维 Pareto + RRPO 正则化 + 对抗样本 |
| **LALM Judge 不可靠** | VoxParadox/DEAF: LALM 可能不真正"听"音频 | 对抗负样本 (TTS-PRISM: 去掉后 LCC 暴跌); 人类标注校准 |
| **标注一致性差** | MOS-Bias: 男女标注员系统性偏差 | A/B 偏好 > 绝对分数; 标注员校准; Krippendorff α 监控 |
| **评测与业务脱节** | 学术 benchmark 不覆盖我们的场景 | 自建业务场景评测集 (VoiceAgent/方言/情感) |
| **资源不足** | 标注成本高 | Active Learning (LALM 预筛 → 人标难例) |

## 八、总结

### 核心逻辑

```
问题: "好"无法度量 → 无法系统迭代 → 只能靠听 demo
           ↓
方案: 三层评测框架 (基线→诊断→闭环)
           ↓
差异化: Instruct-Following 评测+RM (行业空白)
           ↓
目标: 从"随机的好"到"可度量、可优化、可控的好"
```

### 优先级排序

1. **P0: 自动化基线评测** — 结束"手动跑指标"模式,Q3 交付
2. **P0: 标注工具 + 首批标注** — 评测和 RM 的数据基础,Q3 启动
3. **P1: LALM 诊断 judge** — 多维属性评估,Q3–Q4
4. **P1: Instruct-Following RM** — 差异化核心,Q4
5. **P2: RL/DPO 闭环** — 依赖 RM 成熟度,Q4–次年 Q1

### 一句话

> 评测不是附加项,是"可控表现力"差异化路线成立的前提。字节有 SpeechJudge,小米有 TTS-PRISM,我们需要的是 Instruct-Following 评测+RM — 这恰好是全行业没人做过的空位。
