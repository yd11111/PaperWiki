# PaperWiki 系统总览

> 本文档是系统当前状态的完整描述。AGENTS.md 是规则权威,本文档是结构总览。

## 一、系统目标与定位

### 1.1 一句话目标

以 TTS/语音合成为核心的个人知识库,AI agent 辅助人类进行论文阅读、概念整理与知识积累。

### 1.2 三个职责(筛/懂/连)

| 职责 | 含义 | 体现 |
|------|------|------|
| **筛** | 从海量论文中筛出值得关注的 | DailyPapers 推荐 + Inbox 缓冲 |
| **懂** | 带着已有知识读新论文 | KB 检索注入背景 → 精读笔记 |
| **连** | 把论文连成知识网络 | 实体页 + MOC + 反向更新 |

### 1.3 四条底线(可理解/可溯源/可导航/不腐烂)

- **可理解**: 精读必须体现 WHY + HOW,不是摘抄
- **可溯源**: Claim 标注 `[§X.X]` / `[Table N]`,内容区分 `[论文原文]` / `[agent 解读]`
- **可导航**: MOC 作主视图,wikilink 互连,实体页是枢纽
- **不腐烂**: Lint 检测 stale/orphan/dead-link,审阅拦截事实错误,backlog 告警提醒 review

### 1.4 设计哲学

- **允许不完美但可运行** — 局部完整优先,全局一致逐步达成
- **失败降级不阻断** — 任何子步骤失败均标注跳过,不中断主流程
- **默认不升级** — Agent 永不自作主张升级笔记层级

## 二、角色分工

### 2.1 人(你)的职责

- 触发升级(card → deep → repro)
- 确认知识进入可信层(pending-review → confirmed / draft → reviewed)
- 执行 merge / deprecate 等生命周期决策
- 放入 inbox、决定处理优先级

### 2.2 Agent 的职责

- 论文摘录与笔记生成(4 层)
- KB 检索 + 背景注入
- 实体页创建/追加更新
- MOC 自动刷新
- Lint 检查与报告
- 操作日志记录

### 2.3 Reviewer Agent 的职责

- 精读/复现笔记生成后、反向更新前自动触发
- 对照 review-checklist 检查 5 维度 x 10 问题类型
- 输出结构化审阅报告(YAML + callout),结论决定是否允许反向更新
- 只诊断不重写,不阻断 pipeline,每个问题提供 location + detail + suggestion

### 2.4 概念库的角色

论文之间的**连接节点** + KB 检索的**知识缓存层**。服务于"懂"和"连"两个职责。读得越多,confirmed 实体页越丰富,后续精读背景越完整。

### 3.2 关键目录/文件说明

**AGENTS.md** — 系统唯一权威规范,Agent 只需读此文件即可完整运行。

**CLAUDE.md** — Session 启动时的 bootstrap 文件,包含关键约束摘要、精读流程速查、skill 使用声明(paperwiki-reader / paperwiki-reviewer)。

**_templates/ (10 个模板)**:

| 模板 | 用途 |
|------|------|
| `paper-card.md` | 卡片笔记(每日推荐) |
| `paper-enhanced-card.md` | 增强卡片(快速了解) |
| `paper-deep.md` | 精读笔记(完整分析) |
| `paper-repro.md` | 复现笔记(代码级) |
| `concept.md` | 概念实体页 |
| `model.md` | 模型实体页 |
| `task.md` | 任务实体页 |
| `dataset.md` | 数据集实体页 |
| `inbox-item.md` | Inbox 条目(title+source+why) |
| `review-checklist.md` | 审阅 checklist(5 维度 x 10 问题类型) |

**Skills**: paperwiki-reader(精读)、paperwiki-reviewer(审阅)、daily-papers(每日推荐)、paper-compare(对比报告)、paper-highlights(亮点入库)、daily-papers-weekly(周报)等。

**论文笔记/ — 四层笔记体系**:

| 层级 | 深度 | KB 检索 | 信任 |
|------|------|---------|------|
| card | 标题+一句话+标签 | 不触发 | draft,不可引用 |
| enhanced-card | 摘要+方法+结果 | 不触发 | draft,不可引用 |
| deep | 完整机制+实验解读 | 触发 | reviewed 后可信 |
| repro | 代码级+复现要点 | 触发 | reviewed 后可信 |

**概念库/** — 准入规则: 满足 >=2 条: (1)多篇引用 (2)前置知识 (3)连接不同论文。Category 类型: technique / component / model-family / representation / problem / design-choice / taxonomy / trade-off,不分子目录。

**_review/** — 单篇审阅输出 `{论文名}-review.yml`,跨篇模式分析输出 `pattern-analysis-YYYY-MM-DD.md`。

**_MOC/** — 主视图导航,>=3 active 实体时自动创建 sub-MOC。仅收录 deep/repro 笔记。

**DailyPapers/** — 纯索引,禁止双重真相。只收当天 arXiv 发布论文。

**Sources/** — PDF 原文,gitignored。可追溯性通过 frontmatter `arxiv_id`/`source` 保证。

## 四、核心流程

### 4.1 精读 Pipeline (9 步)

```
① 读原文 PDF (pdftotext 优先,fallback Read OCR)
② KB 检索 (匹配 confirmed 实体页 → 注入 KB 背景节)
③ 生成笔记草稿 (paper-deep 模板,速查卡片,Claim 标注,status: draft)
④ 审阅 (反向更新前,对照 checklist 检查 → _review/xxx-review.yml)
⑤ Git commit 草稿 + 审阅报告
⑥ 反向更新 (仅审阅通过后; append key_papers / 新建实体页 pending-review)
⑦ 局部 lint (wikilink 有效性 + frontmatter 完整性)
⑧ Git commit + log
⑨ 审核积压检查 (pending-review ≥10 或 draft deep ≥5 → alert)
```

**关键变更**: 审阅(步骤④)插在反向更新之前,充当知识库安全门。只有审阅结论为 pass 或 pass-with-fixes 时才执行反向更新,revise/reject 时阻止反向更新直至修正。

### 4.2 KB 检索

- **触发**: 仅 deep/repro 层级
- **匹配**: title/alias 精确匹配 OR tags 交集>=2 OR frontmatter 直接引用
- **过滤**: lifecycle:active; confirmed 为主参考,pending-review 标 `[待确认]`
- **排序**: direct-ref > tag > alias,同级按 updated 降序,Top 6
- **降级**: 无匹配 → 标注继续; 仅 pending → "仅供参考"; >3 月未更新 → "可能过时"

### 4.3 反向更新

- **Append**(不改 status): 向 key_papers / 列表 / 表格末尾追加
- **Substantive**(→ pending-review): 重写定义、修改关系型 frontmatter、改写已有段落

### 4.4 概念页生命周期

- **创建**: 去重检查(搜索 title + aliases) → 满足准入规则(>=2 条) → 新建 pending-review
- **积累**: 精读触发 append(key_papers 自然增长)
- **重写**: 用户指定论文重写 → substantive update → pending-review
- **确认**: 用户 batch review → confirmed
- **Merge**: 用户指令 → 迁移内容 + 旧名加入 aliases + `grep -rl` 全局替换 wikilink → **删除源页**(不留 redirect)
- **Deprecate**: 用户指令 → lifecycle:deprecated + MOC 移至历史参考

### 4.5 每日推荐

抓取当天 arXiv + HF trending(过滤非当天论文) → 打分筛选 → card 笔记到 `论文笔记/` + 索引到 `DailyPapers/`。当天无新论文可不生成。

### 4.6 Inbox

放入(title+source+why) → 用户决策(精读/快看/跳过) → 处理后删除。零承诺,无时间压力。

### 4.7 Lint

- **Local**(每次 ingest): wikilink 有效性、frontmatter 完整性、实体存在性
- **Full**(每周): dead links、orphan pages、frontmatter 一致性、MOC 覆盖、概念去重、staleness、backlog 告警
- **Cognitive**(手动触发): 矛盾检测、stale SOTA、missing links — 结果标 `[疑似]`,永不自动修改

### 4.8 审核机制

- **实体页**: Agent 创建/实质修改 → pending-review → 用户 batch review → confirmed
- **笔记**: Agent 生成 → draft → 用户审核 → reviewed
- **告警阈值**: pending-review >= 10 或 draft deep >= 5 → log.md 记录 alert/backlog

### 4.9 笔记审阅

**单篇审阅**(每次 deep/repro 自动触发):
- 审阅 agent 对照 checklist 检查 5 维度(可理解性/可溯源性/严谨性/可导航性/知识库安全性)
- 10 类问题: factual-error / traceability-gap / overclaim / fact-inference-mixing / summary-without-mechanism / missing-lineage / weak-reusability / bad-linking / template-compliance / kb-safety-risk
- 严重度: high(必须修正) / medium(建议修正,可放行) / low(可忽略)
- 结论: pass / pass-with-fixes / revise / reject-as-deep
- 输出: `_review/{论文名}-review.yml` (结构化) + 笔记末尾 `[!review]` callout (人类可读)

**跨篇模式分析**(每 5-10 篇手动触发):
- 统计高频问题类型 → 判断根因(模板/规则/skill/检索) → 产出系统升级建议
- 输出: `_review/pattern-analysis-YYYY-MM-DD.md`

## 五、关键规则汇总

### 5.1 六条系统原则

1. **可信知识层** — confirmed/reviewed 才可信,AI 生成未确认不得入可信层
2. **主视图 = 实体页 + MOC** — 论文是输入端,实体页是沉淀端
3. **Inbox 零承诺** — 无时间压力,无处理义务
4. **失败降级** — 标注跳过,不阻断
5. **默认不升级** — 用户说才动
6. **允许不完美** — 局部完整优先

### 5.2 概念库规则

- **准入**: 满足 >=2 条: (1)多篇论文引用 (2)是前置知识 (3)连接不同论文。不满足 → 内嵌到相关页或 MOC
- **Category 类型**: technique / component / model-family / representation / problem / design-choice / taxonomy / trade-off
- **去重**: 创建前搜索 title + aliases,语义相近 → 追加到已有页 + 新名加 aliases;不确定 → 先合不拆
- **Merge 流程**: 迁移内容 → 旧名加 aliases → grep 全局替换 wikilink → 删除源页(无 redirect)

### 5.3 可信层定义

| 可信 | 不可信 |
|------|--------|
| 精读/复现 status:reviewed | 精读/复现 status:draft |
| 实体页 status:confirmed | 实体页 status:pending-review |
| — | card / enhanced-card (永远不可信) |

### 5.4 内容标注规则

- **Claim 标注**: `[§X.X]` 章节 / `[Table N]` 表格 / `[Fig N]` 图片
- **来源标注**: 论文原文内容标 `[论文原文]`,agent 解读标 `[agent 解读]`,禁止混写
- **同名消歧**: `[[论文笔记/CosyVoice 3|CosyVoice 3]]`,实体页 key_papers 始终用此格式

### 5.5 Commit 格式

`[type/subtype] pages — description`。Types: ingest / update / create / lint / review / alert / skip / moc / kb / lifecycle / init。
