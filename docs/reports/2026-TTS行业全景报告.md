## 一、技术路线图

### 1.1 当前主流架构: LLM + 两阶段生成

2024-2026 年形成的行业共识架构:

```
文本 → [LLM AR 解码器] → 语义 token → [Flow Matching / DiT] → 声学特征 → 波形
                ↑                              ↑
         Tokenizer/Codec                  声学解码器
```

采用者: CosyVoice (阿里), Seed-TTS (字节), GLM-TTS (智谱), Voxtral TTS (Mistral), Spark-TTS (NPU/Soul), StepAudio (阶跃), Qwen3-TTS (阿里 Qwen)

### 1.2 五大技术流派

| 流派 | 核心理念 | 代表 | 优势 | 风险 |
|------|----------|------|------|------|
| **① AR + Flow Matching** | 语义 token 自回归 + FM 声学渲染 | CosyVoice 3, GLM-TTS, Voxtral TTS | 成熟稳定, 质量高 | 同质化严重 |
| **② AR + DiT** | 连续/离散 token + Diffusion Transformer | DiTAR (字节, ICML), DiSTAR (X-LANCE/字节), WavTTS (X-LANCE/字节) | DiT 建模能力强, 可跳过 codec | 推理成本高 |
| **③ 非 AR 掩码生成** | 语义 token + 掩码并行生成, 无自回归瓶颈 | MaskGCT (港中深, ICLR 210 cit., 语义 tokenizer), Metis | 低延迟, 可并行 | 质量 ceiling 待验证 |
| **④ Dual-AR** | 快慢双自回归, 分工处理 RVQ | Fish-Speech S2 (31K stars) | 平衡质量与效率 | Fish 独创, 生态窄 |
| **⑤ SSM/Mamba** | 状态空间模型替代 Transformer | Cartesia Sonic (40ms 延迟) | 线性复杂度, 天然端侧 | 需证明大规模可行 |

**新兴流派** (2026 前沿):
- **直接波形 DiT**: WavTTS (X-LANCE/字节合作, 2026.06) — 跳过所有 codec, 直接在波形空间建模
- **连续 VAE Tokenizer**: MingTok-Audio (蚂蚁) — 非离散, 统一理解/生成/编辑
- **LLM-native TTS**: Qwen3-TTS, Gemini Flash TTS, Kimi-Audio (月之暗面) — 语音作为 LLM 原生输出模态

### 1.3 Tokenizer/Codec 路线分化

Tokenizer 是当前分歧最大的技术层:

| 路线 | 代表 | 特征 |
|------|------|------|
| 监督语义 token | CosyVoice (阿里) | ASR/TTS 多任务监督, 高语义保真 |
| 自监督 token | Mimi (Kyutai/Sesame) | HuBERT 系, 无需标注 |
| VQ-FSQ 混合 | Voxtral Codec (Mistral) | 两种量化器结合 |
| Dual-codebook | StepAudio (阶跃) | Linguistic + Semantic 物理并行 |
| 超低码率 | GLM (智谱, 175bps) | 12.5Hz 单 codebook |
| 语义-声学双流 | SAC (Soul/NPU, ACL 2026) | 双流分离, 各自优化 |
| 连续表征 | MingTok-Audio (蚂蚁, 连续 VAE), DiTAR (字节, AR 连续向量预测), VoxCPM (面壁, Tokenizer-free) | 非离散; MingTok 高维+低维双表示, DiTAR 直接预测连续 token, VoxCPM 用 LLM 建模连续语音 |
| 变长 token | VARSTok (阿里, AAAI 2026 Oral) | 自适应压缩率 |
| 单层高效 | MagiCodec (字节) | 高斯注入, Zipf 分布, LM 友好 |
| 离散+连续混合输入 | Kimi-Audio (月之暗面) | 12.5Hz 离散语义 token + 连续 Whisper 特征双输入, LLM 输出离散 token, FM detokenizer 还原 |
| 无 codec (波形直接建模) | WavTTS (X-LANCE/字节), MELLE (CUHK+MS) | 跳过所有中间表征, 直接在波形空间生成 |

### 1.4 Post-training: 从探索到标配

2024 年字节首创 TTS RL, 2026 年已成行业标配:

| 团队 | 方法 | 特色 |
|------|------|------|
| **字节** | RL → DPO (ARDM-DPO) → SpeechJudge (Reward Model) | 最完整迭代链; SpeechJudge 基于 Qwen2.5-Omni-7B |
| **阿里通义** | DiffRO (可微分 Reward 优化) | 直接优化 reward, 不用 RL 近似, CosyVoice 3 核心创新 |
| **阶跃** | SFT→DPO→PPO/GRPO→RLHF (三模式) | ASR 用 verifiable decoding, TTS 用 preference, Realtime 用 generative reward |
| **智谱** | GRPO (四维: CER+SIM+Emotion+Laughter) | 多维度同时优化 |
| **Fish Audio** | GRPO (语义准确性+指令遵循+声学偏好+音色) | 开源实践 |

### 3.4 三大范式转移

**范式转移 1: 独立 TTS → LLM-native 语音能力**

```
旧范式: 独立 TTS 系统 (Tacotron → VITS → CosyVoice)
         ↓ GPT-4o 催化
新范式: 语音是 LLM 的原生输出模态 (Qwen-Omni, Gemini Flash TTS, UniVocal)
状态: 过渡期 — 独立系统和 LLM-native 共存, 但趋势明确
```

**范式转移 2: 手工特征工程 → Post-training 对齐**

```
旧范式: 精心设计 tokenizer + 架构 + 数据配比
         ↓ RL/DPO/GRPO 引入
新范式: 用 reward model 自动优化 (SpeechJudge, DiffRO, GRPO)
状态: 早期 — 已验证有效, reward model 设计仍分散
```

**范式转移 3: Transformer 独占 → 架构多元化**

```
旧范式: Transformer-only (GPT/Llama-style)
         ↓ Mamba/SSM 挑战
新范式: SSM (Cartesia) + DiT (字节) + Masked Generative (MaskGCT) + Dual-AR (Fish) 并行
状态: 活跃竞争期 — 尚未形成新共识
```

## 四、空白地带

| # | 空白 | 现状 | 潜在价值 | 难度 |
|---|------|------|----------|------|
| 1 | **TTS 可解释性** | 几乎无人做 | LLM-TTS 是黑盒, 无法解释"为什么这样读" | 高 |
| 2 | **长文本一致性 (> 10 分钟)** | 仅 SoulX-Podcast (5 分钟+) | 有声书/播客需要小时级一致性 | 高 |
| 3 | **多说话人对话 TTS (3+ 人)** | 仅 JoyVoice (8 人) | 会议/播客/影视配音需求大 | 中 |
| 4 | **端侧部署 (< 1B)** | 仅 Cartesia Edge, 阶跃有计划 | 手机/IoT/车载需求大, 学术关注极低 | 中 |
| 5 | **跨语种声音克隆** | 零碎探索 | 中文参考→英语输出, 保持说话人特征 | 中 |
| 6 | **对话韵律建模** | 仅 Sesame CSM (Voice Presence) | 打断/犹豫/共情等动态韵律 | 高 |
| 7 | **TTS 水印标准化** | Google SynthID, 清华 VoiceMark | AI Act 等法规要求, 但缺行业统一标准 | 中 |
| 8 | **障碍语音 TTS** | 极少量 | 构音障碍等特殊人群需求 | 中 |
| 9 | **实时语音编辑 API** | 仅阶跃 EditX (3B) | 实时修改情感/风格/语速 | 中 |
| 10 | **独立第三方评估标准** | SEED-TTS-Eval 由字节主导 | 需要更中立的评估基准 | 低 |

## 十、个人规划参考

### 10.1 高价值研究方向 (学术)

| 方向 | 理由 | 竞争度 | 入手难度 |
|------|------|:---:|:---:|
| **Post-training / Reward Model** | 从 1 家到 5+ 家, 但方法论仍分散, DiffRO 独创性高 | 中 | 中 |
| **Codec 设计** | 分化极快 (10+ 路线), 基础设施层, 一篇好 codec 能被广泛采用 | 高 | 中 |
| **全双工对话** | HumDial 首个竞赛, 评测+方法均需迭代 | 中高 | 高 |
| **歌声/音乐合成** | 从边缘到多方投入, 数据集和评测仍不完善 | 中 | 中 |
| **语音安全** | 法规驱动 (AI Act), 从学术到产品 (SynthID), 社会意义大 | 低 | 中 |

### 10.2 空白机会 (差异化)

| 方向 | 理由 |
|------|------|
| **端侧 TTS (< 1B)** | 手机/IoT/车载需求大, 仅 Cartesia 涉足 |
| **多说话人对话 TTS** | 会议/播客场景需求大, 系统方案极少 |
| **TTS 可解释性** | 几乎无人做, 但对调试和安全至关重要 |
| **跨语种声音克隆** | 系统性研究近乎空白 |

### 10.3 技术赌注评估

| 赌注 | 赔率 | 风险 | 代表 |
|------|------|------|------|
| SSM 替代 Transformer | 高 | 高 (需大规模验证) | Cartesia |
| 连续 VAE tokenizer | 高 | 中 (蚂蚁 SIM 偏低) | MingTok-Audio |
| 直接波形 DiT (无 codec) | 高 | 高 (刚出现) | WavTTS (字节) |
| LLM-native TTS | 中 | 低 (已有产品) | Qwen3-TTS, Gemini |
| Post-training 标准化 | 中 | 低 (已验证有效) | SpeechJudge, DiffRO |
| 非 AR 掩码生成 | 中 | 中 (quality ceiling) | MaskGCT, Metis |
