# PaperWiki 使用手册

## 1. 系统概览

PaperWiki 是一个以 TTS/语音合成为核心的个人知识库,由 Claude Code 辅助维护。你通过自然语言下达指令,Agent 负责论文阅读、笔记生成、概念页维护、审阅检查和系统检查。知识库的主视图是实体页(概念/模型/数据集) + MOC 导航,论文笔记是输入端,实体页是沉淀端。核心哲学:允许不完美但可运行。

### 系统架构

```
AGENTS.md (Tier 1, ~200 行)          ← 系统总纲,所有 agent 加载
    ↓ 引用
docs/rules/ (Tier 2, 6 个文件)       ← 按角色加载的详细规则
    sources.md  — PDF 存储/命名
    notes.md    — 笔记体系/升级/速查卡片
    kb.md       — 实体页/检索/反向更新
    moc.md      — MOC 治理 (5 原则 + R1-R8)
    review.md   — 审阅系统 (笔记/KB/MOC 三模式)
    checks.md   — 系统检查 (lint + 人工)

_templates/ (审阅标准)
    review-checklist.md      — 论文笔记审阅 (5 原则 + 检查项)
    moc-review-checklist.md  — MOC 审阅 (5 原则 + 17 检查项)
    kb-review-checklist.md   — KB 更新审阅 (3 原则 + 检查项)

scripts/
    lint.py                  — 8 项自动化检查
```

## 2. 日常操作速查表

| 你想做什么 | 说什么 | 系统会做什么 | 产出在哪 |
|---|---|---|---|
| 精读一篇论文 | "读一下这篇 [URL/PDF路径]" | 8 步 pipeline(含独立审阅 + KB 审阅 + lint) | `论文笔记/` + `_review/` |
| 从 inbox 处理 | "处理一下 inbox" | 逐条检视 `_inbox/` 条目,询问你要精读/快看/跳过 | 视选择而定,处理后删除 |
| 每日论文推荐 | "今日论文推荐" | 抓取当天 arXiv 论文 → 打分筛选 → 生成 card | `DailyPapers/` + `论文笔记/` |
| 选读(升级为加强卡片) | "快速看一下 [[某篇]]" | 在已有 card 基础上扩展为 enhanced-card | 原文件原地升级 |
| 指定复现级阅读 | "复现分析 [URL/PDF]" | 8 步 pipeline(repro 模式) | `论文笔记/` + `_review/` |
| 用某篇论文重写概念页 | "用 [[论文]] 重写 [[概念]]" | 以指定论文为权威来源,重写概念页 | `概念库/`, status → pending-review |
| 搜索补充概念页 | "搜索补充一下 [[概念]]" | Playwright 搜索 → 补充概念页 | `概念库/`, status → pending-review |
| 审阅一篇笔记 | "审阅这篇笔记 [[论文]]" | 独立 subagent 对照 checklist 两层审阅 | `_review/xxx-review.yml` |
| 审阅 MOC | "审阅 MOC 零样本语音合成" | 对照 MOC checklist 审阅结构/年份/重复/标注 | `_review/moc-review-xxx.yml` |
| 批量审阅 | "批量审阅所有笔记" | 审阅所有未审阅的 deep/repro 笔记 | `_review/` 多个报告 |
| 系统检查 | "系统检查" | lint.py 自动化检查 + 人工项(孤儿/过时/积压) | `_lint/` 报告 |
| 确认实体页 | "batch review" | 列出 pending-review 实体页,逐个确认 | status → confirmed |
| 收一篇到 inbox | "收一下 [URL],因为 [原因]" | 在 `_inbox/` 创建最小条目 | `_inbox/` |
| 合并概念 | "把 [[A]] 合并到 [[B]]" | 内容迁移 + 全局替换引用 + 删除旧文件 | `概念库/` B 页更新 |
| 刷新 MOC | "刷新 MOC" | 重新生成所有 MOC 导航页 | `_MOC/` |

## 3. 笔记层级说明

| 层级 | 什么时候用 | 深度 | 能否被引用 |
|---|---|---|---|
| **card** | 每日推荐/扫一眼 | 标题+一句话+标签 | 不能 |
| **enhanced-card** | 想快速了解核心方法 | 摘要+方法+结果 | 不能 |
| **deep** | 认真精读 | 完整机制分析+实验+KB 背景+审阅 | 审核后可以 |
| **repro** | 要复现/深度理解 | 代码级分析+复现要点+审阅 | 审核后可以 |

升级只能由你触发。Agent 永远不会自作主张升级。

## 4. 精读完整流程 (8 步)

```
① 读原文 PDF (pdftotext 优先)
② KB 检索 (搜索 confirmed 实体页,生成背景)
③ 生成笔记草稿 (含速查卡片 + KB 背景 + [论文原文]/[agent 解读] 标注)
④ 审阅 (独立 subagent dispatch,不共享生成上下文)
⑤ Git commit 草稿 + 审阅报告
⑥ KB 更新审阅 (独立 subagent,审阅反向更新变更计划)
⑦ 反向更新 (仅 KB 审阅通过后: 追加已有页 / 创建新实体页)
⑧ 自动检查 (lint.py) + Git commit + log
```

关键设计:
- **审阅与生成隔离** — 审阅 agent 是独立 session,不看生成过程,只看产出文件
- **KB 审阅在反向更新前** — 如果更新有事实错误,不会污染概念页
- **lint 脚本自动执行** — 死链、frontmatter、年份一致性等 8 项机械化检查

## 5. 审阅系统 (三种模式)

### 笔记审阅 (每次精读后自动触发)

独立 subagent 对照 `review-checklist.md` 做两层审阅:
- **原则层** (5 条): 可复述 / 可信赖 / 可区分 / 可定位 / 不污染
- **检查项层**: 具体可验证的条目(claim 标注率、指标名、frontmatter 等)

| 结论 | 含义 |
|------|------|
| pass | 直接反向更新 |
| pass-with-fixes | 有 medium 问题,可放行 |
| revise | 有 high 问题,需修正 |
| reject-as-deep | 质量不达标,建议降为 enhanced-card |

**产出:** `_review/xxx-review.yml` + 笔记末尾 `[!review]` callout

### KB 更新审阅 (反向更新前自动触发)

审阅反向更新的变更计划是否安全。检查:
- factual accuracy (事实正确性)
- append vs substantive 分类是否正确
- 新建概念是否满足准入规则
- 是否有语义相近的已有页被忽略

结论: pass / pass-with-fixes / block

### MOC 审阅 (手动触发)

说 "审阅 MOC xxx" 触发。对照 `moc-review-checklist.md` 检查:
- 5 原则: 可导航 / 不混层 / 可溯源 / 不腐烂 / 不过载
- 17 检查项: scope 声明、概念分层、模型准入、年份一致、重复检测等

结论: pass / pass-with-fixes / revise / restructure

**产出:** `_review/moc-review-xxx.yml`

## 6. Lint 自动化检查

`scripts/lint.py` 提供 8 项机械化检查:

| 检查项 | 说明 |
|--------|------|
| 死链 | wikilink 指向不存在的文件 |
| frontmatter 完整性 | 必须字段存在且非空 |
| 年份一致性 | MOC 年份 section 与 frontmatter year 一致 |
| 重复 wikilink | 同一 MOC 内无重复条目 |
| MOC 覆盖 | 所有 deep/repro 被至少一个 MOC 收录 |
| 审阅覆盖 | deep/repro 笔记有 review callout |
| PDF 命名 | Sources/ 文件名与笔记名一致 |
| 概念去重 | title/aliases 无语义重叠 |

两种运行模式:
- **per-ingest**: 精读后自动运行(轻量子集)
- **full-check**: 手动运行 `python3 scripts/lint.py`(完整集)

## 7. 知识库怎么帮你

读第 N+1 篇论文时,系统自动检索 confirmed 实体页,注入"KB 背景"节:
- 谱系定位: 这篇在已有认知里什么位置
- 已有认知: 库里对相关概念已知什么
- 创新判断: 相对已知方法,新在哪

读得越多 → 概念页越厚 → 下一篇背景越丰富 → 复利。

## 8. MOC 导航

MOC 遵循 AGENTS.md §11 的完整规则体系:

- **scope 声明**: 每个 MOC 明确覆盖什么、不包含什么
- **概念分层**: 范式 / 模块 / 技巧 三层,不平铺
- **模型准入**: 代表模型只放主线系统,backbone/vocoder 放子节
- **论文容量**: 单页 ≤ 50 条,超过则拆 sub-MOC
- **年份从 frontmatter**: 不手动判断年份
- **演进关系**: → 直接后继 / ⇢ 借鉴 / ∥ 并行 / ⊃ 包含
- **强判断标注**: 首创/SOTA/唯一等必须标注来源

## 9. 审核节奏建议

| 时机 | 做什么 | 耗时 |
|---|---|---|
| 每精读 3-5 篇后 | "batch review" 确认实体页 | 5-10 min |
| 每周一次 | "系统检查" 看健康报告 | 5 min |
| 精读后看一眼 | 笔记末尾的 `[!review]` callout,只看 high/medium | 1-2 min |
| backlog 告警时 | pending-review >= 10 或 draft deep >= 5 | 按需 |

审核时重点看审阅 callout 标出的问题,不必逐字校对。不是强制节奏。

## 11. 注意事项

- **每日推荐只收当天论文** — HuggingFace trending ≠ 当天,系统过滤
- **Card/enhanced-card 永远不可信** — 只有 reviewed deep/repro 和 confirmed 实体页才是可信层
- **审阅与生成隔离** — 审阅 agent 不看生成上下文,保证独立判断
- **[论文原文]/[agent 解读]** — 精读笔记的"方法"节须标注解释来源
- **允许不完美** — 死链/孤儿/pending 积压是正常状态
- **网络操作用 Playwright** — WebFetch/WebSearch 不稳定
- **升级需要你说** — Agent 不自动升级 tier
- **Append 不改 status** — 往 confirmed 页追加不打回 pending-review
- **概念准入规则** — 新建概念须满足 ≥2 条: 多篇引用 / 前置知识 / 连接论文
- **合并不留 redirect** — grep 替换所有引用 + 旧名进 aliases + 删旧文件
- **MOC 论文 ≤ 50** — 超过自动拆 sub-MOC
