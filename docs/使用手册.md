# PaperWiki 使用手册

## 1. 系统概览

PaperWiki 是一个以 TTS/语音合成为核心的个人知识库，由 Claude Code 辅助维护。你通过自然语言下达指令，Agent 负责论文阅读、笔记生成、概念页维护和 lint 检查。知识库的主视图是实体页（概念/模型/数据集）+ MOC 导航，论文笔记是输入端，实体页是沉淀端。核心哲学：允许不完美但可运行。

## 2. 日常操作速查表

| 你想做什么 | 说什么 | 系统会做什么 | 产出在哪 |
|---|---|---|---|
| 精读一篇论文 | "读一下这篇 [URL/PDF路径]" | KB 检索 → 生成 deep 笔记 → 创建/更新实体页 → local lint → 刷新 MOC | `论文笔记/` |
| 从 inbox 处理 | "处理一下 inbox" | 逐条检视 `_inbox/` 条目，询问你要精读/快看/跳过 | 视选择而定，处理后删除 inbox 条目 |
| 每日论文推荐 | "今日论文推荐" | 抓取当天 arXiv+HF 论文 → 打分筛选 → 生成推荐 → 可选批量笔记 | `DailyPapers/` |
| 选读（升级为加强卡片） | "快速看一下 [[某篇]]" | 在已有 card 基础上扩展为 enhanced-card（摘要+核心方法+关键结果） | 原文件原地升级 |
| 指定复现级阅读 | "复现分析 [URL/PDF]" | KB 检索 → 生成 repro 笔记（含代码级分析+复现要点） | `论文笔记/` |
| 用某篇论文重写概念页 | "用 [[NaturalSpeech 3]] 重写 [[Flow Matching]]" | 以指定论文为权威来源，substantive update 概念页 | `概念库/` 对应页，status → pending-review |
| 搜索补充概念页 | "搜索补充一下 [[Flow Matching]]" | Playwright 网络搜索 → 整合最新信息 → 更新概念页 | `概念库/` 对应页，status → pending-review |
| 查看某概念的知识 | "[[Flow Matching]] 现在有什么" | 展示该实体页当前内容 + 相关论文笔记列表 | 终端输出 |
| 跑全量 lint | "跑一下 full lint" | 检查死链、孤儿页、frontmatter 一致性、MOC 覆盖、backlog 告警 | `_lint/` 报告 |
| 确认实体页 | "batch review" | 列出所有 pending-review 实体页，逐个展示摘要，你说 confirm/reject | 确认后 status → confirmed |
| 收一篇到 inbox | "收一下 [URL]，因为 [原因]" | 在 `_inbox/` 创建最小条目（title + source + why） | `_inbox/` |

## 3. 笔记层级说明

| 层级 | 什么时候用 | 深度 | 耗时 | 能否被引用 |
|---|---|---|---|---|
| **card** | 每日推荐/扫一眼 | 标题+一句话+标签 | 1-3 min | 不能 |
| **enhanced-card** | 想快速了解核心方法 | 摘要+方法+结果 | 5-10 min | 不能 |
| **deep** | 认真精读 | 完整机制分析+实验解读+KB 检索 | 30-60 min | 审核后可以 |
| **repro** | 要复现/深度理解代码 | 代码级分析+复现要点+KB 检索 | 60+ min | 审核后可以 |

升级只能由你触发（"升级为精读"），Agent 永远不会自作主张升级。

---

## 4. 知识库怎么帮你

当你精读第 N+1 篇论文时，系统会自动检索你已确认的概念页（confirmed 状态），把匹配的实体页内容注入笔记的 "KB 背景" 节。这意味着：

- 你读得越多，confirmed 实体页越丰富，后续精读时的背景信息越完整
- 新论文的笔记会自动标注它和你已有知识的关系（用了什么已知概念、提出了什么新概念）
- 概念页的 `key_papers` 列表会反向积累，帮你追踪哪些论文涉及同一技术

读前 5 篇时体感不明显，到 20+ 篇时效果显著。

## 5. 审核节奏建议

| 时机 | 做什么 | 预计耗时 |
|---|---|---|
| 每精读 3-5 篇后 | 说 "batch review"，确认新产生的实体页 | 5-10 min |
| 每周一次 | 说 "跑一下 full lint"，看看有无死链/孤儿/backlog 告警 | 5 min 看报告 |
| backlog 告警时 | pending-review >= 10 或 draft deep >= 5 时系统会提醒 | 按需处理 |

审核时重点检查：实体页的定义是否准确、关系字段是否合理、有无明显错误。不必逐字校对。

这不是强制节奏，忽略告警不会阻塞任何操作。

## 6. 概念页成熟流程

概念页有三条成长路径：

1. **自动积累**：每次精读涉及该概念时，Agent 自动 append 到 `key_papers` 列表（不改变 status）
2. **指定重写**：你说 "用 [[某论文]] 重写 [[某概念]]"，Agent 以该论文为权威来源做 substantive update（status → pending-review）
3. **搜索补充**：你说 "搜索补充一下 [[某概念]]"，Agent 用 Playwright 搜索最新资料更新页面（status → pending-review）

溯源提醒：当一个概念页的 `key_papers` >= 3 但 `origin_paper` 为空时，full lint 会提示 "建议找原始论文完善此概念页"。这是为了确保核心概念有明确的权威来源。

## 7. 目录结构速查

```
PaperWiki/
├── 论文笔记/          所有论文笔记（card 到 repro 都在这）
├── 概念库/            概念实体页（technique、loss、architecture 等）
├── 模型库/            模型实体页（VITS、CosyVoice 等）
├── 数据集/            数据集实体页
├── 任务库/            任务实体页
├── _MOC/             导航页（自动生成+维护）
├── DailyPapers/      每日推荐索引（仅 title + wikilink）
├── _inbox/           零承诺收件箱
├── Sources/          PDF 原文（gitignored）
├── _templates/       Obsidian 模板
├── _lint/            Lint 报告
├── docs/             系统文档
├── log.md            Agent 操作日志
└── AGENTS.md         系统唯一规范
```

## 8. 注意事项

- **每日推荐只收当天论文**：HuggingFace trending 不等于当天发布，系统会过滤
- **Card/enhanced-card 永远不可信**：只有 `status: reviewed` 的 deep/repro 笔记和 `status: confirmed` 的实体页才属于可信层
- **允许不完美**：死链、孤儿页、pending-review 积压都是正常的，不影响系统运行
- **网络操作用 Playwright**：WebFetch/WebSearch 不稳定，系统默认通过 Playwright MCP 工具访问网页
- **升级需要你说**：Agent 不会自作主张把 card 升为 deep，你不说就不动
- **Append 不改 status**：往 confirmed 页追加论文引用不会把它打回 pending-review
- **同名消歧**：论文笔记和实体页同名时用 `[[论文笔记/X|X]]` 格式区分
