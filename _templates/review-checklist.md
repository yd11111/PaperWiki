# 审阅标准

> 原则是宪法,检查项是法律,案例是判例法。
> 原则不变,检查项随系统演进更新。
>
> 本 checklist 用于论文笔记审阅。MOC 审阅使用 `moc-review-checklist.md`。

---

## 第一层: 评估原则 (稳定,极少变动)

从用户使用场景推导,不从文档属性推导。

| 原则 | 使用场景 | 核心问题 |
|------|----------|----------|
| **可复述** | 3 个月后回来看这篇笔记 | 读完笔记(不看原文),能向同事解释这篇为什么 work 吗? |
| **可信赖** | 引用笔记中的数据写报告 | 笔记里的每个事实,你敢直接写进自己的报告吗? |
| **可区分** | 决定是否复现某个方法 | 哪些是论文用实验证明的,哪些是 agent 的推测?边界清楚吗? |
| **可定位** | 读新论文时 KB 背景提供定位 | 这篇在领域中的位置清楚吗?和已有知识的关系明确吗? |
| **不污染** | 笔记信息流入概念页 | 这些信息进入概念页后,会让未来的 KB 背景更好还是更差? |

---

## 第二层: 当前检查项 (v1, 动态更新)

每条检查项标注它服务的原则。检查项会随系统架构演进而增删。

### 可复述

- [ ] "方法:它怎么 work" 节包含因果解释(WHY),而非仅组件罗列(WHAT)
- [ ] 每个关键设计选择回答了"为什么选这个而不是那个"
- [ ] 速查卡片"可借鉴"字段是具体可迁移 trick,不是"提出了新方法"

### 可信赖

- [ ] 数字型 claim 旁有 [§X.X]/[Table N]/[Fig N] 标注(目标覆盖率 ≥ 80%)
- [ ] 指标名使用正确(CER/WER/MOS/SIM/PESQ 不混淆),且与论文原文表头一致
- [ ] 速查卡片"指标"字段含具体数字 + 数据集名 + 来源标注,指标名与原文表头一致
- [ ] 无方向性错误(如"WER 越低越好"不被写成"超越")
- [ ] 比较表中非本文模型数字准确(抽样 ≥2 个 baseline 与 PDF 核对)
- [ ] 消融实验数字交叉一致(方法节引用的消融数字与实验表数据一致)
- [ ] 消融总结中的数字与笔记内详细消融表格一致
- [ ] 关键统计量数学一致(如 total = categories × per_category)
- [ ] 无定量指标的论文在实验节显式声明"本文无标准定量指标"
- [ ] 系统/框架论文有端到端验证结果(或显式说明无端到端评估)
- [ ] benchmark 论文: `models` 仅列本文模型,被评估系统在正文讨论

### 可区分

- [ ] 因果解释标注了 [论文原文] 或 [agent 解读]
- [ ] 因果解释来源标注覆盖率 ≥ 80%(方法节中的 WHY 解释有多少标了来源)
- [ ] 不存在把推断写成断言的句子(缺少"作者认为/实验显示/论文指出"限定词)
- [ ] "SOTA/唯一/全面优于/远超" 等强断言有数字+出处支撑

### 可定位

- [ ] KB 背景节有具体谱系定位(包含论文/模型名,不是"与已有工作相关")
- [ ] KB 背景的"创新判断"有对比基准
- [ ] frontmatter 字段存在且非空(fields_present)
- [ ] frontmatter 字段语义正确: models 列本文模型+对比 baseline(非后续系统); concepts 列本文涉及的概念(fields_semantically_correct)
- [ ] 速查卡片 5 字段都有实质内容(非空/非泛泛)

### 不污染

- [ ] 新建概念页满足准入规则(多篇引用/前置知识/连接论文 ≥ 2)
- [ ] 已有概念库中无语义相近页(去重检查)
- [ ] 反向更新内容无 factual-error 或 overclaim
- [ ] 反向更新正确分类为追加(不改 status)或实质修改(→ pending-review)

## 问题词汇表 (命名用,不是 checklist)

审阅发现问题时用以下类型命名,便于跨篇统计:

| type | 含义 |
|------|------|
| factual-error | 事实/数字/指标名错误 |
| traceability-gap | claim 无出处标注 |
| overclaim | 结论超出证据 |
| fact-inference-mixing | 事实与推断未区分 |
| summary-without-mechanism | 方法节是摘要不是机制解释 |
| missing-lineage | 缺谱系定位 |
| weak-reusability | 可借鉴太泛 |
| bad-linking | 概念挂接不合理或遗漏 |
| template-compliance | 格式/字段不合规 |
| kb-safety-risk | 会污染知识库 |
| successor-as-model | frontmatter models 列了后续系统而非本文对比 baseline |
| baseline-number-swap | 比较表多 baseline 数字整体互换(行偏移) |
| metric-naming-ambiguity | 同论文中名称相近但语义不同的指标需区分 |
| column-mismatch | 追加表格行时字段与列定义不匹配 |

**如果发现新类型的问题(不在此表中),直接命名并记录。** 这个表会在模式分析时扩展。

## 严重度

| 级别 | 含义 | 行动 |
|------|------|------|
| high | 影响可信性,会误导后续使用 | 必须修正才能反向更新 |
| medium | 影响质量,但不阻塞 | 建议修正,可标注后放行 |
| low | 影响可读性/复用性 | 可忽略或后续批量改善 |

---

## 审阅结论

| 结论 | 判定条件 |
|------|----------|
| pass | 所有原则基本满足,无 high issue |
| pass-with-fixes | 有 medium issue 但不阻塞反向更新 |
| revise | ≥ 1 个 high issue,修正后重审 |
| reject-as-deep | ≥ 2 个原则明显不满足,建议降为 enhanced-card |
