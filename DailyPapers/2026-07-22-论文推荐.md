### 1. StellarTTS: Sparse Temporal Embedding for Low-Latency and Robust Speech Synthesis
- **作者**: Kaicheng Luo, Xuefei Gong, Yutao Sun, Jinling He, Yujie Hou, Xiaoyang Xing, Huiyan Li, Bing Han, Yanmin Qian
- **机构**: 上海交通大学 AI 学院 MoE 人工智能重点实验室 / Honor
- **链接**: [arXiv](https://arxiv.org/abs/2607.19859) | [PDF](https://arxiv.org/pdf/2607.19859)
- **来源**: 📄 arXiv 关键词检索
- 📒 **笔记**: [[StellarTTS]]

![](https://arxiv.org/html/2607.19859v1/x1.png)

- **核心方法**: 输入文本、输出语音的移动端 NAR TTS。核心是「[[sparse temporal embedding]]（稀疏时序嵌入）」——在 phone 级别对时长/发音/韵律做稀疏可控编码，替代传统 NAR 的刚性对齐；配一个 [[semantic-aware codec]]（语义感知编解码器）实现单阶段解码。骨干是 83M 的 masked generative transformer（[[MaskGCT]] 路线），条件化在稀疏嵌入上，RTF 做到 0.08。与现有 NAR 的核心区别：不靠硬对齐堆时长，而是把稀疏时序嵌入当成可调控制信号，兼顾鲁棒性与韵律。
- **对比方法/Baselines**: 对比 [[CosyVoice2]]、[[NaturalSpeech3]]、[[MaskGCT]]、[[FireRedTTS]] 等 SOTA；借鉴 [[MaskGCT]] 的掩码生成范式、[[HuBERT]]/[[WavLM]] 类语义特征做 codec。评测集是 Seed-TTS test-zh 与 test-hard。
- **借鉴意义**: 做端侧/低延迟 TTS 的人值得抄——83M + RTF 0.08 + 单阶段解码是很实在的部署组合，稀疏时序嵌入这套「解耦时长控制」的思路可迁移到流式 TTS 的时长规划模块。
- **锐评**: 少见地把 latency、robustness、prosody 三角都摊开谈的 NAR 工作，且真做了 ablation（表 III）和时长控制专项（图 2 对比 MaskGCT）。但注意它自己写的是「maintaining competitive performance in audio quality」——翻译过来就是音质没超 SOTA，赢的是延迟和鲁棒性。83M 小模型在 test-hard 上的 SIM/CMOS 到底掉多少，得看全文表格，摘要只给了「competitive」这种模糊话。属于有真东西但别被 RTF 0.08 晃花眼的工作。
- **🧪 锐评依据**:

- **关联笔记**: [[MaskGCT]]（同为掩码生成 TTS，本文骨干路线）、[[CosyVoice2]]（主要对比基线）、[[NaturalSpeech3]]（韵律解耦对照）。

### 2. SimulS2ST-Omni: Data-Efficient Streaming Speech-to-Speech Translation via Explicit Trajectory Supervision
- **作者**: Rongshen He, Zhizheng Wu 等
- **机构**: 香港中文大学（深圳）
- **链接**: [arXiv](https://arxiv.org/abs/2607.19810) | [PDF](https://arxiv.org/pdf/2607.19810)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2607.19810v1/x1.png)

- **核心方法**: 输入源语言流式语音、输出目标语言流式语音的 S2ST。核心贡献是「joint text-code trajectory supervision（联合文本-码轨迹监督）」——把目标文本和声学语义码排成一条统一的「commitment path」同步调度,省掉了单独训练的、不稳定的 speech-side emission controller。架构用 [[Thinker-Talker]] 双流分解，把语言推理和稠密声学预测解耦以缓解模态干扰。全程只用 ~2k 小时 paired S2ST 数据 + 多任务辅助监督，把 paired 预算砍 90% 仍稳。
- **对比方法/Baselines**: 对标闭源 [[LiveInterpret]] 2.0，在 RealSI、ACL60/60-dev 上比 ASR-BLEU；借鉴 [[Thinker-Talker]] 双流范式、[[LoRA]] 微调；提及 [[UniSS]]、[[Seamless-Streaming]] 等流式同传线。
- **借鉴意义**: 做全双工/流式语音生成的人重点看它的「trajectory supervision」——用统一轨迹替代显式 emission policy，正好对上 turn-taking 里「何时该说」的 commit 决策难题；数据高效（2k 小时打平闭源）对没有海量 paired 语料的团队是好消息。
- **锐评**: 真解决了流式生成里「what + when to commit」这个硬问题，且把 emission controller 这个老大难直接消解掉，思路漂亮。数据高效的 claim 也有 ablation 撑（表 5 paired 预算砍 90%）。但「matching ... closed-source systems such as LiveInterpret 2.0」这种「打平闭源」的话要留神——只在 ASR-BLEU 一个指标上 match，声学质量（A.PCP / SIM-O）的曲线（图 4）到底压不压得住 offline 参考线，摘要没明说。Thinker-Talker 也不是它发明的，属于组合创新而非架构突破。

### 3. Efficient Chain-of-Modality Reasoning via Progressive Compression for Spoken Language Models
- **作者**: Pengchao Feng, Chao-Hong Tan, Qian Chen, Wen Wang, Xiangang Li, Xie Chen
- **机构**: Token Foundry（阿里巴巴）/ 上海创智学院 / 上海交通大学
- **链接**: [arXiv](https://arxiv.org/abs/2607.19932) | [PDF](https://arxiv.org/pdf/2607.19932)
- **来源**: 📄 arXiv 关键词检索

![](https://arxiv.org/html/2607.19932v1/x1.png)

- **核心方法**: 输入语音问题、输出语音答案的 Spoken LM，聚焦口语数学推理。核心是 ECoM Reasoning——把标准 [[Chain-of-Modality]]（先生成完整中间文本再转语音）里的文本组件「压缩」，让它同时充当语音引导信号和推理表示，从而用更少 token 完成推理。训练用 Progressive Compression：课程式地从「全文推理」逐步过渡到「压缩推理」。相比标准 CoM 的区别：不再显式吐出冗长中间文本，推理表示被压进更短的 token 预算。
- **对比方法/Baselines**: 对比标准 [[CoM]]（有/无推理）、[[CoT]]，用 [[CosyVoice3]] 合成语音、[[UTMOS]] 评质量；数学基准含 MultiArith、AddSub、SingleEq、SVAMP。
- **借鉴意义**: 做 Speech LLM 端到端 speech-in/speech-out 且关心推理成本的人可以看——「压缩推理表示同时兼作语音引导」是个省 token 的巧思，可迁移到语音对话里的隐式推理链。但仅此而已，对纯 TTS 无用。
- **锐评**: 方向蹭对了（Spoken LM 推理效率是真问题），+21% over no-reasoning CoM 的数字也够大。但战场选得太窄——口语数学题 QA 本身就是个小众到近乎人造的场景，「+3% over full-reasoning CoM while using 40% tokens」这种「省 token 换微涨精度」的收益，在真实语音对话里能不能复现是大问号。method_summary 为空、没给端到端语音质量对比的结论（虽然附录 F 提到 speech-quality eval），属于方向正确但说服力受限于评测面的工作。
- **🧪 锐评依据**:
  - `Claim: 战场窄，仅口语数学题 QA` | `Evidence: abstract「spoken mathematical question answering benchmarks」+ 基准 MultiArith/AddSub/SingleEq/SVAMP 均为数学题集` | `Confidence: 高`
  - `Claim: 相对 full-reasoning CoM 只是省 token 换微涨(+3%)` | `Evidence: abstract「by 3% over CoM with full reasoning traces while using only 40% of the text tokens」` | `Confidence: 高`
  - `Claim: 泛化到真实语音对话的说服力存疑` | `Evidence: 评测仅覆盖数学 QA，无开放域对话推理证据（领域推断）` | `Confidence: 低`
- **关联笔记**: [[Chain-of-Modality]]（本文改进对象）、[[CosyVoice3]]（语音合成后端）。
