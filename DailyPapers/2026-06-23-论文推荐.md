### 1. FlowTTS-GRPO: Online Reinforcement Learning with Multi-Objective Reward Optimization for Flow-Matching Based Text-to-Speech
- **作者**: Haoxu Wang, Biao Tian, Weiqing Li, Xiang Lyu, Han Zhu, Xiangang Li
- **机构**: Tongyi Lab, Alibaba
- **链接**: [arXiv](https://arxiv.org/abs/2506.17949) | [PDF](https://arxiv.org/pdf/2506.17949)
- **来源**: 📄 arXiv 关键词检索

- **核心方法**: 把 GRPO（Group Relative Policy Optimization）从 LLM 搬到 Flow-Matching TTS。关键技巧是把 ODE 轨迹转成 SDE 路径，让采样过程变成可优化的随机策略。用三个 reward 同时优化：[[DNSMOS]] 自然度、ASR-based 可懂度（CER）、说话人相似度（SS）。通过动态权重平衡多目标奖励。还加了 Hard Case Synthesis 生成难例文本做鲁棒训练。直接在 [[CosyVoice]] 3.0 和 [[F5-TTS]] 上微调验证。
- **对比方法/Baselines**: 基于 [[CosyVoice]] 3.0 和 [[F5-TTS]] 做 post-training。对比了 DiffRO（离线 RL 方法）。借鉴了 LLM 领域的 GRPO 和 Flow-based RL 思路。
- **借鉴意义**: 这是 Flow-Matching TTS 的 RL 后训练范式的正式落地。ODE→SDE 的转换让 FM 模型可以用标准 RL pipeline 微调，这个技巧可以迁移到任何 FM-based 生成模型。多目标 reward 的动态平衡对实际 TTS 系统很有参考价值——你总是要同时优化自然度、可懂度和说话人相似度，单一 reward 不够用。
- **锐评**: 这篇是 Tongyi Lab 在 CosyVoice post-training 上的正式技术报告，ODE→SDE 的核心 trick 虽然不是他们原创（Diffusion RL 早有类似思路），但在 FM-TTS 上的工程落地和多目标优化设计很扎实。硬例合成策略（数字、多音字、中英混合）说明他们真的在解决产品级问题。不过，MOS 提升幅度需要看全文确认——摘要只说"有提升"但没给具体数字，RL 微调在 TTS 上的收益通常不大（从 4.2 到 4.3 这种量级）。此外，reward model 本身的局限性（DNSMOS 的天花板、ASR CER 的粒度）没有讨论。🔥

### 2. Streaming T5-based Text-to-Speech Synthesis with Limited Lookahead
- **作者**: Muyang Rong, Jason Roche, Junjie Lai
- **机构**: NVIDIA (China + USA)
- **链接**: [arXiv](https://arxiv.org/abs/2506.17968) | [PDF](https://arxiv.org/pdf/2506.17968)
- **来源**: 📄 arXiv 关键词检索

- **核心方法**: S5-TTS 是 T5-TTS 的流式变体，通过 encoder-decoder 语言模型实现逐词增量语音合成。核心设计是 Lookahead-Causal Masks（LCM）——在 encoder 端给每个 token 提供有限的未来上下文（而非完全 causal），平衡延迟和质量。输入是文本 token 序列，输出是 [[FSQ]]（Finite Scalar Quantization）音频 token。还用了 Interleaved Multi-Source Distillation（IMSD）从非流式教师模型蒸馏知识。基于 [[MAS]]（Monotonic Alignment Search）做对齐学习。
- **对比方法/Baselines**: 对比了 [[FireRedTTS]]（非流式）及其他 AR/NAR TTS 模型（Table 3）。借鉴 T5-TTS 架构和 [[FSQ]] tokenizer。
- **借鉴意义**: Lookahead-Causal Mask 是一个非常实用的设计——在工业级流式 TTS 中，你经常需要在"完全 causal"和"full context"之间找平衡。这个方案提供了一个可配置的旋钮。IMSD 蒸馏策略也可以迁移到其他流式语音模型的训练中。NVIDIA 出品，工程质量应该有保证。
- **锐评**: NVIDIA 很少做 TTS 论文，这篇的工程品质确实高于平均水平。LCM 的设计简洁优雅，ablation（Table 2）也做得充分。但 FSQ tokenizer 的选择需要商榷——FSQ 在低码率下的重建质量不如 [[RVQ]]，论文是否讨论了这个 trade-off 需要看全文。另外，IMSD 蒸馏的计算开销不小，摘要未提训练成本。流式 TTS 的核心 metric 是首包延迟（FPL），但章节标题里没看到专门的 latency analysis section。🔥

### 5. ProsoCodec: Prosody-Oriented Speech Codec for Voice Conversion
- **作者**: Jeongsoo Choi, Ji-Hoon Kim, Shujie Liu, Joon Son Chung
- **机构**: KAIST + Chung-Ang University

- **来源**: 📄 arXiv 关键词检索

- **核心方法**: 设计了一种韵律导向的语音 codec，把内容、说话人和韵律三者解耦。核心思路是在 codec 训练中显式加入韵律保持约束——让 local tokens 保留韵律信息（pitch contour、duration）而不是说话人特征。用于 Voice Conversion 场景：输入源语音提取韵律 token，输入目标说话人提取 speaker token，合成保持源韵律但换了声音的语音。训练策略包含 bottleneck 配置（frame rate、codebook size、bitrate）的 ablation。
- **对比方法/Baselines**: 对比了 [[HierSpeech++]]、[[UniAudio]] 等 VC 方法。在 [[LibriTTS]] 和 [[VCTK]] 上评估。使用 [[UTMOS]]、WER、SIM 等指标。
- **借鉴意义**: 韵律-说话人解耦是 VC 的核心问题，也直接影响零样本 TTS 的韵律可控性。如果你的 TTS 系统需要"保持某段语音的韵律节奏但换一个说话人"，这篇的 codec 设计值得参考。Ablation 中 frame rate 和 codebook size 对韵律保持的影响分析可能有价值。

### 6. SDP-Codec: A Speaker-Decoupled Speech Codec with Pitch Injection for Low-Bitrate Coding and Zero-Shot Voice Conversion
- **作者**: Hounsu Kim, Juhan Nam
- **机构**: KAIST
- **链接**: [arXiv](https://arxiv.org/abs/2506.17543) | [PDF](https://arxiv.org/pdf/2506.17543)
- **来源**: 📄 arXiv 关键词检索

- **核心方法**: 说话人解耦 codec，在 local branch 注入显式 pitch 信息来保持韵律。Content encoder 用冻结的 vq-wav2vec 提取内容特征（天然去除说话人信息），Pitch encoder 用冻结的 FCPE F0 提取器。Global branch 用冻结的 [[HuBERT]] 提取说话人嵌入。三路信息拼接后解码。核心卖点是不需要多阶段训练或辅助对抗训练就能实现说话人解耦。
- **对比方法/Baselines**: 对比了 [[BiCodec]]、[[DualCodec]]、[[FocalCodec]] 等最新说话人解耦 codec。在 [[LibriSpeech]]、[[LibriTTS]]、MLS 上评估。Speaker probing accuracy（Table 4）直接量化了 local tokens 的说话人泄漏程度。
- **借鉴意义**: 如果你需要一个 content-speaker 解耦的 codec（用于 VC、voice anonymization、或者 TTS 中的说话人控制），这篇的架构简洁且验证充分。用冻结的预训练模型（vq-wav2vec + FCPE + HuBERT）做各通道提取，避免了端到端训练的解耦难题——工程实用性强。
- **锐评**: 架构设计很工程导向——全用冻结的预训练模型，训练成本低，reproducibility 好。Speaker probing 实验（Table 4）是这类工作的标配但做得规范。不过，所有冻结组件的质量天花板就是整个系统的天花板——vq-wav2vec 的内容表示能力不如更新的 [[HuBERT]] 或 [[WavLM]]，为什么选它？可能是因为 vq-wav2vec 天然去说话人更好，但摘要里没有 justify 这个选择。另外 pitch injection 对非声调语言的 VC 效果是否一样好？中文 VC 的评估缺失。👀

### 10. Whisper-CD: Accurate Long-Form Speech Recognition using Multi-Negative Contrastive Decoding
- **作者**: Hoseong Kim, Jeongyun Lee, Yoonji Lee, Kyuhong Shim
- **机构**: Sungkyunkwan University, Republic of Korea
- **链接**: [arXiv](https://arxiv.org/abs/2506.17830) | [PDF](https://arxiv.org/pdf/2506.17830)
- **来源**: 📄 arXiv 关键词检索

- **核心方法**: Whisper-CD 用 contrastive decoding 解决 [[Whisper]] 在长音频上的幻觉、重复循环和内容遗漏问题。核心思路是对比 clean-audio logits 和"负样本" logits——用多种音频扰动（噪声、时间偏移等）生成负样本，解码时抑制负样本中的 high-probability tokens。训练无关（training-free），直接在推理时应用。
- **对比方法/Baselines**: 基于 [[Whisper]] 各版本（Table 1）。在 CORAAL、TED-LIUM、VoxPopuli、REV-16 等长音频数据集上评估。Ablation 对比了不同扰动策略（Table 3）和对比强度 α（Table 2）。
- **借鉴意义**: Long-form ASR 的幻觉和重复循环是 Whisper 部署中的真实痛点。Training-free 的解码策略意味着可以直接应用到现有 Whisper 部署中，不需要重新训练。如果你的 ASR pipeline 用 Whisper 处理长音频（会议记录、播客转录），这个方法值得试。
- **锐评**: 思路来自 NLP 的 contrastive decoding，移植到 ASR 上是自然的。但多个负样本的扰动计算让推理成本翻了 N 倍——RTF（Real Time Factor）增加了多少？摘要没提。Fig. 2 的定性示例很直观（打破重复循环），但定量结果（WER/GER 的改进幅度）需要看 Table 1。对于本来就不幻觉的短音频，contrastive decoding 是否引入了性能退化？这类方法通常有这个问题。👀
- **🧪 锐评依据**：
  - `Claim: 推理成本可能翻倍` | `Evidence: 摘要 "contrasts clean-audio logits against negative logits"，需要多次前向传播；section_headers 无 RTF/efficiency 讨论` | `Confidence: 中`

### 11. Beyond Acoustic Prefixes: Persistent Grounding in Serialized Acoustic Memory for LLM-Based Multi-Talker Speech Recognition
- **作者**: Hao Shi, Yuan Gao, Xugang Lu, Tatsuya Kawahara
- **机构**: Kyoto University + NICT, Japan
- **链接**: [arXiv](https://arxiv.org/abs/2506.17824) | [PDF](https://arxiv.org/pdf/2506.17824)
- **来源**: 📄 arXiv 关键词检索

- **核心方法**: 解决 LLM-based 多说话人 ASR 中三人及以上场景性能骤降的问题。发现传统方法把声学信息只作为 prefix 输入 LLM，在长序列解码中说话人信息逐渐消散。提出"Persistent Grounding"——在解码过程中持续注入序列化的声学记忆（Serialized Acoustic Memory），让 LLM 在每个解码步都能访问细粒度的说话人线索。用 [[CTC]] 提取 serialized talker representations 作为声学记忆源。
- **对比方法/Baselines**: 对比了 AcousticPrompt、TokenPrompt、HybridPrompt、EncSep 等方法。基于 [[WavLM]] 做特征提取，用 [[LoRA]] 微调 LLM。在 [[LibriMix]] 和 LibriCSS 上评估（Table VI）。

- **锐评**: Kyoto + NICT 在多说话人 ASR 上的积累深厚。"acoustic prefix 信息消散"的诊断很有说服力，persistent grounding 的解决方案也合理。但 TABLE VI 只展示了 LibriCSS 的结果——这是一个相对干净的仿真数据集（LibriSpeech 拼接），真实会议录音（如 AMI、ICSI）的性能如何？另外，persistent grounding 增加了多少解码计算量？每步都注入声学记忆意味着 KV cache 更大。👀
